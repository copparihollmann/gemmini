### Optimization Strategy: Hoisting Loop-Invariant Scratchpad and Scale-Factor DRAM Transfers

To significantly reduce the execution latency of the weight-stationary MX-matmul, we will apply **Loop-Invariant Scratchpad and Scale-Factor Load Hoisting**. 

#### Analysis of Inefficiencies in Baseline:
1. **Redundant Configurations:** The configuration command `gemmini_extended3_config_ex(...)` and pipeline flushes (`gemmini_flush`) are executed inside the innermost loop `j0`. Because the hardware format parameters do not change between tiles, setting these registers in every tile iteration causes unnecessary CPU-to-coprocessor control overhead.
2. **Redundant Scale Factor Loads:** The row-wise scale factors for matrix A (`A_scales_perf`) only change when moving to a new row block index `i0`. However, they are loaded via `gemmini_mx_load_scales` inside the inner column-block loop `j0`, leading to $BLOCKS\_N$ redundant DRAM transfers of the same scale data.
3. **Redundant Matrix A DRAM Loads:** The inputs of matrix A are row-block invariant. In the baseline loop structure, the exact same blocks of A are loaded from DRAM into the scratchpad via `gemmini_extended_mvin` inside the inner `j0` loop. Since the scratchpad is safely partitioned (`a_base` is at `0`, `b_base` is at `6144`, and together they occupy only $4096$ of the $8192$ available rows), loading B never overwrites the loaded A tiles. Therefore, A can be loaded into scratchpad memory exactly once per outer loop iteration and reused across all column blocks.

#### Proposed Changes:
1. Move the one-time `gemmini_flush(0)` and `gemmini_extended3_config_ex` configuration calls completely outside all loops.
2. Hoist the loading of A scale factors (`gemmini_mx_load_scales` with `sel=0`) from the inner loop `j0` to the outer loop `i0`.
3. Hoist the `gemmini_config_ld` stride configuration and the nested `gemmini_extended_mvin` loop for matrix A out of the inner loop `j0` to the outer loop `i0`.

This strategy eliminates redundant DRAM bandwidth consumption for matrix A activation data and scales by a factor of $BLOCKS\_N$, while removing redundant coprocessor configuration overhead.

### Optimized Program Code

```c
// Optimized tiled MX matmul with loop-invariant load hoisting.
void solution(void) {
  // Pre-format scale factor matrices to eliminate CPU-side staging in the hot loop
  static uint8_t A_scales_perf[BLOCKS_M][MATMUL_K / 32][BLK];
  static uint8_t B_scales_perf[BLOCKS_N][MATMUL_K / 32][BLK];

  // One-time pre-formatting before main loops start
  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    for (int g = 0; g < MATMUL_K / 32; g++) {
      int mrows = REAL_M - i0 * BLK;
      if (mrows > BLK) mrows = BLK;
      if (mrows <= 0) continue;
      
      // Only copy actual data, handle partial blocks correctly
      for (int i = 0; i < mrows; i++) {
        A_scales_perf[i0][g][i] = A_scales_row[g][i0 * BLK + i];
      }
      // Pad with zeros for partial blocks if needed
      for (int i = mrows; i < BLK; i++) {
        A_scales_perf[i0][g][i] = 0;
      }
    }
  }

  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    for (int g = 0; g < MATMUL_K / 32; g++) {
      int ncols = REAL_N - j0 * BLK;
      if (ncols > BLK) ncols = BLK;
      if (ncols <= 0) continue;
      
      // Only copy actual data, handle partial blocks correctly
      for (int j = 0; j < ncols; j++) {
        B_scales_perf[j0][g][j] = B_scales_col[g][j0 * BLK + j];
      }
      // Pad with zeros for partial blocks if needed
      for (int j = ncols; j < BLK; j++) {
        B_scales_perf[j0][g][j] = 0;
      }
    }
  }

  // --- 1. Move Static Configurations out of all loops ---
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    int mrows = REAL_M - i0 * BLK; 
    if (mrows > BLK) mrows = BLK; 
    if (mrows <= 0) continue;

    int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
    uint32_t a_base = 0;

    // --- 2. Hoist A Scale-Factor Loads to the outer row-block loop ---
    gemmini_mx_load_scales((uint64_t)&A_scales_perf[i0][0][0], A_S_BYTES, 0);

    // --- 3. Hoist Matrix A scratchpad MVIN to the outer row-block loop ---
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K
    for (int i = 0; i < tiles; i++) {
      for (int k = 0; k < tiles_K; k++) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      }
    }

    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int ncols = REAL_N - j0 * BLK; 
      if (ncols > BLK) ncols = BLK; 
      if (ncols <= 0) continue;

      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      // Load column-dependent scale factors for B
      gemmini_mx_load_scales((uint64_t)&B_scales_perf[j0][0][0], B_S_BYTES, 1);

      // MVIN B remains inside the loop as B is variant across j0
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
      for (int j = 0; j < tiles; j++) {                  // B[k][j0*BLK+j] -> slot (k*tiles + j)
        for (int k = 0; k < tiles_K; k++) {
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
        }
      }

      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      // Accelerator-centric readout of output tiles
      for (int r = 0; r < mrows; r++) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
  }
}
```
