**Plan:**

For each fixed `i`, the K-tiles are stored contiguously in both DRAM (sequential columns in a row of A_buf, stride = `MATMUL_K`) and scratchpad (sequential rows at `a_base + i*tiles_K*DIM`). This enables batching up to `MAX_BLOCK_LEN=4` consecutive K-tile mvin commands into a single DMA instruction.

Specifically, instead of:
```c
for (int k = 0; k < tiles_K; k++)

```

We batch groups of up to 4 tiles:
```c
for (int k = 0; k < tiles_K; k += MAX_BLOCK_LEN) {

  gemmini_extended_mvin(ptr + k*DIM, spad + k*DIM, DIM, batch*DIM);
}
```

Using `rows = batch*DIM` with `cols = DIM` in `gemmini_extended_mvin` loads `batch` consecutive DIM-row tiles in one command. This applies identically to the B-tile mvin loop.

For this problem: `tiles_K = MATMUL_K/16`. The total mvin instruction count drops by up to 4×, reducing instruction dispatch overhead and freeing the instruction queue for overlap with compute.

The B-tile mvin loop for fixed `j` also has contiguous K-tiles in both DRAM and scratchpad, so the same batching applies there.
