## Strategy: Interleave A and B mvin Commands to Maximize DMA Port Utilization

### Observation

In the original code, all A tiles are loaded first (using `gemmini_extended_mvin` on port mvin), then all B tiles are loaded (also using `gemmini_extended_mvin` on the same port). This is strictly sequential: the DMA engine finishes all A loads before starting any B loads.

The hardware exposes **three independent mvin ports**: `mvin` (port 0), `mvin2` (port 1), and `mvin3` (port 2). Ports 0 and 1 (mvin and mvin2) target the scratchpad independently. When A and B loads are issued on separate ports, the DMA engine can fetch both matrices from DRAM **simultaneously**, cutting the total tile-load latency roughly in half.

### What to Change

1. Issue A-tile loads via `gemmini_extended_mvin` (port 0), configured with the A-matrix DRAM stride.
2. Issue B-tile loads via `gemmini_extended_mvin2` (port 1), configured with the B-matrix DRAM stride via a separate `gemmini_extended3_config_ld(..., id=1)` call.
3. **Interleave** the two streams: for each `(i, k)` A-tile issue, immediately follow with the corresponding `(j, k)` B-tile on port 1, so both DMA channels are active concurrently throughout the load phase.

Because `gemmini_extended3_config_ld` takes an `id` parameter (0 = mvin, 1 = mvin2), the two ports can be configured with different strides independently without interfering with each other.

### Why This Helps

The current bottleneck in the load phase is DRAM bandwidth serialized through a single DMA channel. With two independent channels active simultaneously:
- DRAM bandwidth is better utilized (two in-flight requests).
- Total load latency for tiles overlaps rather than adds.
- The compute phase (`gemmini_loop_ws_spad`) can start sooner.

### Concrete Code Change

```c
void solution(void) {
  // im2col
  for (int pi = 0; pi < CONV_H / CONV_KSZ; pi++)
    for (int pj = 0; pj < PATCHES_X; pj++)
      for (int c = 0; c < CONV_C; c++)
        for (int dy = 0; dy < CONV_KSZ; dy++)
          for (int dx = 0; dx < CONV_KSZ; dx++)
            A_buf[pi * PATCHES_X + pj][c * CONV_KSZ * CONV_KSZ + dy * CONV_KSZ + dx] =
                X_in[c][pi * CONV_KSZ + dy][pj * CONV_KSZ + dx];

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
      1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure port 0 (mvin) for A: stride = MATMUL_K columns of elem_t
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Configure port 1 (mvin2) for B: stride = MATMUL_K columns of elem_t
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Interleave A and B tile loads across independent DMA ports
  // Outer loops: iterate over all (i,k) and (j,k) pairs together
  // We issue one A-tile on port 0 then one B-tile on port 1 back-to-back
  // so both DMAs stay busy simultaneously.
  int ai = 0, bi = 0;
  int total_a = tiles_I * tiles_K;
  int total_b = tiles_J * tiles_K;
  int max_total = (total_a > total_b) ? total_a : total_b;

  for (int idx = 0; idx < max_total; idx++) {
    if (idx < total_a) {
      int i = idx / tiles_K;
      int k = idx % tiles_K;
      gemmini_extended_mvin(
          (void*)(((elem_t*)A_buf) + i * DIM * MATMUL_K + k * DIM),
          a_base + (i * tiles_K + k) * DIM,
          DIM, DIM);
    }
    if (idx < total_b) {
      int j = idx / tiles_K;
      int k = idx % tiles_K;
      gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
          b_base + (j * tiles_K + k) * DIM,
          DIM, DIM);
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors,
      tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0,
      a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST,
      false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```

### Summary

By splitting A and B loads onto ports 0 and 1 (`mvin` and `mvin2`) and issuing them in an interleaved fashion, both DMA channels are active simultaneously. This overlaps the two previously-sequential DRAM fetch streams, reducing total mvin latency toward the time of the larger of the two transfers rather than their sum—a meaningful improvement when tile counts for A and B are comparable.
