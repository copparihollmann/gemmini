**Specific plan:** Restructure the inner `for (int k = ...)` loop over K-tiles for A to process up to 4 tiles at a time by replacing `gemmini_extended_mvin(..., DIM, DIM)` (cols=DIM, rows=DIM — a 1-tile transfer) with `gemmini_extended_mvin(..., 4*DIM, DIM)` (cols=4*DIM, rows=DIM — a 4-tile block transfer) whenever 4 consecutive K-tiles remain. The key insight: `gemmini_extended_mvin(dram_ptr, spad_addr, cols, rows)` with `cols = block_len * DIM` and `rows = DIM` transfers `block_len` consecutive DIM-wide tiles in one instruction (up to MAX_BLOCK_LEN=4). The DRAM pointer advances by `block_len * DIM * sizeof(elem_t)` bytes, and the spad address is the base of the first tile in the block — the hardware fills consecutive spad rows automatically.

**Why this improves performance:** Reducing the number of RoCC instruction dispatches from `tiles_K` down to `ceil(tiles_K/4)` per I-row:
- Decreases instruction-issue overhead on the host CPU
- Reduces the number of DMA command-queue entries, allowing the DMA engine to sustain higher throughput
- Frees CPU cycles sooner (after issuing fewer commands), so the CPU can begin im2col for the next I-row earlier, increasing overlap between CPU im2col work and DMA transfers

For the B tiles, the same unrolling can be applied to the `k` loop.
