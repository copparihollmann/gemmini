## Analysis of the Baseline Code

Looking at the baseline, the `gemmini_mxquant_config_mvout` call uses:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
```

The `lut_update_granularity` is set to **1**, meaning the requantizer refreshes its LUT on every single tile during the output write-back phase. With `tiles_I=4`, `tiles_J=2`, `tiles_K=8` (since MATMUL_M=64, MATMUL_N=32, MATMUL_K=128, divided by DIM=16), this causes 4×2×8 = 64 LUT refresh operations.

## Selected Strategy: #14 — Increase `lut_update_granularity`

### Why This Strategy Applies

The problem uses FP8 format (`act_mx_fmt=0`, `wgt_mx_fmt=0`, `out_mx_fmt=3` for BF16 output, `uselut=0`). All output tiles share the same weight format throughout the entire matmul. The `lut_update_granularity` G controls how often the requantizer's LUT refreshes during the output quantization pass. Setting G=1 means a refresh on every tile step, which is maximally conservative but wasteful. Since all B tiles use the same weight format and the scales are loaded once before the loop, the LUT state does not change between tiles — correctness is preserved with a much larger G.

### Concrete Change

The maximum sensible value for G in this problem is `tiles_K` (= K/DIM = 128/16 = 8), which means the LUT refreshes only once per (I,J) output tile pair rather than once per (I,J,K) triple. This reduces LUT refresh overhead by a factor of `tiles_K` = 8.

### Plan

Change this single line:
```c
// Before:
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

// After:
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
```

No other changes are needed. The rest of the sequence (config_ex, load_scales, mvin, loop_ws_spad, read_smem, fence) remains identical and in correct order.

```c
void solution(void) {
  // im2col: patch (pi,pj) -> row pi*PATCHES_X+pj; column c*k*k + dy*k + dx
  for (int pi = 0; pi < CONV_H / CONV_KSZ; pi++)
    for (int pj = 0; pj < PATCHES_X; pj++)
      for (int c = 0; c < CONV_C; c++)
        for (int dy = 0; dy < CONV_KSZ; dy++)
          for (int dx = 0; dx < CONV_KSZ; dx++)
            A_buf[pi * PATCHES_X + pj][c * CONV_KSZ * CONV_KSZ + dy * CONV_KSZ + dx] =
                X_in[c][pi * CONV_KSZ + dy][pj * CONV_KSZ + dx];

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++)
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin((void*)(((elem_t*)A_buf) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
  for (int j = 0; j < tiles_J; j++)
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                            b_base + (j * tiles_K + k) * DIM, DIM, DIM);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
