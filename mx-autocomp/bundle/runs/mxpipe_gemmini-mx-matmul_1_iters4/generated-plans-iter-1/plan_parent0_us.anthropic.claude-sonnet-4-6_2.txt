## Analysis of the Original Code

The original code loads A tiles using `gemmini_extended_mvin` and B tiles also using `gemmini_extended_mvin` (the same port). This means A and B DMA transfers are serialized — the hardware cannot overlap them because they both go through the same mvin channel.

Looking at the B tile loop specifically:
```c
for (int j = 0; j < tiles_J; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                          b_base + (j * tiles_K + k) * DIM, DIM, DIM);
```

B tiles are loaded via `gemmini_extended_mvin` (funct `k_MVIN`), the same instruction used for A tiles. The hardware has **three independent mvin ports**: `k_MVIN` (mvin), `k_MVIN2` (mvin2), and `k_MVIN3` (mvin3). By using the same port for both A and B, all B loads are serialized behind the A loads.

## Selected Strategy: #12 — Replace `gemmini_extended_mvin` with `gemmini_extended_mvin2` for B-tile loads

## Plan

**Change**: Replace every `gemmini_extended_mvin` call in the B tile loading loop with `gemmini_extended_mvin2`, which uses the dedicated second DMA port (`k_MVIN2`).

**Specific change in the code**:

The A tile loads remain on `gemmini_extended_mvin` (port 0). The B tile loads switch to `gemmini_extended_mvin2` (port 1):

```c
// A tiles: keep using gemmini_extended_mvin (port 0)
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int i = 0; i < tiles_I; i++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                          a_base + (i * tiles_K + k) * DIM, DIM, DIM);

// B tiles: switch to gemmini_extended_mvin2 (port 1) — same stride config applies
for (int j = 0; j < tiles_J; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin2((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                           b_base + (j * tiles_K + k) * DIM, DIM, DIM);
```

**Why this works**: The `gemmini_config_ld` stride configuration set before the A loads (stride = `MATMUL_K * sizeof(elem_t)`) also applies to mvin2 because the same configured stride is used for both ports in this hardware. The scratchpad addresses, tile dimensions, and DRAM pointer arithmetic remain identical — only the RoCC funct field changes from `k_MVIN` to `k_MVIN2`. The hardware can now issue A and B DMA transfers concurrently, overlapping the two sets of 4 tiles (tiles_I×tiles_K = 4 A-tiles, tiles_J×tiles_K = 4 B-tiles for a 32×32×32 problem with DIM=16), reducing total DMA stall time and allowing the systolic array to start sooner.
