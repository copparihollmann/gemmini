## Analysis of the Original Code

Looking at the original code, I notice that `gemmini_block_mvin` is used to load A and B tiles. This macro is defined as:

```c
#define gemmini_block_mvin(dram_addr, spad_addr, len) \
  gemmini_extended_mvin(dram_addr, spad_addr, (len) * DIM, DIM)
```

It always uses `rows=DIM` (1 tile row) and `cols=len*DIM`. With `tiles_K=4` for a 64×64 matrix (K=64, DIM=16), each call loads 4 tiles in one command — that's the MAX_BLOCK_LEN=4 limit being reached in a single call per row-of-tiles.

**But the A and B mvin loops are completely sequential**: first all A tiles are loaded, then all B tiles. The hardware has **separate DMA ports** (mvin vs mvin2) for A and B that can operate concurrently.

## New Strategy: Interleave A and B Loads Using Separate DMA Ports (mvin + mvin2)

**Strategy:** Restructure the mvin loops so that within a single loop iteration, an A-tile row is loaded via `gemmini_extended_mvin` (port 0) and a B-tile row is loaded via `gemmini_extended_mvin2` (port 1) back-to-back in the same iteration, allowing the hardware to overlap both DMA transfers simultaneously.

**Why this improves performance:** The current code issues all A mvins sequentially, then all B mvins sequentially — the B DMA port sits idle while A loads, and vice versa. By interleaving the commands, both DMA channels can be active concurrently, roughly halving the effective data movement latency for the mvin phase.

## Implementation

```c
void solution(void) {
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
        1, 1, 0, 0, false, 0, 0, 3, 0);
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    // Configure stride for both mvin ports (same row stride = MATMUL_K bytes)
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

    // Interleave A (port 0) and B (port 1) loads within the same loop.
    // tiles_I == tiles_J for this 64x64 problem (both = 4), so we can
    // pair each A row with a B row. Loop over the common count.
    int common = (tiles_I < tiles_J) ? tiles_I : tiles_J;
    int i, j;
    for (i = 0, j = 0; i < common && j < common; i++, j++) {
        // Load one full row of A tiles (all K blocks for row i) via port 0
        gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + i * DIM * MATMUL_K),
            a_base + i * tiles_K * DIM,
            tiles_K * DIM, DIM);
        // Load one full row of B tiles (all K blocks for col j) via port 1
        gemmini_extended_mvin2(
            (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K),
            b_base + j * tiles_K * DIM,
            tiles_K * DIM, DIM);
    }
    // Handle remaining A rows if tiles_I > tiles_J
    for (; i < tiles_I; i++) {
        gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + i * DIM * MATMUL_K),
            a_base + i * tiles_K * DIM,
            tiles_K * DIM, DIM);
    }
    // Handle remaining B cols if tiles_J > tiles_I
    for (; j < tiles_J; j++) {
        gemmini_extended_mvin2(
            (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K),
            b_base + j * tiles_K * DIM,
            tiles_K * DIM, DIM);
    }

    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0,
                         a_base, BANK_NUM * BANK_ROWS, 0,
                         SPAD_DEST,
                         false, false, false, false, false,
                         NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
}
```

**Key changes:**
1. Both mvin ports are configured with the same stride using `gemmini_extended3_config_ld(..., id=0)` and `gemmini_extended3_config_ld(..., id=1)`.
2. Within a single loop iteration, `gemmini_extended_mvin` (port 0, A) and `gemmini_extended_mvin2` (port 1, B) are issued back-to-back, letting the hardware pipeline both DMA transfers concurrently.
3. `cols = tiles_K * DIM = 4 * 16 = 64` fits within MAX_BLOCK_LEN=4 tiles per command, so each call loads an entire row of K-tiles in one command — same total command count as the original, but now A and B loads overlap in hardware.
