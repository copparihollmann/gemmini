## Analysis of the Original Code

Looking at the original code, I need to identify which strategy applies:

```c
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int i = 0; i < tiles_I; i++)
    gemmini_block_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K),
                       a_base + i * tiles_K * DIM, tiles_K);
for (int j = 0; j < tiles_J; j++)
    gemmini_block_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K),
                       b_base + j * tiles_K * DIM, tiles_K);
```

The A-loop uses `gemmini_block_mvin` (port 0) and the B-loop also uses `gemmini_block_mvin` (port 0, since `gemmini_block_mvin` calls `gemmini_extended_mvin`). These are issued sequentially — all A tiles first, then all B tiles — which means A and B DMA transfers cannot overlap.

## Selected Strategy: #9 — Interleave A and B mvin Commands Using Separate Ports

**Strategy 9** says: issue A mvin on port 0 (`gemmini_extended_mvin`) and B mvin on port 1 (`gemmini_extended_mvin2`) within the same loop iteration, allowing hardware to overlap A and B DMA transfers.

## Plan

1. **Merge the two separate loops** (one over `i` for A, one over `j` for B) into a **single loop** that iterates over `max(tiles_I, tiles_J)` steps. Since `tiles_I == tiles_J` for square matrices (both equal `MATMUL_M/DIM` and `MATMUL_N/DIM`), a single loop from 0 to `tiles_I` (= `tiles_J`) covers both.

2. **Inside this single loop**, issue the A tile load using `gemmini_extended_mvin` (port 0) and the B tile load using `gemmini_extended_mvin2` (port 1) **back-to-back within the same loop iteration**. Since `gemmini_block_mvin` calls `gemmini_extended_mvin` with `cols = tiles_K * DIM` and `rows = DIM`, we replicate this with the appropriate port call for B.

3. **`gemmini_config_ld` applies to port 0 only** (id=0). Port 1 (`mvin2`) has its own config. We must also call `gemmini_extended3_config_ld` or `gemmini_extended4_config_ld` with `id=1` to set the stride for port 1, since B has the same stride (`MATMUL_K * sizeof(elem_t)`).

4. The rest of the code (config_ex, load_scales, config_st, mxquant_config_mvout, loop_ws_spad, read_smem, fence) remains unchanged.

void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure stride for port 0 (A) and port 1 (B) — same stride since both are row-major with K columns
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0); // port 0 for A
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1); // port 1 for B

  // Interleave A (port 0) and B (port 1) mvin commands in the same loop
  // to allow hardware DMA overlap between A and B transfers
  for (int ij = 0; ij < tiles_I; ij++) {
    gemmini_extended_mvin(
        (void*)(((elem_t*)A_in) + ij * DIM * MATMUL_K),
        a_base + ij * tiles_K * DIM,
        tiles_K * DIM, DIM);
    gemmini_extended_mvin2(
        (void*)(((elem_t*)B_in) + ij * DIM * MATMUL_K),
        b_base + ij * tiles_K * DIM,
        tiles_K * DIM, DIM);
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
