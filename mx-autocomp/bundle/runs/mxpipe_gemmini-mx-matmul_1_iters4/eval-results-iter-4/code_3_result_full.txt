Looking at the baseline code for a 32×32×32 FP8 matmul (tiles_I=2, tiles_J=2, tiles_K=2):

```c
// Two separate loops loading A and B tiles sequentially via the SAME mvin port
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int i = 0; i < tiles_I; i++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin(..., a_base + (i*tiles_K+k)*DIM, DIM, DIM);  // mvin port
for (int j = 0; j < tiles_J; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin(..., b_base + (j*tiles_K+k)*DIM, DIM, DIM);  // same mvin port
```

**The key inefficiency:** A tiles and B tiles are loaded sequentially using only `gemmini_extended_mvin` (port 0). The hardware provides three independent mvin ports: `mvin` (port 0), `mvin2` (port 1), and `mvin3` (port 2). By using `mvin2` for B tiles, the hardware can overlap A and B tile loads simultaneously, halving the effective DMA latency before compute begins.

## Plan: Apply Strategy 9 — Use mvin2 port to parallelize A and B tile loads

**Specific change:** Use `gemmini_extended_mvin` for A tiles and `gemmini_extended_mvin2` for B tiles, issuing them in an interleaved fashion so both DMA channels are active concurrently.

**Steps:**

1. Keep `gemmini_config_ld` for port 0 (A tiles stride). Use `gemmini_extended3_config_ld` with `id=1` to configure port 1 (mvin2) with the B stride = `MATMUL_K * sizeof(elem_t)`.

2. Interleave the A and B mvin calls in a single merged loop so both ports get issued back-to-back, allowing the hardware to overlap their DMA transfers:

```c
// Configure both mvin ports
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0); // port 0 for A
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1); // port 1 for B

// Interleave A and B loads across both ports
for (int i = 0; i < tiles_I; i++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin((void*)(((elem_t*)A_in) + i*DIM*MATMUL_K + k*DIM),
                          a_base + (i*tiles_K + k)*DIM, DIM, DIM);

for (int j = 0; j < tiles_J; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin2((void*)(((elem_t*)B_in) + j*DIM*MATMUL_K + k*DIM),
                           b_base + (j*tiles_K + k)*DIM, DIM, DIM);
```

By issuing all A mvins then all B mvin2s in sequence, the command queue fills both DMA ports so they operate in parallel. The B tiles use port 1 (`mvin2`) which is independent of port 0, allowing the scratchpad to receive A and B data simultaneously rather than serially.
