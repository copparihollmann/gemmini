Both A and B tiles are loaded **sequentially** using the same `mvin` port. The hardware has **independent mvin and mvin2 ports** that can operate in parallel. Loading B tiles through `mvin2` while A tiles are loading through `mvin` would allow both DMA engines to run simultaneously, cutting effective load latency roughly in half.

## Plan

1. **Change the B tile mvin loop to use `gemmini_extended_mvin2` instead of `gemmini_extended_mvin`**. The `mvin2` port has its own configuration register, so we need to issue a `gemmini_extended3_config_ld` (or equivalent) with `id=1` to set the stride for the mvin2 port before issuing mvin2 commands.

2. **Interleave the A and B mvin commands** so that for each `(i, j, k)` combination, we issue an A tile load via `mvin` and a B tile load via `mvin2` back-to-back. This lets the hardware dispatch both DMA requests simultaneously since they target independent ports.

3. **Restructure the loop nest** to iterate over `(i, j, k)` together, issuing paired `mvin` + `mvin2` calls per iteration. Since all A tiles and all B tiles must be in the scratchpad simultaneously anyway (as required by `gemmini_loop_ws_spad`), we can interleave the loads without violating the memory layout constraints. Specifically, we can loop over `k` in the outer loop, and for each `k` emit A loads across all `i` and B loads across all `j` interleaved, or simply restructure so each A[i,k] is followed immediately by B[j,k] for some j.

4. **The simplest correct restructuring**: keep the original scratchpad layout unchanged (`a_base + (i*tiles_K + k)*DIM` for A, `b_base + (j*tiles_K + k)*DIM` for B), but rewrite the two separate sequential loops into a single loop over `k`, issuing all `i`-indexed A mvins and all `j`-indexed B mvin2s for that `k` slice interleaved. This maximizes the chance the hardware can dispatch both ports simultaneously.

5. **Issue `gemmini_extended3_config_ld` with `id=1`** before the mvin2 calls to configure the mvin2 port's stride to `MATMUL_K * sizeof(elem_t)`. The `id=0` config already covers mvin, and `id=1` covers mvin2.
