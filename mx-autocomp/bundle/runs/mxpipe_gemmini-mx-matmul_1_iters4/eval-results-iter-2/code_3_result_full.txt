## New Strategy: Fix FP4 B-Matrix Stride and Use Separate `gemmini_config_ld` for A vs B

**Strategy: Use separate `gemmini_config_ld` configurations for A and B to correctly set the FP4-packed stride for B, and ensure the B DRAM pointer arithmetic accounts for the 2:1 packing ratio.**

### How It Improves Performance/Correctness

The current code sets `gemmini_config_ld(MATMUL_K * sizeof(elem_t))` and uses it for both A and B. For FP4, B is packed 2 elements per byte, so:
- **A stride** (fp4 activation, row-major): `MATMUL_K * sizeof(elem_t)` = `MATMUL_K` bytes per row
- **B stride** (fp4 weight, packed): `MATMUL_N * sizeof(elem_t) / 2` = `MATMUL_N / 2` bytes per row

Using the wrong stride for B means the DMA loads data from wrong DRAM locations, causing **silently incorrect results** and wasted memory bandwidth from cache thrashing. Fixing this with a separate `gemmini_config_ld` before the B mvins ensures correct tile loading.
