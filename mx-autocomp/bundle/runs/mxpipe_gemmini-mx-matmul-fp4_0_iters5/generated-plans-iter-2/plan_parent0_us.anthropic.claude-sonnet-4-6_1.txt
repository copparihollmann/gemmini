## Analysis

The original code uses `ti = MATMUL_M/DIM/2 = 4`, `tj = MATMUL_N/DIM/2 = 4`, `tk = MATMUL_K/DIM = 16` as half-dimension tile counts. The scratchpad utilization report says 0KB used — this is because the single `gemmini_loop_ws_spad` call already handles the full tiled computation internally, but the A and B tiles are loaded for only the half-dimension subproblem.

Looking more carefully: the original uses `ti=4, tj=4, tk=16` for a 128×128×256 problem where full tile counts would be `tiles_I=8, tiles_J=8, tiles_K=16`. The baseline only computes a quarter of the output (4×4 tiles of C). Wait — re-reading: `MATMUL_M/DIM/2 = 128/16/2 = 4`. This means the original is deliberately halving I and J, doing only a 64×64 submatrix.

Actually, looking again at rule 14: `tiles_I=M/DIM`, `tiles_J=N/DIM`, `tiles_K=K/DIM`. The original uses half tile counts. This is either a double-buffer setup or a bug. Given the feedback says "scratchpad utilization 0KB out of 256KB", the full 128×128 matmul isn't being computed correctly in a single pass.

The key strategy I'll apply is **strategy 11: reorder I/J/K loop nest** combined with the natural approach — use the full `tiles_I=8, tiles_J=8, tiles_K=16` and partition into two halves via **double buffering (strategy 4)** to fit within scratchpad.

Let me check scratchpad fit with full dimensions:
- `tiles_I=8, tiles_J=8, tiles_K=16`
- A rows: `8*16*16 = 2048`
- B rows: `8*16*16 = 2048`  
- Total: 4096 rows ≤ 8192 ✓

The full problem fits in a single pass! The original unnecessarily halved the tile counts. The fix is to use full tile counts and do the entire matmul in one `gemmini_loop_ws_spad` call.

## Plan: Use Full Tile Counts (Strategy 2 — Loop Tiling / Correct Tiling)

The original code uses `ti = MATMUL_M/DIM/2` and `tj = MATMUL_N/DIM/2`, halving both I and J tile dimensions without necessity. This means only 1/4 of the output matrix is computed, which is semantically incorrect OR the loop is being issued multiple times (it isn't). The scratchpad has room for the full problem.

**Plan:**
1. Set `ti = MATMUL_M/DIM = 8`, `tj = MATMUL_N/DIM = 8`, `tk = MATMUL_K/DIM = 16`
2. Verify scratchpad fit: A uses `ti*tk*DIM = 8*16*16 = 2048` rows, B uses `tj*tk*DIM = 8*16*16 = 2048` rows, total 4096 ≤ 8192 ✓
3. Update `bb = BANK_NUM*BANK_ROWS - tk*tj*DIM = 8192 - 16*8*16 = 8192 - 2048 = 6144`
4. Update mvin loops to cover all `ti×tk` A tiles and all `tk×tj` B tiles
5. Update `gemmini_mxquant_config_mvout` bounds to `ti, tj, tk`
6. Issue single `gemmini_loop_ws_spad(ti, tj, tk, ...)` covering the full 128×128×256 matmul
7. Issue `gemmini_mx_read_smem` for full `MATMUL_M * MATMUL_N` elements

```c
void solution(void) {
  {
    int ti = MATMUL_M / DIM;   // 8
    int tj = MATMUL_N / DIM;   // 8
    int tk = MATMUL_K / DIM;   // 16
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;  // 8192 - 2048 = 6144
    int SDST = 128;

    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
        1, 1, 0, 0, false, 2, 2, 3, 0);

    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 1);

    // MVIN A: all ti*tk tiles
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++)
      for (int k = 0; k < tk; k++)
        gemmini_extended_mvin(
            (void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM),
            ab + (i*tk + k)*DIM, DIM, DIM);

    // MVIN B: all tk*tj tiles (fp4 packs 2/byte → stride = MATMUL_N/2)
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++)
      for (int j = 0; j < tj; j++)
        gemmini_extended_mvin(
            (void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2) + j*DIM),
            bb + (k*tj + j)*DIM, DIM, DIM);

    // Full tiled matmul in one hardware loop
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0,
        ab, BANK_NUM * BANK_ROWS, 0, SDST,
        false, false, false, false, false,
        NO_ACTIVATION, 0, 0, false, 0x38);

    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
