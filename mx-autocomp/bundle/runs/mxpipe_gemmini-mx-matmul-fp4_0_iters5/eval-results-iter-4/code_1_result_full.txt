## Selected Strategy: **Reuse loaded B (weight) tiles across multiple I-tile iterations without re-mvin**

### Plan

The key insight is that B tiles are loaded once but could serve all `ti` I-tile iterations. Currently, the code loads ALL A tiles and ALL B tiles upfront, then runs a single `gemmini_loop_ws_spad`. This is correct but uses only half the tiles (ti=4, tj=4).

**The real opportunity**: change `ti` and `tj` to use the **full** matrix dimensions (`tiles_I = MATMUL_M/DIM = 8`, `tiles_J = MATMUL_N/DIM = 8`) and verify the scratchpad constraint is satisfied.

Full dimensions:
- `tiles_I = 8`, `tiles_K = 16`, `tiles_J = 8`
- A tiles: `8 × 16 × 16 = 2048` rows
- B tiles: `8 × 16 × 16 = 2048` rows  
- Total: `4096` rows ≤ `8192` ✓
- Accumulator: `8 × 8 × 16 = 1024` rows > `256` ✗

Accumulator overflow! So we need to split over J or I. The strategy is: **fix `tj` to fit accumulator, loop over I-blocks, reuse B tiles across I-block iterations without re-mvin**.

With `tj=4` (half N), `ti=4` (half M), accumulator = `4×4×16 = 256` ✓. Now loop over 2 I-blocks, reusing B each time.

- Load B once (all `tk × tj` tiles at `b_base`)
- For each I-block: load A tiles, run `gemmini_loop_ws_spad`, read smem
- B is never reloaded → saves `tk × tj × MAX_BLOCK_LEN`-batched mvin commands on the second I-block iteration

This implements strategy 3: **reuse loaded B tiles across multiple I-tile iterations without re-mvin**.

The B placement stays at `b_base = BANK_NUM*BANK_ROWS - tk*tj*DIM` (fixed for all iterations).  
A tiles for I-block `ib` go at `a_base + (i_local*tk + k)*DIM` (same `ab=0` base, overwritten each I-block — this is safe since `gemmini_loop_ws_spad` consumes them before the next I-block's A mvin begins, enforced by the implicit ordering of the hardware queue).

The `gemmini_mxquant_config_mvout` and `gemmini_mx_read_smem` output address must be adjusted per I-block to write to the correct row of `C_hw`.

```c
void solution(void) {
  int tiles_I_full = MATMUL_M / DIM;  // 8
  int tiles_J      = MATMUL_N / DIM / 2;  // 4  (half N to fit accumulator)
  int tiles_K      = MATMUL_K / DIM;  // 16

  // I-blocking: split tiles_I_full into 2 blocks of ti each
  int ti_block = tiles_I_full / 2;  // 4

  // Scratchpad check: (ti_block*tiles_K + tiles_J*tiles_K)*DIM
  // = (4*16 + 4*16)*16 = (64+64)*16 = 2048 <= 8192 OK
  // Accumulator check: ti_block*tiles_J*DIM = 4*4*16 = 256 <= 256 OK

  uint32_t ab   = 0;
  uint32_t bb   = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
  int      SDST = 128;

  static uint32_t scale_factors[512] __attribute__((aligned(32))) = {0};

  // Step 1: Configure execution with FP4 E2M1 format (done once)
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
      1, 1, 0, 0, false, 2, 2, 3, 0);

  // Step 2: Load scale factors for A and B (done once — covers full matrix)
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Step 3: No LUT needed for FP4 E2M1 with uselut=0

  // Step 4b: MVIN B tiles ONCE — reused across all I-block iterations
  // B stride: MATMUL_N/2 bytes per row (FP4 packed)
  gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t) / 2, MVIN_SCALE_IDENTITY, false, 1);
  for (int k = 0; k < tiles_K; k++) {
    int j = 0;
    while (j < tiles_J) {
      int batch = tiles_J - j;
      if (batch > MAX_BLOCK_LEN) batch = MAX_BLOCK_LEN;
      gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + k * DIM * (MATMUL_N / 2) + j * DIM),
          bb + (k * tiles_J + j) * DIM,
          DIM * batch,
          DIM);
      j += batch;
    }
  }

  // Loop over I-blocks: B is already in scratchpad, reuse it
  for (int ib = 0; ib < 2; ib++) {
    int i_global_start = ib * ti_block;  // global tile-I offset

    // Step 4a: MVIN A tiles for this I-block (overwrite ab region)
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
    for (int i = 0; i < ti_block; i++) {
      int ig = i_global_start + i;  // global row-tile index for DRAM addressing
      int k = 0;
      while (k < tiles_K) {
        int batch = tiles_K - k;
        if (batch > MAX_BLOCK_LEN) batch = MAX_BLOCK_LEN;
        gemmini_extended_mvin(
            (void*)(((elem_t*)A_in_hw) + ig * DIM * MATMUL_K + k * DIM),
            ab + (i * tiles_K + k) * DIM,
            DIM * batch,
            DIM);
        k += batch;
      }
    }

    // Step 5: Configure requantized mvout for this I-block
    // Output rows for this block: rows [i_global_start*DIM .. (i_global_start+ti_block)*DIM)
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors,
        ti_block, tiles_J, tiles_K,
        0, 0, 1);

    // Step 6: Compute weight-stationary tiled matmul for this I-block
    // B tiles remain at bb from the single mvin above
    gemmini_loop_ws_spad(ti_block, tiles_J, tiles_K, 0, 0, 0,
        ab, BANK_NUM * BANK_ROWS, 0, SDST,
        false, false, false, false, false,
        NO_ACTIVATION, 0, 0, false, 0x38);

    // Step 7: Drain results — write to the correct output rows for this I-block
    // smem offset: SDST*16 (in bf16 units)
    // output destination: C_hw[i_global_start*DIM][0]
    gemmini_mx_read_smem(
        &C_hw[i_global_start * DIM][0],
        SDST * 16,
        ti_block * DIM * MATMUL_N);
    gemmini_fence();
  }
}
```
