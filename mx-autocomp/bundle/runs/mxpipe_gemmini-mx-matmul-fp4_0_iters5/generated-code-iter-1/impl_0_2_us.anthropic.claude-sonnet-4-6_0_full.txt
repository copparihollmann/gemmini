Looking at the original code, I need to understand what it does:
- 128x128x256 FP4 (E2M1) matmul
- `ti = M/DIM/2 = 128/16/2 = 4`, `tj = N/DIM/2 = 4`, `tk = K/DIM = 16`
- It only computes a quarter of the output (ti×tj = 4×4 tiles instead of full 8×8)

Wait, re-reading: `ti = MATMUL_M/DIM/2 = 4`, `tj = MATMUL_N/DIM/2 = 4`. This seems like a bug or the original is computing a sub-block. Since I need semantic equivalence, I'll preserve the same ti, tj, tk values and logic, just optimize the mvin pattern.

Key optimizations:
1. Use `gemmini_extended_mvin2` for B tiles (separate port from A tiles to overlap loads)
2. Batch mvin calls using `MAX_BLOCK_LEN=4` to reduce instruction count
3. Reorder loops to improve locality

The B matrix stride: `MATMUL_N * sizeof(elem_t) / 2` - FP4 packs 2 elements per byte, so stride is `MATMUL_N/2` bytes.

For A: stride is `MATMUL_K * sizeof(elem_t) = MATMUL_K` bytes (FP4, but elem_t=uint8_t, so MATMUL_K bytes... actually for FP4 it's MATMUL_K/2). The original uses `MATMUL_K * sizeof(elem_t)` which equals `MATMUL_K`.

I'll preserve the original strides exactly and optimize by batching mvins and using mvin2 for B.

```c
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;

    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
        1, 1, 0, 0, false, 2, 2, 3, 0);

    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    // Mvin A tiles using mvin (port 0), stride = MATMUL_K * sizeof(elem_t)
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += MAX_BLOCK_LEN) {
        int batch = tk - k < MAX_BLOCK_LEN ? tk - k : MAX_BLOCK_LEN;
        for (int b = 0; b < batch; b++) {
          gemmini_extended_mvin(
            (void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + (k+b)*DIM),
            ab + (i*tk + k + b)*DIM,
            DIM, DIM);
        }
      }
    }

    // Mvin B tiles using mvin2 (port 1), stride = MATMUL_N/2 * sizeof(elem_t)
    gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t) / 2, MVIN_SCALE_IDENTITY, false, 1);
    for (int k = 0; k < tk; k++) {
      for (int j = 0; j < tj; j += MAX_BLOCK_LEN) {
        int batch = tj - j < MAX_BLOCK_LEN ? tj - j : MAX_BLOCK_LEN;
        for (int b = 0; b < batch; b++) {
          gemmini_extended_mvin2(
            (void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2) + (j+b)*DIM),
            bb + (k*tj + j + b)*DIM,
            DIM, DIM);
        }
      }
    }

    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors,
        ti, tj, tk, 0, 0, 1);

    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0,
        ab, BANK_NUM * BANK_ROWS, 0, SDST,
        false, false, false, false, false,
        NO_ACTIVATION, 0, 0, false, 0x38);

    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
