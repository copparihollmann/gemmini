## Analysis

Looking at the original code, the outer loop is `i0` (rows) outer, `j0` (columns) inner. For each `(i0, j0)` pair:
1. B scales are copied via `memcpy` from `B_scales_col`
2. B tiles are mvin'd from DRAM into the scratchpad
3. The full computation runs

This means for a fixed `j0`, the **same B tiles and B scale factors** are loaded repeatedly for every `i0` iteration — pure redundant work. Strategy 11 directly addresses this.

## Selected Strategy: #11 — Restructure to j0-outer / i0-inner, loading B tiles and B scales once per j0

### Plan

**Restructure the loop nest to `j0`-outer, `i0`-inner.**

For a fixed `j0`, B's data (both tiles and scales) is identical across all `i0` iterations. By making `j0` the outer loop:

1. **B scale memcpy and `gemmini_mx_load_scales` for B** move outside the `i0` loop — executed once per `j0` instead of `BLOCKS_M` times per `j0`.
2. **B tile mvin loop** moves outside the `i0` loop — the B tiles are loaded into their fixed scratchpad region (`b_base`) once per `j0` and reused for all `i0` iterations.
3. The **`gemmini_extended3_config_ex`** and **`gemmini_flush`** also move outside the `i0` loop since they are format-invariant (strategy 4 is a bonus here, but the key move is B reuse).
4. Inside the `i0` loop, only the A-side work remains: A scale memcpy, `gemmini_mx_load_scales` for A, A tile mvin, then compute and readout.

**Scratchpad capacity check:** The current code uses `tiles = BLK/DIM` tiles in I and J, `tiles_K = MATMUL_K/DIM` in K. The scratchpad constraint is `(tiles_I*tiles_K + tiles_J*tiles_K)*DIM ≤ 8192`. Since `BLK`, `MATMUL_K`, `BLOCKS_M`, `BLOCKS_N` are unchanged, B tiles occupy exactly the same region as before — only the *number of times we mvin them* changes. The layout is identical and remains valid.

**Correctness:** The programming model sequence must still be honored inside the `i0` loop: `config_ex` (already done once outside) → `mx_load_scales` (A only, since B scales are already loaded and unchanged) → mvin A tiles → `mxquant_config_mvout` → `loop_ws_spad` → `mx_read_smem` → `fence`. Since B scales don't change across `i0`, reusing the loaded B scale buffer is correct per rule 15.

**Instruction count reduction:** B scale memcpy (`MATMUL_K/32` calls), `gemmini_mx_load_scales` (1 call), and B mvin (`tiles * tiles_K` calls) are reduced by a factor of `BLOCKS_M`, directly proportional to the number of row blocks.
