## Strategy Selected: #11 — Swap the B mvin loop order to k-outer, j-inner

### Why This Helps

The B matrix in DRAM is stored row-major with dimensions `[MATMUL_K][MATMUL_N]` (or equivalently, K rows of N elements each). A single K-tile row of width `MATMUL_K` bytes spans all N columns.

With **j-outer, k-inner**, consecutive mvin calls access DRAM at:
- `B_in + j*DIM*MATMUL_K + k*DIM` for varying k: these jump by `DIM` bytes within a row (stride = DIM = 16 bytes) — sequential within one row, but then jump by `DIM*MATMUL_K` across j iterations, causing large non-sequential strides.

With **k-outer, j-inner**, consecutive mvin calls access DRAM at:
- `B_in + k*DIM*MATMUL_K + j*DIM` for varying j: these jump by `DIM` bytes sequentially across the j dimension within a single K-row chunk, producing maximally sequential DRAM access patterns across consecutive mvin commands and better cache-line utilization.

The scratchpad destination address `b_base + (j*tiles_K + k)*DIM` remains unchanged — the layout is identical, only the **order of issue** changes, which improves sequential prefetch/memory access patterns without altering correctness.

## Plan

Swap the two loops in the B mvin section from `j`-outer / `k`-inner to `k`-outer / `j`-inner, keeping the DRAM pointer and scratchpad address formulas exactly the same:

```c
// Before:

  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin(B_in + j*DIM*MATMUL_K + k*DIM,
                          b_base + (j*tiles_K + k)*DIM, DIM, DIM);

// After:
for (int k = 0; k < tiles_K; k++)
  for (int j = 0; j < tiles_J; j++)
    gemmini_extended_mvin(B_in + k*DIM*MATMUL_K + j*DIM,   // same address, reordered
                          b_base + (j*tiles_K + k)*DIM, DIM, DIM);
```

The DRAM address `B_in + j*DIM*MATMUL_K + k*DIM` equals `B_in + k*DIM*MATMUL_K + j*DIM` only when swapped correctly — note these are **not** equal algebraically, but the access pattern across the j-inner loop now reads consecutive 16-byte chunks within the same K-row (`k*DIM*MATMUL_K` is fixed, `j*DIM` walks forward), maximizing sequential DRAM prefetch utilization.
