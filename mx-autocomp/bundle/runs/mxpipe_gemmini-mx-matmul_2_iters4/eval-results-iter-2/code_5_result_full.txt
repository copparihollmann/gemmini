## Selected Strategy: Strategy 11

**Swap the B mvin loop order to k-outer, j-inner** to match DRAM row-major layout.

The B matrix in DRAM is laid out as `B_in[MATMUL_K][MATMUL_N]` (K rows, each row has MATMUL_N elements). With `j-outer, k-inner`:
- For j=0: accesses rows k=0,1,...,tiles_K-1 at column offset 0
- For j=1: accesses rows k=0,1,...,tiles_K-1 at column offset DIM

This causes the DMA to jump back to row 0 every time j increments, thrashing prefetch/cache lines.

With `k-outer, j-inner`:
- For k=0: accesses row 0 at columns j=0, DIM, 2*DIM, ... (sequential within the row)
- For k=1: accesses row 1 at columns j=0, DIM, 2*DIM, ...

This reads DRAM sequentially within each K-row before advancing to the next K-row, maximizing cache-line utilization.

The scratchpad address `b_base + (j*tiles_K + k)*DIM` remains **identical** — loop reordering does not change which address each `(j,k)` tile lands at, only the order of issue. Correctness is fully preserved.
