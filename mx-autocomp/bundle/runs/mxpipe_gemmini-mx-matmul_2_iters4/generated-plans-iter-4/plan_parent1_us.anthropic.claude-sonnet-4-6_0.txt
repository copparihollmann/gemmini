## Analysis of the Current Code

The current code loads A tiles with port 0 (`gemmini_extended_mvin`) and B tiles with port 1 (`gemmini_extended_mvin2`) in an interleaved k-first loop. Each tile is loaded with a separate `gemmini_extended_mvin` / `gemmini_extended_mvin2` instruction.

For the current dimensions (MATMUL_M, MATMUL_N, MATMUL_K with DIM=16), let's consider what's happening in the A-tile loads:

In the inner loop over `i` for a fixed `k`, the A tiles are laid out contiguously in scratchpad at addresses `A_BASE + (i * TILES_K + k) * DIM`. For a fixed `k`, as `i` increments from 0 to TILES_I-1, the scratchpad addresses are:
- `A_BASE + (0*TILES_K + k)*DIM`
- `A_BASE + (1*TILES_K + k)*DIM`
- `A_BASE + (2*TILES_K + k)*DIM`
- ...

These are **not** contiguous (they are spaced TILES_K*DIM apart), so we cannot coalesce across `i`.

However, for the B tiles: for a fixed `k`, as `j` increments, the scratchpad addresses are `B_BASE + (j*TILES_K + k)*DIM`, which are also spaced TILES_K*DIM apart — not contiguous.

## Selected Strategy: Strategy 15 — Coalesce A-tile mvins into a single wide mvin

Wait — looking more carefully at the A layout: `a_base + (i*TILES_K + k)*DIM`. For fixed `i`, as `k` goes 0..TILES_K-1, the addresses are `A_BASE + i*TILES_K*DIM + k*DIM` — these **are** contiguous. So the **k-inner loop for fixed i** gives contiguous scratchpad rows.

The current loop is k-outer, i-inner, which breaks contiguity. **Strategy 15** says: coalesce all A-dimension tile mvins for a fixed `i` (iterating over k) into a single wide mvin with `rows = TILES_K * DIM, cols = DIM`, since for fixed `i`, tiles at `k=0..TILES_K-1` are contiguous in the scratchpad.

Similarly for B: for fixed `j`, as `k` goes 0..TILES_K-1, the addresses `B_BASE + j*TILES_K*DIM + k*DIM` are also contiguous. So B tiles for fixed `j` can be coalesced into a single wide mvin2.

This reduces the number of mvin/mvin2 instructions from `TILES_I*TILES_K + TILES_J*TILES_K` down to `TILES_I + TILES_J`, dramatically reducing instruction dispatch overhead.

## Plan

**Switch from k-outer, i/j-inner loops to i-outer (k-inner for A) and j-outer (k-inner for B) loops, then coalesce all k-dimension tiles for each fixed i (or j) into a single wide mvin call.**

Specifically:

1. **Restructure the A mvin loop**: Instead of `for k { for i { mvin 1 tile } }`, do `for i { mvin TILES_K tiles at once }`. For fixed `i`, the DRAM pointer starts at `((elem_t*)A_in) + i*DIM*MATMUL_K + 0*DIM` and the scratchpad address is `A_BASE + i*TILES_K*DIM`. Issue a single `gemmini_extended_mvin(..., A_BASE + i*TILES_K*DIM, DIM, TILES_K*DIM)` (cols=DIM, rows=TILES_K*DIM). But wait — `MAX_BLOCK_LEN=4`, so we can only do 4 rows at a time. If TILES_K > 4, we need to chunk. But if TILES_K ≤ 4, a single call works.

   More precisely: split into chunks of `min(TILES_K, MAX_BLOCK_LEN)` = up to 4 consecutive DIM-row tiles per mvin. This reduces instruction count by up to 4×.

2. **Restructure the B mvin2 loop**: Similarly, for fixed `j`, issue `ceil(TILES_K / MAX_BLOCK_LEN)` calls with `rows = min(chunk, TILES_K - k_start) * DIM`.

3. **The DRAM stride** (`gemmini_extended3_config_ld` stride) must equal `MATMUL_K * sizeof(elem_t)` so that successive DIM-row blocks step by one row of DIM-wide tiles in DRAM. This is already correctly set.

4. **Keep the rest of the code unchanged** (config_ex, load_scales, config_st, mxquant_config_mvout, loop_ws_spad, mx_read_smem, fence).

This directly implements **strategy 15** and reduces the total mvin instruction count significantly.

## Rewritten Code

void solution(void) {
  static const int TILES_I        = MATMUL_M / DIM;
  static const int TILES_J        = MATMUL_N / DIM;
  static const int TILES_K        = MATMUL_K / DIM;
  static const uint32_t A_BASE    = 0;
  static const uint32_t B_BASE    = BANK_NUM * BANK_ROWS - (MATMUL_K / DIM) * (MATMUL_N / DIM) * DIM;
  static const uint32_t SPAD_DEST_ADDR = 0;

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure port 0 (mvin) for A tiles: stride = MATMUL_K bytes (row stride in DRAM)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Configure port 1 (mvin2) for B tiles: stride = MATMUL_K bytes
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Coalesce A tiles: for each i, all k tiles are contiguous in scratchpad.
  // Issue up to MAX_BLOCK_LEN=4 consecutive DIM-row tiles per mvin command.
  for (int i = 0; i < TILES_I; i++) {
    int k = 0;
    while (k < TILES_K) {
      int chunk = TILES_K - k;
      if (chunk > MAX_BLOCK_LEN) chunk = MAX_BLOCK_LEN;
      elem_t *dram_ptr = ((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM;
      uint32_t sp_addr = A_BASE + (i * TILES_K + k) * DIM;
      gemmini_extended_mvin((void*)dram_ptr, sp_addr, DIM, chunk * DIM);
      k += chunk;
    }
  }

  // Coalesce B tiles: for each j, all k tiles are contiguous in scratchpad.
  for (int j = 0; j < TILES_J; j++) {
    int k = 0;
    while (k < TILES_K) {
      int chunk = TILES_K - k;
      if (chunk > MAX_BLOCK_LEN) chunk = MAX_BLOCK_LEN;
      elem_t *dram_ptr = ((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM;
      uint32_t sp_addr = B_BASE + (j * TILES_K + k) * DIM;
      gemmini_extended_mvin2((void*)dram_ptr, sp_addr, DIM, chunk * DIM);
      k += chunk;
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, TILES_I, TILES_J, TILES_K, 0, 0, 1);
  gemmini_loop_ws_spad(TILES_I, TILES_J, TILES_K, 0, 0, 0,
                       A_BASE, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST_ADDR,
                       false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST_ADDR * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
