## Analysis of the Current Code

The current code interleaves A and B tile loads using two DMA ports (mvin and mvin2) in a `k`-outer, then `i`/`j`-inner loop pattern:

```c
for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++)
        gemmini_extended_mvin(...)   // A tiles: row-strided access
    for (int j = 0; j < tiles_J; j++)
        gemmini_extended_mvin2(...)  // B tiles: row-strided access
}
```

**The key inefficiency**: For each `(j, k)` B tile, the DRAM pointer is `B_in + j * DIM * MATMUL_K + k * DIM`. With `k` as the inner loop (but `j` inside `k`-outer), each `j` step jumps by `DIM * MATMUL_K` bytes — a large stride, causing poor DRAM burst efficiency. The B tiles for a fixed `j` are contiguous along `k` (stride = DIM bytes), so iterating **J-outer / K-inner** for B gives sequential DRAM accesses along the K dimension of each B row.

## Selected Strategy: Strategy 8 — J-outer / K-inner Loop Order for B Tiles

**Plan:**

Restructure the mvin loops so that B tiles are loaded with `j` as the outer loop and `k` as the inner loop. For a fixed `j`, the B tile pointer is `B_in + j * DIM * MATMUL_K + k * DIM`, and as `k` increments by 1, the pointer advances by exactly `DIM` bytes — a perfectly sequential DRAM burst. This maximizes memory-level parallelism and burst efficiency for B.

For A tiles, similarly restructure to `i`-outer / `k`-inner, which for a fixed `i` gives pointer `A_in + i * DIM * MATMUL_K + k * DIM` incrementing by `DIM` bytes per `k` step — also sequential.

**Specific changes:**

1. **Separate the A and B mvin loops** (they're already logically separate inside the `k`-outer loop, but now remove the outer `k` loop entirely and give each matrix its own doubly-nested loop).

2. **A tile loop**: Change from `k`-outer/`i`-inner to `i`-outer/`k`-inner:
   ```c
   for (int i = 0; i < tiles_I; i++)
     for (int k = 0; k < tiles_K; k++)
       gemmini_extended_mvin(A_in + i*DIM*MATMUL_K + k*DIM, a_base + (i*tiles_K+k)*DIM, DIM, DIM);
   ```
   For fixed `i`, pointer advances by `DIM` bytes per step — sequential burst.

3. **B tile loop**: Change from `k`-outer/`j`-inner to `j`-outer/`k`-inner:
   ```c
   for (int j = 0; j < tiles_J; j++)
     for (int k = 0; k < tiles_K; k++)
       gemmini_extended_mvin2(B_in + j*DIM*MATMUL_K + k*DIM, b_base + (j*tiles_K+k)*DIM, DIM, DIM);
   ```
   For fixed `j`, pointer advances by `DIM` bytes per step — sequential burst.

4. **Keep `gemmini_config_ld` stride** set to `MATMUL_K * sizeof(elem_t)` as before (it sets the DRAM row stride for the mvin DMA engine, which still needs to reflect the actual matrix row width).

5. **All other steps remain identical** (flush, config_ex, load_scales, config_st, mxquant_config_mvout, loop_ws_spad, mx_read_smem, fence).

This reordering does not change which tiles are loaded or their scratchpad addresses — the address formula `a_base + (i*tiles_K+k)*DIM` and `b_base + (j*tiles_K+k)*DIM` are unchanged — so correctness is preserved. The benefit is that each B (and A) mvin sequence for a fixed outer index now issues `tiles_K` consecutive DMA requests into a contiguous DRAM region of `tiles_K * DIM` bytes, enabling the DMA engine to burst efficiently rather than striding by `MATMUL_K` bytes between requests.

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure port 0 (mvin) for A tiles: stride = full K row width
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0);
  // Configure port 1 (mvin2) for B tiles: stride = full K row width
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1);

  // A tiles: i-outer / k-inner for sequential DRAM bursts along K for each row i
  for (int i = 0; i < tiles_I; i++)
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);

  // B tiles: j-outer / k-inner for sequential DRAM bursts along K for each col j
  for (int j = 0; j < tiles_J; j++)
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                             b_base + (j * tiles_K + k) * DIM, DIM, DIM);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_I * tiles_J);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
