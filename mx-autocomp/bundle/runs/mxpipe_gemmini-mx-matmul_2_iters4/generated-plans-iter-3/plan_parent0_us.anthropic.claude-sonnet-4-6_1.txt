## Analysis of the Current Code

The current code has `lut_update_granularity = 1` in the `gemmini_mxquant_config_mvout` call:

```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
```

This means the output requantizer refreshes its LUT after **every single output tile**, which is maximally expensive. The `lut_update_granularity` parameter G controls how often the requantizer LUT refreshes during the quantization post-pass — smaller G means more frequent (and more costly) refreshes.

## Selected Strategy: #12 — Increase `lut_update_granularity`

### Plan

**Change `lut_update_granularity` from `1` to `tiles_K`** in the `gemmini_mxquant_config_mvout` call.

The current format configuration uses `uselut=0` (FP8, no LUT) with `out_mx_fmt=3` (BF16 output). In this configuration the output stage still has a requantizer granularity parameter, but since the A/B formats are FP8 (not FP6 LUT-indexed), the LUT refresh is unnecessary overhead. Setting `lut_update_granularity = tiles_K` amortizes any refresh overhead across all K tiles rather than paying it per-tile.

Concretely, `tiles_K = MATMUL_K / DIM`. The change is:

```c
// Before:
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

// After:
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
```

This is safe because:
1. The output format is BF16 (`out_mx_fmt=3`), and `uselut=0`, so no LUT is loaded or consulted for A/B dequantization — the refresh is pure overhead.
2. The parameter only controls the frequency of output LUT refresh; increasing it does not change which scales are applied or the final BF16 values produced, preserving bit-exact correctness.
3. `tiles_K` is the natural maximum granularity for a single `gemmini_loop_ws_spad` invocation covering all K tiles in one shot.

No other changes to the code are needed. The scratchpad layout, mvin ordering, and all other parameters remain identical.

## Rewritten Code

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure port 0 (mvin) for A tiles: stride = MATMUL_K bytes
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Configure port 1 (mvin2) for B tiles: stride = MATMUL_K bytes
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Interleave A (port 0) and B (port 1) loads to overlap DMA transfers
  for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
    for (int j = 0; j < tiles_J; j++) {
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                             b_base + (j * tiles_K + k) * DIM, DIM, DIM);
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  // Increase lut_update_granularity from 1 to tiles_K to amortize requantizer
  // refresh cost across all K tiles instead of refreshing every output tile.
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
