An elegant and highly effective way to optimize this MX-Gemmini matrix multiplication kernel is to apply **Strategy 6: minimize `gemmini_fence` calls by deferring synchronization to after full tile batch completes**.

### Optimization Plan

1. **Identify the Bottleneck**: 
   Currently, a `gemmini_fence()` is issued inside the `i0` loop immediately after `gemmini_mx_read_smem`. This is a blocking operation that stalls the host CPU until the asynchronous DMA transfer from MX shared memory (`mx_smem`) to DRAM completes. This synchronization occurs on every single iteration of the `i0` loop.

2. **Formulate the Strategy**:
   Instead of stalling the CPU on every single block iteration, we can pipeline the execution of multiple blocks. We can dispatch all matrix multiplication computations (`gemmini_loop_ws_spad`) and memory reads (`gemmini_mx_read_smem`) for all `i0` blocks in a batch asynchronously, and then issue a single `gemmini_fence()` at the end of the `i0` loop.

3. **Avoid Shared Memory Overwrite (Address Offsetting)**:
   If we defer the fence, successive iterations of `gemmini_loop_ws_spad` would overwrite the same `SPAD_DEST` address in the MX shared memory while previous DMA reads are still in progress. To avoid this hazard, we calculate a unique `cur_spad_dest` offset for each iteration of `i0`. 
   
   Since each block of size `BLK` × `BLK` has `BLK * BLK` elements, and the `SPAD_DEST` addressing unit corresponds to 16 BF16 elements, each `i0` block consumes `(BLK * BLK) / 16` rows of accumulator/SMEM space.
   
   We define:
   `int cur_spad_dest = SPAD_DEST + i0 * ((BLK * BLK) / 16);`

4. **Code Restructuring**:
   - Update `gemmini_loop_ws_spad` to target `cur_spad_dest`.
   - Update `gemmini_mx_read_smem` to read from `cur_spad_dest * 16 + r * BLK`.
   - Remove the `gemmini_fence()` calls from within the fast and slow dispatch branches.
   - Insert a single `gemmini_fence()` at the end of the outer `j0` loop (right after the nested `i0` loop finishes).

---

### Optimized Code

```c
void solution(void) {
  int tiles   = BLK / DIM;
  int tiles_K = MATMUL_K / DIM;
  int GK      = MATMUL_K / 32;

  uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
  uint32_t a_base = 0;
  int SPAD_DEST = 128;

  static uint8_t A_scales_T[BLOCKS_M][A_S_BYTES];
  static uint8_t B_scales_T[BLOCKS_N][B_S_BYTES];

  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    for (int g = 0; g < GK; g++) {
      memcpy(&A_scales_T[i0][g * BLK],
             &A_scales_row[g][i0 * BLK],
             BLK);
    }
  }

  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    for (int g = 0; g < GK; g++) {
      memcpy(&B_scales_T[j0][g * BLK],
             &B_scales_col[g][j0 * BLK],
             BLK);
    }
  }


  // Hoist the configuration outside all loops as the parameters are invariant
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
                              1, 1, 0, 0, false, 0, 0, 3, 0);

  // Pre-configure the A load stride outside the j0 loop
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));

  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    int ncols = REAL_N - j0 * BLK;
    if (ncols > BLK) ncols = BLK;
    if (ncols <= 0) continue;

    // --- OPTIMIZATION 1: Hoist weight scale loading ---
    // Load B scales once per j0, not per i0
    gemmini_mx_load_scales((uint64_t)B_scales_T[j0], B_S_BYTES, 1);

    // Mvin B tiles once per j0
    gemmini_config_ld(MATMUL_N * sizeof(elem_t));
    for (int j = 0; j < tiles; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin(
          (void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
          b_base + (k * tiles + j) * DIM, DIM, DIM);

    for (int i0 = 0; i0 < BLOCKS_M; i0++) {
      int mrows = REAL_M - i0 * BLK;
      if (mrows > BLK) mrows = BLK;
      if (mrows <= 0) continue;

      gemmini_flush(0);

      // Load A scales for current i0 block
      gemmini_mx_load_scales((uint64_t)A_scales_T[i0], A_S_BYTES, 0);

      // Mvin A tiles (using pre-configured stride)
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
            a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      // Configure requantized mvout
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors,
                                   tiles, tiles, tiles_K, 0, 0, 1);

      // Calculate unique SPAD_DEST per i0 iteration to allow deferred fencing
      int cur_spad_dest = SPAD_DEST + i0 * ((BLK * BLK) / 16);

      // Dispatch: fast interior path vs slow boundary path
      if (i0 < BLOCKS_M - 1 && j0 < BLOCKS_N - 1) {
        // Fast interior: pad_i = 0, pad_j = 0, mrows = BLK, ncols = BLK
        gemmini_loop_ws_spad(tiles, tiles, tiles_K, 0, 0, 0,
                             a_base, BANK_NUM * BANK_ROWS, 0, cur_spad_dest,
                             false, false, false, false, false,
                             NO_ACTIVATION, 0, 0, false, 0x38);

        for (int r = 0; r < BLK; r++)
          gemmini_mx_read_smem(
            &C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
            cur_spad_dest * 16 + r * BLK, BLK);

      } else {
        // Slow boundary path: handle partial tiles
        int pad_i = BLK - mrows;
        int pad_j = BLK - ncols;

        gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0,
                             a_base, BANK_NUM * BANK_ROWS, 0, cur_spad_dest,
                             false, false, false, false, false,
                             NO_ACTIVATION, 0, 0, false, 0x38);

        for (int r = 0; r < mrows; r++)
          gemmini_mx_read_smem(
            &C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
            cur_spad_dest * 16 + r * BLK, ncols);

      }
    }
    // Defer synchronization to after the entire column-block computation completes
    gemmini_fence();
  }
}
```
