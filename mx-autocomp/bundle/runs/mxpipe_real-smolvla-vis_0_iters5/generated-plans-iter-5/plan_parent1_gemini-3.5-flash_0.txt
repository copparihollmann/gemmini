An elegant and highly effective optimization plan to address the performance overhead on the host CPU.

### Inefficiency Analysis
In the original implementation, the spatial loop nests performing memory copies (`mvin` and `mx_read_smem`) recalculate complex linear DRAM offsets in every iteration. For example:
* In the $B$-loading nested loop: `(k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)`
* In the $A$-loading nested loop: `(i0 * BLK + i * DIM) * MATMUL_K + k * DIM`
* In the $C$ read-back loop: `&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD]`

These calculations involve loop-invariant scalar multiplications and divisions (such as `i0 * BLK`, `j0 * BLK`, `/ BF16_PER_WORD`, and `* MATMUL_K`) inside the innermost loops. Since the Gemmini coprocessor relies on the host CPU to generate instructions rapidly to avoid execution stalls, these redundant arithmetic computations bottleneck performance.

---

### Optimization Plan: Pre-calculate and Register-Allocate DRAM Base Offset Pointers

We will apply **Strategy 1** by performing strength reduction and pre-calculating the block DRAM base pointers and loop-invariant indices outside the innermost spatial loop nests:

1. **Precompute Outer-Loop Invariants:**
   * In the outer loop `j0`, precalculate the column offset for the output matrix:
     `const int c_col_offset = (j0 * BLK) / BF16_PER_WORD;`
   * Calculate the base pointer for $B$:
     `elem_t *b_base_ptr = ((elem_t*)B_in) + j0 * BLK;`
   * In the middle loop `i0`, calculate the row index base of $C$:
     `const int c_row_base = i0 * BLK;`
   * Calculate the base pointer for $A$:
     `elem_t *a_base_ptr = ((elem_t*)A_in) + (i0 * BLK) * MATMUL_K;`

2. **Simplify Inner-Loop Index Arithmetic:**
   * **B loading loop:** Convert to `b_base_ptr + (j * DIM) + (k * DIM) * MATMUL_N`.
   * **A loading loop:** Convert to `a_base_ptr + (i * DIM) * MATMUL_K + (k * DIM)`.
   * **C read-back loop:** Direct access using `&C_hw[c_row_base + r][c_col_offset]`, eliminating the repetitive divisions and index offset multiplications inside the loop over rows `r`.

3. **Keep Code Correctness and Hardware Model Intact:**
   * Retain all correct hardware parameterizations (`DIM = 16`, `b_base` address computation, correct use of scale memories, `gemmini_loop_ws_spad`, and `gemmini_fence()`).
