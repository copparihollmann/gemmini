### Optimization Plan

The baseline implementation suffers from severe CPU/host data staging overhead and underutilizes the on-chip memory hierarchy. Specifically, both $M$ and $N$ dimensions are symmetrically tiled with a small block size (`BLK`), which forces:
1. Slicing and staging of scale factors for both $A$ and $B$ via slow CPU `memcpy` routines on every iteration of the outer nested loops.
2. Repetitive DRAM loads of the $A$ matrix into the scratchpad, wasting DRAM bandwidth.

#### Our Strategy: Asymmetric Tiling with Scratchpad and Scale Reuse
We design an asymmetric tiling scheme that sets the $M$-block size to the full padded $M$ dimension ($M_{\text{blk}} = 128$, i.e., $\text{tiles}_I = 8$) and the $N$-block size to $32$ ($\text{tiles}_J = 2$). This configuration yields major benefits:

1. **100% Accumulator Utilization:** The accumulator row requirement is $\text{tiles}_I \times \text{tiles}_J \times \text{DIM} = 8 \times 2 \times 16 = 256$ rows, maximizing the $64\text{ KB}$ accumulator capacity.
2. **Scratchpad Space Partitioning & Reuse:** Since the total scratchpad requirement is only $(\text{tiles}_I \times \text{tiles}_K + \text{tiles}_J \times \text{tiles}_K) \times \text{DIM} = 2560$ rows, it fits comfortably within the $8192$-row limit. Because $A$'s scratchpad memory space ($0 \to 2047$) does not overlap with $B$'s ($7680 \to 8191$), **we can load the entire $A$ matrix into the scratchpad exactly once before the outer loop.** This eliminates 87.5% of $A$'s DRAM loads.
3. **A-Scale Staging Elimination:** Since we process the entire $M$ dimension as a single block, we can load `A_scales_row` directly from DRAM in its entirety once outside the loop. This completely eliminates the CPU `memcpy` overhead for $A$ scale factors.
4. **Fewer Loop Iterations:** We completely remove the outer loop over $M$, and the remaining outer loop over $N$ runs only 8 times with a highly reduced scale-factor copy overhead.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

void solution(void) {
  // Define tiling counts based on: M_blk = 128 (tiles_I = 8), N_blk = 32 (tiles_J = 2)
  const int tiles_I = 8;
  const int tiles_J = 2;
  const int tiles_K = 16; // K = 256 / 16

  uint32_t a_base = 0;
  uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM; // 8192 - 16 * 2 * 16 = 7680
  int SPAD_DEST = 128;

  // Staging buffer for B scale factors (32 bytes per scale group along K)
  uint8_t B_s[8][32];

  gemmini_flush(0);

  // Configure execution once: WS mode, BF16 output
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  // 1. Load entire A scale factors once (no slicing or host staging needed)
  gemmini_mx_load_scales((uint64_t)A_scales_row, sizeof(A_scales_row), 0);

  // 2. Pre-load B scale factors for the first block to satisfy the pipeline sequence
  for (int g = 0; g < 8; g++) {
    memcpy(&B_s[g][0], &B_scales_col[g][0], 32);
  }
  gemmini_mx_load_scales((uint64_t)B_s, sizeof(B_s), 1);

  // 3. Load entire A matrix into the scratchpad once (reused across all J blocks)
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i * DIM) * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
  }

  // 4. Outer-loop over N block dimensions (8 blocks of size 32)
  for (int j0 = 0; j0 < 8; j0++) {
    // Skip loading B scales for the first iteration as we loaded it in step 2
    if (j0 > 0) {
      for (int g = 0; g < 8; g++) {
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * 32], 32);
      }
      gemmini_mx_load_scales((uint64_t)B_s, sizeof(B_s), 1);
    }

    // Load B tiles into the top of the scratchpad
    gemmini_config_ld(MATMUL_N * sizeof(elem_t));
    for (int j = 0; j < tiles_J; j++) {
      for (int k = 0; k < tiles_K; k++) {
        gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * 32 + j * DIM)),
                              b_base + (k * tiles_J + j) * DIM, DIM, DIM);
      }
    }

    // Configure the output stride and requantizer mvout bounds
    gemmini_config_st(tiles_J * DIM / BF16_PER_WORD * sizeof(out_t)); // 8 words (32 BF16 values)
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

    // Compute the full M (128 with padding) x 32 N block weight-stationary matmul
    // pad_i = 128 - 113 = 15; pad_j = 0; pad_k = 0
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 15, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                         SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

    // Drain SMEM to C_hw for the 113 real rows
    for (int r = 0; r < 113; r++) {
      gemmini_mx_read_smem(&C_hw[r][(j0 * 32) / BF16_PER_WORD],
                           SPAD_DEST * 16 + r * 32, 32);
    }
    gemmini_fence();
  }
}
```
