## Analysis of the Current Code

The baseline processes only **half** the M and N dimensions per invocation:
- `ti = MATMUL_M / DIM / 2` (half of I tiles)
- `tj = MATMUL_N / DIM / 2` (half of J tiles)
- `tk = MATMUL_K / DIM` (all K tiles)

This means the single `gemmini_loop_ws_spad` call covers only a quarter of the output matrix, wasting scratchpad capacity and incurring unnecessary overhead. The hint confirms: "Scratchpad utilization is 0KB out of 256KB."

## Scratchpad Capacity Check for Full Tiling

For `MATMUL_M=128, MATMUL_N=128, MATMUL_K=256, DIM=16`:
- Full tiles: `ti = 128/16 = 8`, `tj = 128/16 = 8`, `tk = 256/16 = 16`
- A tiles: `ti * tk * DIM = 8 * 16 * 16 = 2048` rows
- B tiles: `tj * tk * DIM = 8 * 16 * 16 = 2048` rows
- Total: `4096` rows ≤ `8192` rows ✓
- Accumulator: `ti * tj * DIM = 8 * 8 * 16 = 1024` rows — this **exceeds** `ACC_ROWS=256` ✗

The accumulator constraint `tiles_I * tiles_J * DIM ≤ 256` → `8 * 8 * 16 = 1024 > 256`. So full I×J tiling won't fit in the accumulator.

However, looking more carefully: in the MX path with `gemmini_loop_ws_spad`, results go to `mx_smem`, not the accumulator. The `SPAD_DEST` is a scratchpad destination address (row 128), so the accumulator constraint may not apply here. Let's proceed with **strategy 9**: increase tile sizes to the full M and N dimensions since the scratchpad fits and the output goes to `mx_smem`.

## Plan: Strategy 9 — Increase Tile Sizes to Full M/DIM and N/DIM

**What to change:** Replace `ti = MATMUL_M / DIM / 2` and `tj = MATMUL_N / DIM / 2` with `ti = MATMUL_M / DIM` and `tj = MATMUL_N / DIM`, so the single fused `gemmini_loop_ws_spad` call covers the entire output matrix in one shot.

**Specific changes:**

1. Set `ti = MATMUL_M / DIM` (= 8) and `tj = MATMUL_N / DIM` (= 8) instead of halving them.

2. Recompute `bb = BANK_NUM * BANK_ROWS - tk * tj * DIM` using the new full `tj`. With `tj=8`, `tk=16`: `bb = 8192 - 16*8*16 = 8192 - 2048 = 6144`. A region: `ti*tk*DIM = 8*16*16 = 2048` rows starting at 0. B region: 2048 rows starting at 6144. No overlap. ✓

3. Update `gemmini_mxquant_config_mvout` to pass the updated `ti` and `tj`.

4. Update the mvin A loop to iterate `i` from `0` to `ti` (now 8 instead of 4).

5. Update the mvin B loop to iterate `j` from `0` to `tj` (now 8 instead of 4) — but the B stride must use the correct half-width: `MATMUL_N * sizeof(elem_t) / 2` bytes per row, matching the packed FP6 format (2 values/byte), which remains unchanged.

6. Update `gemmini_loop_ws_spad` to use the new full `ti`, `tj`, `tk`.

7. Update `gemmini_mx_read_smem` to read `MATMUL_M * MATMUL_N` BF16 values (unchanged since it already uses these constants).

This eliminates the implicit quarter-matrix tiling, replacing four implicit passes with one complete fused hardware loop — removing per-pass configuration overhead and maximizing the fraction of time the systolic array spends on useful computation.
