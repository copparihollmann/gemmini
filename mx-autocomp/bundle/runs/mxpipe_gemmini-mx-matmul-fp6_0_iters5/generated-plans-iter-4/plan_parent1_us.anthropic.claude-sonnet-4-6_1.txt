## Analysis of the Current Code

The current baseline loads only **1 LUT entry** for both B and A banks:
```c
gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);  // only 1 LUT for B
gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);  // only 1 LUT for A
```

However, the problem dimensions are:
- `MATMUL_M = 128`, `MATMUL_N = 128`, `MATMUL_K = 256`
- `tiles_I = MATMUL_M / DIM / 2 = 4` (half-M tiles)
- `tiles_J = MATMUL_N / DIM / 2 = 4` (half-N tiles)
- `QUANT_LUT_UPDATE_GRANULARITY = 1` (from reference patterns)

Looking at the reference patterns (`matmul_tiled_fp6_128x128.c`), the number of LUTs required is:
- **B LUTs:** `MATMUL_N >> QUANT_LUT_UPDATE_GRANULARITY = 128 >> 1 = 64` entries
- **A LUTs:** `MATMUL_M >> QUANT_LUT_UPDATE_GRANULARITY = 128 >> 1 = 64` entries

Loading only 1 LUT means 63 groups are using stale/uninitialized LUT data, producing incorrect results AND wasting repeated partial-load overhead. Strategy 8 directly addresses this: **load all required LUTs in a single batched `gemmini_mx_load_lut` call**.

## Plan: Apply Strategy 8

### What to Change

1. **Replace the single-LUT B load** with a batched load of all `MATMUL_N >> QUANT_LUT_UPDATE_GRANULARITY` LUT entries in one call.
2. **Replace the single-LUT A load** with a batched load of all `MATMUL_M >> QUANT_LUT_UPDATE_GRANULARITY` LUT entries in one call.
3. The `B_lut_p` and `A_lut_p` pointers must point to the start of the full LUT arrays (all entries contiguous in DRAM, as packed by the data header).

Specifically, change:
```c
gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
```
to:
```c
gemmini_mx_load_lut((uint64_t)B_lut_p, MATMUL_N >> QUANT_LUT_UPDATE_GRANULARITY, 0);
gemmini_mx_load_lut((uint64_t)A_lut_p, MATMUL_M >> QUANT_LUT_UPDATE_GRANULARITY, 1);
```

This single change:
- Ensures all N-groups and M-groups have valid LUT entries loaded before compute begins
- Amortizes the LUT-load instruction overhead (2 instructions vs. 128+128 individual loads)
- Eliminates silently incorrect results from stale LUT entries for groups 1–63
- Requires no change to scratchpad layout, tile counts, or any other part of the code

The `QUANT_LUT_UPDATE_GRANULARITY` is defined as 1 in this kernel, matching the reference patterns which use `MATMUL_N >> QUANT_LUT_UPDATE_GRANULARITY` and `MATMUL_M >> QUANT_LUT_UPDATE_GRANULARITY` as the loop bounds for LUT loading. The `gemmini_mx_load_lut` intrinsic expects `num_luts × 3 × sizeof(uint32_t)` bytes to be contiguously packed at `dram_addr`, which the pre-packed `B_lut_p`/`A_lut_p` arrays satisfy.
