An elegant and effective optimization strategy for this code is to **maximize DMA block length utilization and raise the requantization LUT refresh granularity**. 

### Optimization Plan

1. **Maximize DMA Transfer Width (Strategy 1 & 7)**:
   The baseline Gemmini DMA controller supports a `MAX_BLOCK_LEN` of 4 for scratchpad transfers, allowing up to $4 \times \text{DIM} = 64$ columns of data to be transferred in a single burst. The original implementation naively transfered only $2 \times \text{DIM} = 32$ columns at a time.
   - For **Matrix A**, we will increase the stride of the inner K-loop to `k += 4` and read $4 \times \text{DIM}$ columns in a single `gemmini_extended_mvin` call.
   - For **Matrix B**, because `tj = 4`, the entire width of B loaded per K-step fits exactly into $4 \times \text{DIM} = 64$ columns. We can completely eliminate the inner J-loop and load all columns contiguously in a single command. This halves the total number of DMA commands issued to the RoCC interface.

2. **Raise Requantization LUT Refresh Granularity (Strategy 9)**:
   The post-pass requantization unit reads values from the loaded FP6 scale/LUT. In the fp6 path, the quantization LUT is invariant across the reduction along K. By raising `lut_update_granularity` in `gemmini_mxquant_config_mvout` to `tk` (16), we force the hardware to refresh the output LUT only once per full (I, J) tile instead of redundant intermediate steps, significantly boosting the throughput of the final store phase.

### Optimized C Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// OPTIMIZED MX matmul kernel (128x128x256, fp6:e3m2).
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    // 1. Configure execution formats (FP6 inputs, BF16 output, LUT enabled)
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 1, 1, 3, 1);
    
    // 2. Load scale factors
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    
    // 3. Load quant LUTs
    gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
    gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
    
    // 4. Batch MVIN for A: Load 4 tiles (64 columns) at once (MAX_BLOCK_LEN = 4)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 4) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM), ab + (i*tk + k)*DIM, 4 * DIM, DIM);
      }
    }
    
    // 5. Batch MVIN for B: Completely vectorized load of 4 tiles (64 columns), eliminating inner loop overhead
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2)), bb + (k*tj)*DIM, 4 * DIM, DIM);
    }
    
    // 6. Configure requant writeback and set update granularity to tk (16)
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, tk);
    
    // 7. Compute weight-stationary tiled matmul over scratchpad
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    
    // 8. Drain SMEM and synchronize
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
