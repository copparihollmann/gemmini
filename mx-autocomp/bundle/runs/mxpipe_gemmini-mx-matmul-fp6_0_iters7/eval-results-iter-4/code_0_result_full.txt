Plan: An elegant and highly effective way to optimize the performance of the $128 \times 128 \times 256$ matrix multiplication kernel is to choose **Strategy 1: overlap data movement and compute** using a double-buffered 1D tiling pipeline along the $N$ dimension.

### Optimization Plan

1. **Optimal 1D Partitioning Along $N$**:
   Since the accumulator size is limited to $256$ rows, we can partition the global $128 \times 128 \times 256$ matmul into 4 blocks of size $128 \times 32 \times 256$.
   - **Tiling Dimensions per Block**: `ti = 8` (128 rows), `tj = 2` (32 columns), `tk = 16` (256 columns).
   - **Accumulator Space**: Each block consumes exactly $16 \times 16 = 256$ rows, maximizing accumulator utilization without overflowing.

2. **DRAM Bandwidth Optimization (Static A Matrix)**:
   Since we partition strictly along the $N$ dimension, the $A$ matrix ($128 \times 256$) is completely invariant across the 4 blocks. We can load the entire $A$ matrix into the scratchpad at base address `0` exactly **once** at the beginning of the function, eliminating $75\%$ of the $A$ memory traffic.

3. **Double-Buffering $B$**:
   - **$B$ Tile size per block**: $512$ rows ($2 \times 16 \times 16$).
   - We allocate two non-overlapping buffers at the top of the scratchpad:
     - **Buffer 0**: Ends at row $8192$ (occupies `[7680, 8192)`).
     - **Buffer 1**: Ends at row $7680$ (occupies `[7168, 7680)`).
   - Neither buffer overlaps with the static $A$ matrix stored in `[0, 2048)`.

4. **Pipelining Sequence**:
   - Pre-load $A$ into the scratchpad, and load $B$ for block 0.
   - For each block `j_block`:
     - Issue the compute instruction (`gemmini_loop_ws_spad`) for the current block.
     - While compute runs in the background, issue the `gemmini_extended_mvin` instructions to load the next $B$ block into the alternate buffer.
     - Read the compute results to a contiguous local DRAM buffer (`temp_C`) using `gemmini_mx_read_smem`.
     - Call `gemmini_fence()` to synchronize.
     - Use the CPU to copy `temp_C` to the strided final output `C_hw` slice.
