An elegant and highly effective way to optimize this MX-Gemmini kernel is to apply **Strategy 5: raise `lut_update_granularity`**.

### Optimization Plan

1. **Identify the Inefficiency:**
   In the original code, the output requantization LUT update granularity parameter in `gemmini_mxquant_config_mvout` was set to `9`. However, the K-dimension reduction length `tk` is `16` (calculated as `MATMUL_K / DIM = 256 / 16 = 16`). Because the dequantization/requantization LUTs are invariant across the entire K reduction dimension for any given output $(i, j)$ tile, refreshing the LUTs every 9 steps introduces redundant hardware overhead and stall cycles.

2. **Apply Strategy 5:**
   We will change the `lut_update_granularity` parameter in `gemmini_mxquant_config_mvout` from `9` to `tk` (which is `16`). This tells the hardware requantizer to refresh the LUT exactly once per output tile (every 16 K-steps), avoiding unnecessary mid-reduction refreshes and improving overall execution latency.

### Optimized Code

// Optimized MX matmul kernel (128x128x256, fp6:e3m2) using batched MVINs.
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 1, 1, 3, 1);
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    
    // Strategy 5: Raise lut_update_granularity to tk (16) so the output LUT 
    // is refreshed only once per output tile (every 16 steps) instead of every 9 steps.
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, tk);
    
    gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
    gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
    
    // Batch MVIN for matrix A (2 tiles along the K-dimension per instruction)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 2) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i * DIM * MATMUL_K + k * DIM), 
                              ab + (i * tk + k) * DIM, 
                              2 * DIM, 
                              DIM);
      }
    }
    
    // Batch MVIN for matrix B (2 tiles along the J-dimension per instruction)
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      for (int j = 0; j < tj; j += 2) {
        gemmini_extended_mvin((void*)(((elem_t*)B_in) + k * DIM * (MATMUL_N / 2) + j * DIM), 
                              bb + (k * tj + j) * DIM, 
                              2 * DIM, 
                              DIM);
      }
    }
    
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
