### Optimization Strategy: Inter-Iteration Operand Reuse with Single-Pass Weight Loading

In the baseline implementation, the 128×128×256 matrix multiplication was tiled into a single 64×64×256 execution pass, utilizing only a portion of the overall output matrix and requiring redundant loads. Since the accumulator is limited to 256 rows ($256 \times 128 \text{ bytes} = 32\text{ KB}$), we cannot compute the entire 128×128 output at once. Instead, we can partition the computation along the $M$ dimension into two blocks ($bi \in \{0, 1\}$) of size 64×128.

By structuring the execution as a loop over these two row blocks, we can apply **Inter-Iteration Operand Reuse**:
1. **Single-Pass Weight Loading**: The weight matrix $B$ is completely independent of the $M$ (activation row) partition. By placing the nested $B$ load loops completely outside the outer $M$ loop, we load the $B$ tiles into the top of the scratchpad **exactly once** instead of twice. This cuts the overall DRAM-to-Scratchpad bandwidth requirement for weights by $50\%$.
2. **Configuration Hoisting**: All scale factor loads (`gemmini_mx_load_scales`), lookup tables (`gemmini_mx_load_lut`), and requantization configurations (`gemmini_mxquant_config_mvout`) are hoisted completely out of the loops since their parameters are invariant across the row blocks.
3. **Targeted SMEM Draining**: During each iteration of the outer loop, we issue a targeted `gemmini_mx_read_smem` directly to the corresponding row offset of `C_hw` in DRAM (`&C_hw[bi * ti * DIM][0]`).

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// AUTO-GENERATED optimized MX matmul kernel (128x128x256, fp6:e3m2).
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2; // 4 tiles (64 rows)
    int tj = MATMUL_N / DIM / 2; // 4 tiles (64 columns)
    int tk = MATMUL_K / DIM;     // 16 tiles (256 columns)
    
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    // 1. Hoist persistent configurations
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 1, 1, 3, 1);
    
    // 2. Load scale factors once
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    
    // 3. Load LUTs once
    gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
    gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
    
    // 4. Configure requantization bounds once
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 9);
    
    // 5. Single-Pass Weight Loading: Load B tiles into scratchpad once
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      for (int j = 0; j < tj; j += 2) {
        gemmini_extended_mvin((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2) + j*DIM), bb + (k*tj + j)*DIM, 2 * DIM, DIM);
      }
    }
    
    // 6. Outer loop over activation row-blocks
    for (int bi = 0; bi < 2; bi++) {
      // Load A tiles dynamically for the current row-block
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < ti; i++) {
        int global_i = bi * ti + i;
        for (int k = 0; k < tk; k += 2) {
          gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + global_i*DIM*MATMUL_K + k*DIM), ab + (i*tk + k)*DIM, 2 * DIM, DIM);
        }
      }
      
      // Compute tiled WS matmul in hardware
      gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      
      // Drain computed results directly to the corresponding DRAM quadrant slice
      gemmini_mx_read_smem(&C_hw[bi * ti * DIM][0], SDST * 16, ti * DIM * MATMUL_N);
      gemmini_fence();
    }
  }
}
```
