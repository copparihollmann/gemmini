## Analysis of the Original Code

Looking at the original code, I can identify a key inefficiency in the **MVIN B** section:

```c
// MVIN B uses wrong stride and wrong address layout
gemmini_extended3_config_ld(MATMUL_M * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

for (int j = 0; j < tiles_J; j++) {
    // ...
    elem_t *dram_ptr = ((elem_t*)B_in) + j * DIM * MATMUL_M + k * DIM;
    uint32_t sp_addr = b_base + (j * tiles_K + k) * DIM;  // WRONG: j-major instead of k-major
```

And in **MVIN A**:
```c
gemmini_extended3_config_ld(MATMUL_M * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
// Wrong stride: should be MATMUL_K (packed row width), not MATMUL_M
elem_t *dram_ptr = ((elem_t*)A_in) + i * DIM * MATMUL_M + k * DIM;
```

The critical issue for **strategy 2**: B tiles are *not* placed at the correct `b_base = BANK_NUM*BANK_ROWS - tiles_K*tiles_J*DIM` with the correct k-major indexing (`b_base + (j*tiles_K + k)*DIM`). The reference pattern (`matmul_ws_mx_generic.c`) clearly shows B should be indexed as `(k * tiles_J + j) * K_TILE` — but for `loop_ws_spad`, Rule 12 specifies `b_base + (j*tiles_K + k)*DIM`. Additionally, `b_base` must be passed as `BANK_NUM*BANK_ROWS` (the end address) to `gemmini_loop_ws_spad`.

## Plan: Strategy 2 — Assign B tiles to fixed high-address scratchpad region

**What to change:**

1. **Fix `b_base` calculation** to `BANK_NUM*BANK_ROWS - tiles_K*tiles_J*DIM` (= 8192 - tiles_K*tiles_J*16), placing B at the top of the scratchpad growing downward, preventing overlap with A tiles at `a_base=0`.

2. **Fix MVIN B stride** to `(MATMUL_N / VALUES_PER_BYTE) * sizeof(elem_t)` — the actual packed row width of B in DRAM (matching the reference pattern). The original uses `MATMUL_M * sizeof(elem_t)` which is wrong.

3. **Fix MVIN B DRAM pointer** to index B correctly: `(uint8_t*)B_in + k * K_TILE * (MATMUL_N / VALUES_PER_BYTE) + j * DIM`, matching the reference pattern's k-outer, j-inner traversal.

4. **Fix MVIN B scratchpad address** to `b_base + (j * tiles_K + k) * DIM` per Rule 12.

5. **Fix MVIN A stride** to `MATMUL_K * sizeof(elem_t)` (packed row width of A), and **fix DRAM pointer** to `(uint8_t*)A_in_hw + i * DIM * MATMUL_K + k * DIM`, matching the reference.

6. **Pass `BANK_NUM*BANK_ROWS` (= 8192) as the B-end address** to `gemmini_loop_ws_spad` (the second spad address argument), which is the end of the B region, so the hardware addresses B tiles downward from the top.

This ensures all A and B tiles are correctly placed in the scratchpad simultaneously without overlap, enabling weight-stationary reuse of B tiles across I iterations in the fused hardware loop.
