An elegant and highly effective optimization plan to significantly reduce the execution latency of the outer-tiled MX matrix multiplication kernel.

### Inefficiency Analysis
1. **Redundant DRAM Loads for Matrix A:**
   In the baseline, the activation matrix $A$ (and its scale factors `A_s`) is loaded from DRAM inside the innermost `j0` loop. Since $A$ is independent of the column block index `j0`, it is needlessly re-read and streamed into the scratchpad $64$ times. This results in $192 \times 64 = 12,288$ redundant `mvin` instructions for $A$.
2. **Fine-grained DMA Requests for Matrix B:**
   Matrix $B$ is currently loaded tile-by-tile using `gemmini_extended_mvin` with size `DIM` by `DIM`. Issuing $192$ individual small DMA commands per outer block step incurs severe instruction issue and memory latency overhead on the host CPU.

---

### Optimization Plan
We will apply a targeted spatial cache-blocking strategy combined with DRAM-load vectorization to optimize memory bandwidth and instruction throughput:

1. **Hoist Matrix A Loading:** 
   Move the loading of $A$'s scale factors (`A_s` staging and `gemmini_mx_load_scales`) and the $A$ tile data (`gemmini_extended_mvin` loop) out of the inner `j0` loop into the outer `i0` loop. Because $A$ only depends on `i0`, it will be loaded exactly once per row-block, reducing $A$-related host overhead and DRAM latency by $64\times$.
2. **DRAM Load Vectorization (mvin batching) for Matrix B:**
   Since `tiles = 1` (when `BLK = 16`), consecutive tiles of $B$ along the reduction dimension $K$ map to contiguous rows in the Gemmini scratchpad (`b_base + k * DIM`). We can leverage the hardware's `MAX_BLOCK_LEN = 4` limit to pack $4$ consecutive tiles along $K$ into a single `mvin` instruction of size $4 \times \text{DIM} = 64$ rows. This cuts B-side `mvin` overhead by $4\times$ (from $192$ commands to only $48$).

---

// AUTO-GENERATED outer-tiled MX matmul optimized (1x1024x3072).
void solution(void) {
  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    // Partial last M/N block: compute only the real rows, pad the rest.
    int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
    int pad_i = BLK - mrows;
    int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
    uint32_t a_base = 0;
    uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
    int SPAD_DEST = 128;

    // PROF accel
    gemmini_flush(0);

    // Stage and load A scale factors once per row block (independent of j0)
    for (int g = 0; g < MATMUL_K / 32; g++) {
      memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
    }
    gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);

    // Load A data once per row block (independent of j0)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t)); // A rows: stride K
    for (int i = 0; i < tiles; i++) {
      for (int k = 0; k < tiles_K; k++) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      }
    }

    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;
      int pad_j = BLK - ncols;

      // Stage and load B scale factors for the current column block
      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);

      // Load B data using vectorized MVIN (batch 4 tiles together if tiles == 1)
      gemmini_config_ld(MATMUL_N * sizeof(elem_t)); // B rows: stride N
      for (int j = 0; j < tiles; j++) {
        if (tiles == 1) {
          // Batch 4 tiles (4 * DIM rows) per single instruction
          for (int k = 0; k < tiles_K; k += 4) {
            gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                  b_base + (k * tiles + j) * DIM, DIM, 4 * DIM);
          }
        } else {
          // Fallback safe path
          for (int k = 0; k < tiles_K; k++) {
            gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                  b_base + (k * tiles + j) * DIM, DIM, DIM);
          }
        }
      }

      // Configure execution format and run fused WS execution
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);

      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      // Read out-of-order execution results from smem directly to DRAM
      for (int r = 0; r < mrows; r++) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
  }
}
