The current code has an **outer loop over (i0, j0)**, meaning for each `(i0, j0)` pair:
1. It loads A scales for `i0`'s rows
2. It loads B scales for `j0`'s columns  
3. It mvins **all A tiles** for the current `i0` block
4. It mvins **all B tiles** for the current `j0` block
5. It computes and reads out results

**The critical inefficiency**: For a fixed `j0`, B tiles are re-loaded from DRAM on **every** `i0` iteration. If there are `BLOCKS_M` row blocks, each B tile block is loaded `BLOCKS_M` times total. Since the hardware is weight-stationary and B tiles don't change across row iterations, this is `(BLOCKS_M - 1) × B_mvin_cost` of wasted DMA bandwidth.

## Strategy: Reorder Outer Loop to (j0, i0) — Weight-Stationary B Reuse Across M

This directly applies **strategy 5**: reorder the outer loops to `(j0, i0)` so that B tiles for a fixed `j0` column block are mvin'd **once** and reused across all `i0` row iterations.

### How It Works

**Current order `(i0, j0)`**:
- For `i0=0, j0=0`: mvin B[j0=0], compute
- For `i0=0, j0=1`: mvin B[j0=1], compute
- For `i0=1, j0=0`: mvin B[j0=0] **again**, compute  ← redundant
- For `i0=1, j0=1`: mvin B[j0=1] **again**, compute  ← redundant

**New order `(j0, i0)`**:
- For `j0=0, i0=0`: mvin B[j0=0] **once**, compute
- For `j0=0, i0=1`: **skip B mvin**, reuse B in scratchpad, compute
- For `j0=1, i0=0`: mvin B[j0=1] **once**, compute
- For `j0=1, i0=1`: **skip B mvin**, reuse B in scratchpad, compute

B tiles occupy `tiles_K * tiles_J * DIM` rows at the top of the scratchpad. Since A tiles change per `i0` but B tiles stay fixed for the entire inner `i0` loop, we only reload A scales + A tiles on each `i0` iteration while B scales + B tiles are loaded once per `j0`.

### Constraint Check

The scratchpad must hold all A and B tiles simultaneously:
- A tiles: `tiles_I * tiles_K * DIM` rows = `(BLK/16) * (MATMUL_K/16) * 16` rows
- B tiles: `tiles_J * tiles_K * DIM` rows = `(BLK/16) * (MATMUL_K/16) * 16` rows
- Total must be ≤ 8192 rows

This constraint is identical to the original — the reordering doesn't change scratchpad requirements since we still only hold one (i0, j0) pair's tiles at a time. The B layout at `b_base` is unchanged.
