## Selected Strategy: Use `mvin2`/`mvin3` ports to parallelize A and B tile loads into scratchpad simultaneously (Strategy 10)

## Plan

The hardware has three independent mvin ports:
- `gemmini_extended_mvin` (port 0 / `k_MVIN`) — used for A tiles
- `gemmini_extended_mvin2` (port 1 / `k_MVIN2`) — can be used for B tiles
- `gemmini_extended_mvin3` (port 2 / `k_MVIN3`) — for accumulator/bias

Currently both A and B tiles are loaded via port 0 sequentially. By using `mvin2` for B tiles while using `mvin` for A tiles, the two loads can be issued in an interleaved fashion in a single combined loop, allowing the DMA engine to process both streams concurrently.

**Concrete changes:**

1. Keep `gemmini_config_ld` (which configures port 0 / mvin) for A tiles with stride `MATMUL_K * sizeof(elem_t)`.

2. Add a second `gemmini_extended3_config_ld` (or `gemmini_extended3_config_ld` with `id=1`) call to configure port 1 (mvin2) with the same stride for B tiles: `MATMUL_K * sizeof(elem_t)`. Both A and B have the same row stride in this fp8 case (`MATMUL_K` bytes), so a single config suffices for both, but port 1 needs its own config via `gemmini_extended3_config_ld(..., id=1)`.

3. Replace the two separate loops (one over A, one over B) with a **single interleaved loop** over `(i, k)` and `(j, k)` pairs. For each `(k)` step, issue A tile loads via `gemmini_extended_mvin` and B tile loads via `gemmini_extended_mvin2` in an interleaved pattern, so both DMA ports are kept busy simultaneously.

4. The interleaved loop structure: iterate over `k`, and for each `k`, issue all `tiles_I` A-tile mvins (port 0) and all `tiles_J` B-tile mvins (port 1) for that `k` slice. This interleaves A and B loads at the granularity of a k-slice, maximizing overlap.

5. No changes to scratchpad layout, addresses, `gemmini_loop_ws_spad`, `gemmini_mx_read_smem`, or `gemmini_fence` — the computation and output stages remain identical. The semantic result is unchanged.

**Why this helps:** The original code saturates port 0 with all A loads then all B loads sequentially. With port 0 for A and port 1 for B, the hardware DMA units can process both streams in parallel, effectively halving the mvin latency contribution to total execution time.
