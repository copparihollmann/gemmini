## Analysis

Looking at the original code, I can identify the inefficiency targeted by **strategy 10**:

```c
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0);
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1);
```

The second `gemmini_extended3_config_ld` call (for port id=1) configures the same stride (`MATMUL_K * sizeof(elem_t)`), the same scale (`SCALE_IDENTITY`), and the same `shrunk` flag (`false`) as port 0. The port selection for actual data movement is already encoded in the instruction opcode itself — `gemmini_extended_mvin` uses `k_MVIN` while `gemmini_extended_mvin2` uses `k_MVIN2`. The CONFIG_LD for port 1 is therefore redundant when stride/scale parameters are identical to port 0.

## Plan

**Strategy 10: Eliminate the redundant second `gemmini_extended3_config_ld` call.**

The fix is straightforward:
- Remove the second `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1)` call entirely.
- Keep only the single `gemmini_extended3_config_ld(..., 0)` call for port 0.
- Since `gemmini_extended_mvin2` (which loads B tiles) selects port 1 via its opcode `k_MVIN2`, and both ports share the same stride/scale configuration here, the B tile loads will correctly use the same stride configured for port 0. The CONFIG_LD state for stride/scale is shared or defaults correctly; the redundant reconfiguration of port 1 with identical parameters adds instruction overhead without benefit.

This removes one unnecessary RoCC instruction from the critical setup path.

void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0);

  for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++)
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    for (int j = 0; j < tiles_J; j++)
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                             b_base + (j * tiles_K + k) * DIM, DIM, DIM);
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
