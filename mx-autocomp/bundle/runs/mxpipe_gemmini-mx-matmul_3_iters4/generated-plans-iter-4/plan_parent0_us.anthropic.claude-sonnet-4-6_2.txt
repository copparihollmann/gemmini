## Strategy: Interleave A and B mvin Instructions to Maximize DMA Port Utilization

### Analysis of the Current Code

The current mvin loop is:
```c
for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++)
        gemmini_extended_mvin(...)   // A tiles via port 0
    for (int j = 0; j < tiles_J; j++)
        gemmini_extended_mvin2(...)  // B tiles via port 1
}
```

This issues all A-tile mvins for a given K slice, then all B-tile mvins. Even though `mvin` and `mvin2` are independent DMA ports, the software is serializing them: the command queue sees a burst of A loads followed by a burst of B loads. In hardware, commands are dispatched in order, and while the hardware can overlap independent operations, the command buffer fills with one type before seeing the other. More critically, this creates a load-imbalance pattern where the A-port is saturated while B-port is idle, then vice versa.

### The Strategy: True Interleaving of mvin/mvin2 at the Finest Granularity

Instead of nested loops that batch all A then all B for each K, **interleave individual A and B mvin instructions** so that for each (i, j, k) combination, an A-tile load and a B-tile load are issued back-to-back. This allows the hardware to keep both DMA ports busy simultaneously rather than alternating between long burst sequences.

Specifically, restructure the mvin loop so that for each K slice, each A tile load is immediately followed by a corresponding B tile load:

```c
for (int k = 0; k < tiles_K; k++) {
    // Issue one A mvin and one B mvin alternately, not all-A then all-B
    int max_ij = (tiles_I > tiles_J) ? tiles_I : tiles_J;
    for (int ij = 0; ij < max_ij; ij++) {
        if (ij < tiles_I)
            gemmini_extended_mvin(A_ptr(ij,k),  a_addr(ij,k),  DIM, DIM);
        if (ij < tiles_J)
            gemmini_extended_mvin2(B_ptr(ij,k), b_addr(ij,k),  DIM, DIM);
    }
}
```

Since `tiles_I == tiles_J` for square problems (both = MATMUL_M/DIM = MATMUL_N/DIM), the loop simplifies to perfectly paired A/B issues. This ensures the command stream always has alternating port-0 and port-1 requests, giving the hardware scheduler maximum opportunity to overlap the two independent DMA channels.

### Why This Improves Performance

1. **Both DMA ports stay busy**: The hardware has separate datapaths for `mvin` (port 0, A) and `mvin2` (port 1, B). When the command queue alternates between them, both DRAM request channels can be in flight simultaneously, roughly doubling effective DRAM bandwidth utilization for the load phase.

2. **Reduced command queue stalls**: A long burst of same-port commands may cause the port to backpressure while the other sits idle. Interleaving distributes pressure evenly.

3. **Earlier readiness for compute**: Since `gemmini_loop_ws_spad` cannot start until all tiles are loaded, finishing both A and B loads faster (via overlap) reduces the wall-clock time before the compute phase begins.

### Implementation

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0);
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // Precompute base pointers and spad addresses to avoid multiply in inner loop
  for (int k = 0; k < tiles_K; k++) {
    for (int ij = 0; ij < tiles_I || ij < tiles_J; ij++) {
      if (ij < tiles_I)
        gemmini_extended_mvin(
          (void*)(((elem_t*)A_in) + ij * DIM * MATMUL_K + k * DIM),
          a_base + (ij * tiles_K + k) * DIM, DIM, DIM);
      if (ij < tiles_J)
        gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + ij * DIM * MATMUL_K + k * DIM),
          b_base + (ij * tiles_K + k) * DIM, DIM, DIM);
    }
  }

  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```

This change is minimal, semantically equivalent (all the same tiles are loaded to the same scratchpad addresses), and requires no changes to the compute or output stages. It directly targets the underutilization of the two independent mvin DMA ports.
