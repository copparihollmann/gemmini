## Analysis of the Original Code

The original code loads A tiles using `gemmini_extended_mvin` (port 1) and B tiles also using `gemmini_extended_mvin` (port 1) in **separate sequential loops**. This means:

1. All A tiles are loaded first (fully serialized)
2. All B tiles are loaded second (fully serialized)
3. Both use the same mvin port, so loads cannot overlap

The hardware provides **three independent mvin ports** (`mvin`, `mvin2`, `mvin3`), which can issue simultaneously and overlap with each other.

## Selected Strategy: **Strategy 8 — Use `mvin2`/`mvin3` ports to parallelize A and B tile loads into scratchpad simultaneously**

## Plan

### What to Change

Change the B tile loading from `gemmini_extended_mvin` to `gemmini_extended_mvin2`, and configure its stride separately using `gemmini_extended3_config_ld` with `id=1`. Then **interleave** the A and B tile load loops so that for each `(k, j/i)` combination, an A-tile mvin and a B-tile mvin2 are issued back-to-back, allowing the DMA engine to issue both in parallel.

### Specific Changes

1. **Add a second `gemmini_config_ld` call for mvin2 (id=1):** Use `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1)` to configure the B-side DMA port with the correct stride, independently of mvin port 0.

2. **Restructure the tile load loops:** Instead of two separate loops (all-A then all-B), merge them into a single loop over `k` (and nested `i`/`j`) that issues A loads via `gemmini_extended_mvin` and B loads via `gemmini_extended_mvin2` in an interleaved fashion:

```c
// Configure both ports
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0); // mvin port for A
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1); // mvin2 port for B

for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++)
        gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    for (int j = 0; j < tiles_J; j++)
        gemmini_extended_mvin2(
            (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
            b_base + (j * tiles_K + k) * DIM, DIM, DIM);
}
```

### Why This Reduces Latency

- The original code serializes all A loads then all B loads through a single DMA port. With two ports active simultaneously, the hardware can pipeline A and B DMA transfers in parallel, roughly halving the total load time.
- By organizing the loop over `k` first, each `k`-slice of A and the corresponding `k`-slice of B are issued together, keeping the instruction queue balanced between the two ports and maximizing overlap.
- The rest of the sequence (config_ex, load_scales, mxquant_config_mvout, loop_ws_spad, mx_read_smem, fence) remains unchanged, preserving correctness and the required programming model order.
