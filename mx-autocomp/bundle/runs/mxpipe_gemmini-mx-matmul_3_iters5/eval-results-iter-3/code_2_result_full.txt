## Selected Strategy: #11 — Exploit scratchpad double-buffer spad IDs

### Why This Helps

In the current code, `gemmini_loop_ws_spad` is called with `a_spad_id=0` and `b_spad_id=0`, meaning the hardware treats every A and B tile as potentially different on each iteration. With `a_spad_id=1` (or `2`), the hardware knows A tiles are **reused** across all J iterations (since A is the same for all output columns in weight-stationary). This allows the hardware to skip redundant A-tile preloads inside the fused loop for J > 0 iterations, directly reducing the number of internal preload operations.

In weight-stationary mode, A tiles indexed by `(i, k)` are indeed the **same** for all `j` iterations — the A operand does not change as we sweep across output columns. Setting `a_spad_id=1` signals this reuse to the hardware fused loop controller.
