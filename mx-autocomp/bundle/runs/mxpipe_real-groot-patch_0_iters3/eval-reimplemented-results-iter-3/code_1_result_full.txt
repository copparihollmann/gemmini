Currently, the loop structure is:
```

  for j0 in BLOCKS_N:
    mvin A tiles for (i0, all k)
    mvin B tiles for (all k, j0)
    compute
    readout
```

For each `(i0, j0)` pair, B tiles are loaded fresh. But if we restructure to loop `j0` in the outer loop and `i0` in the inner loop, the B tiles for a given `j0` can be loaded **once** and reused across all `i0` iterations. This is classic weight-stationary reuse.

**Concrete changes:**

- Move `gemmini_flush(0)` and `gemmini_extended3_config_ex(...)` before the outer `j0` loop.

- Before the `i0` loop (but inside `j0`): compute `b_base`, issue `gemmini_config_ld(MATMUL_N * sizeof(elem_t))`, and mvin all B tiles for this `j0`.
- Inside the `i0` loop: copy A/B scales, call `gemmini_mx_load_scales` for both A and B (scales differ per block), issue `gemmini_config_ld(MATMUL_K * sizeof(elem_t))`, mvin A tiles, then configure mvout, run `gemmini_loop_ws_spad`, readout, and fence.
