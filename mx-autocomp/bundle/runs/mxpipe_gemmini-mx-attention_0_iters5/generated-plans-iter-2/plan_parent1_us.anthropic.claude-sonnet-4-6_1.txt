## Analysis

Looking at the original code, I need to identify the best single strategy to apply.

**Current code structure:**
1. Block 1 (Q@K^T): calls `gemmini_extended3_config_ex(... 0, 0, 3, 0)` with act=0, wgt=0, out=3, uselut=0
2. Softmax CPU computation
3. Block 2 (P@V): calls `gemmini_extended3_config_ex(... 0, 0, 3, 0)` with **identical** format fields

**Strategy 12** is directly applicable: the `gemmini_extended3_config_ex` call in both blocks uses exactly the same arguments (WEIGHT_STATIONARY, act=0, wgt=0, out=3, uselut=0, no transpose, etc.). The hardware state persists until changed, so issuing it twice is redundant — the second call is a no-op that still consumes instruction issue cycles and serializes the pipeline.

Also, `gemmini_flush(0)` appears in both blocks. The flush in the second block is redundant since the first block ends with `gemmini_fence()` which already ensures all prior operations complete. Removing the second `gemmini_flush(0)` saves unnecessary stall cycles.

## Plan

**Strategy: Hoist the identical `gemmini_extended3_config_ex` (and `gemmini_flush`) outside both matmul blocks (Strategy 12)**

**Specific changes:**

1. **Remove `gemmini_flush(0)` from Block 1** — move it before both blocks to a single call at the top of `solution()`.

2. **Remove `gemmini_flush(0)` from Block 3 (P@V)** — the `gemmini_fence()` at the end of Block 1 already ensures the pipeline is drained before the CPU softmax runs, so a second flush is unnecessary.

3. **Move `gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0)`** out of both Block 1 and Block 3, placing it once at the top of `solution()` (after the single `gemmini_flush(0)`). Since both blocks use identical format/dataflow settings (act_mx_fmt=0, wgt_mx_fmt=0, out_mx_fmt=3, uselut=0, WEIGHT_STATIONARY, no transpose, strides=1), the hardware state is already correctly configured for Block 3 after Block 1, and re-issuing it is pure overhead.

4. **`gemmini_extended_config_st`** calls differ between blocks (`S_OUT_COLS` vs `D_OUT_COLS`), so those remain inside their respective blocks — only the `config_ex` is hoisted.

This saves one `gemmini_flush` and one `gemmini_extended3_config_ex` instruction (both of which stall the pipeline), reducing total instruction count and pipeline stall cycles between the two matmul phases. The ordering rule is still satisfied: the single `config_ex` precedes the first `gemmini_mx_load_scales`, and because hardware config state persists, it remains valid for Block 3 as well.

```c
void solution(void) {
  // Single flush and config_ex hoisted outside both matmul blocks —
  // format fields (act=0, wgt=0, out=3, uselut=0) are identical for both.
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
      1, 1, 0, 0, false, 0, 0, 3, 0);

  // ---- 1) S1 = Q @ K^T on Gemmini (bf16 out) ----
  {
    int tiles_I = ATT_S / DIM, tiles_J = ATT_S / DIM, tiles_K = ATT_D / DIM;
    uint32_t a_base = 0;
    uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
    // config_ex already issued above
    gemmini_mx_load_scales((uint64_t)&Q_scales_row, sizeof(Q_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&KT_scales_col, sizeof(KT_scales_col), 1);
    gemmini_config_ld(ATT_D * sizeof(elem_t));
    for (int i = 0; i < tiles_I; i++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin((void*)(((elem_t*)Q_in) + i * DIM * ATT_D + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    gemmini_config_ld(ATT_S * sizeof(elem_t));
    for (int j = 0; j < tiles_J; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin((void*)(((elem_t*)KT_in) + (k * DIM) * ATT_S + j * DIM),
                              b_base + (k * tiles_J + j) * DIM, DIM, DIM);
    gemmini_config_st(S_OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                         SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&S1_hw[0][0], SPAD_DEST * 16, ATT_S * ATT_S);
    gemmini_fence();
  }

  // ---- 2) P = softmax(S1) rows on CPU ----
  for (int i = 0; i < ATT_S; i++) {
    float row[ATT_S];
    float maxv = -1e30f;
    for (int j = 0; j < ATT_S; j++) {
      uint16_t b = (uint16_t)((S1_hw[i][j / 4] >> ((j % 4) * 16)) & 0xFFFF);
      row[j] = bf16_to_f(b);
      if (row[j] > maxv) maxv = row[j];
    }
    float sum = 0.0f;
    for (int j = 0; j < ATT_S; j++) { row[j] = exp_f(row[j] - maxv); sum += row[j]; }
    float inv_sum = 1.0f / sum;
    for (int j = 0; j < ATT_S; j++) row[j] *= inv_sum;
    for (int g = 0; g < GROUPS_S; g++) {
      float gmax = 0.0f;
      for (int j = g * 32; j < (g + 1) * 32; j++)
        if (f_abs(row[j]) > gmax) gmax = f_abs(row[j]);
      int e = 0;
      if (gmax > 0.0f) e = f_exp(gmax / 16.0f) + 1;
      float inv_scale = pow2i(-e);
      P_scales[g][i] = (uint8_t)(e + 127);
      for (int j = g * 32; j < (g + 1) * 32; j++)
        P_q[i][j] = fp8_e4m3_rtz(row[j] * inv_scale);
    }
  }

  // ---- 3) O = P @ V on Gemmini (bf16 out) ----
  {
    int tiles_I = ATT_S / DIM, tiles_J = ATT_D / DIM, tiles_K = ATT_S / DIM;
    uint32_t a_base = 0;
    uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
    // config_ex already issued above — no re-issue needed
    gemmini_mx_load_scales((uint64_t)&P_scales, sizeof(P_scales), 0);
    gemmini_mx_load_scales((uint64_t)&V_scales_col, sizeof(V_scales_col), 1);
    gemmini_config_ld(ATT_S * sizeof(elem_t));
    for (int i = 0; i < tiles_I; i++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin((void*)(((elem_t*)P_q) + i * DIM * ATT_S + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    gemmini_config_ld(ATT_D * sizeof(elem_t));
    for (int j = 0; j < tiles_J; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin((void*)(((elem_t*)V_in) + (k * DIM) * ATT_D + j * DIM),
                              b_base + (k * tiles_J + j) * DIM, DIM, DIM);
    gemmini_config_st(D_OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                         SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&O_hw[0][0], SPAD_DEST * 16, ATT_S * ATT_D);
    gemmini_fence();
  }
}
```
