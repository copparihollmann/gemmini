Looking at the failing code, I need to identify the issues:

1. **Scale loading convention is wrong**: `gemmini_mx_load_scales` sel=0 is for A (activations), sel=1 is for B (weights). The code has this reversed.

2. **Scale layout mismatch**: The `gemmini_mxquant_config_mvout` expects scales at `scale_dram + m*N_blocks + bi` (row-major, block-indexed). The transposed scale arrays need to match the hardware's expected indexing pattern correctly.

3. **B matrix mvin stride**: B is stored row-major with stride `MATMUL_N`, but the mvin for B tiles needs the correct stride for how B is laid out in DRAM.

4. **B spad layout**: The B spad address calculation uses `(k * tiles + j)` but should be `(j * tiles_K + k)` to match the documented layout `b_base + (j*tiles_K + k)*DIM`.

5. **mx_read_smem offset**: The smem read offset and count need to correctly address BF16 outputs.

6. **Scale factors address**: The `scale_factors` passed to `gemmini_mxquant_config_mvout` needs to point to correctly laid out per-output-tile scales.
