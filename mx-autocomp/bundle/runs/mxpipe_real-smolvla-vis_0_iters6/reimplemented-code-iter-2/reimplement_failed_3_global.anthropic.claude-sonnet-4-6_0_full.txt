Looking at the failing code, I need to identify the bugs:

1. **B matrix mvin uses wrong port**: B should use `gemmini_extended_mvin2` (mvin2 port), not `gemmini_extended_mvin` (mvin port). Using the same port for both A and B causes incorrect scratchpad layout.

2. **B tile layout is wrong**: The B base address formula should be `b_base + (j*tiles_K + k)*DIM` not `b_base + (k*tiles + j)*DIM`. Looking at the architecture docs: "B tile layout: `b_base + (j*tiles_K + k)*DIM`".

3. **Scale buffer selector is swapped**: `gemmini_mx_load_scales` sel=0 is for A (activation), sel=1 is for B (weight). The code has them correct, but let me verify the mxquant config.

4. **`gemmini_config_ld` stride for B**: B is stored column-major in DRAM as a matrix of shape [K][N], so the stride should be `MATMUL_N * sizeof(elem_t)` which is correct in the code.

5. **The `gemmini_flush` call**: This shouldn't be needed inside the loop and may cause issues.

6. **`gemmini_loop_ws_spad` B address**: Should pass `b_base + tiles_J*tiles_K*DIM` (the end = `BANK_NUM*BANK_ROWS`) which is correct.

7. **`gemmini_mx_read_smem` offset calculation**: `SPAD_DEST * 16 + r * BLK` - the smem offset is in 16-bit words. For row `r`, offset should be `SPAD_DEST * 16 + r * ncols` (not BLK when ncols < BLK). Wait, smem stores full BLK-wide rows, so `r * BLK` is correct for row stride.

The main bugs are the B mvin port and B tile indexing formula.
