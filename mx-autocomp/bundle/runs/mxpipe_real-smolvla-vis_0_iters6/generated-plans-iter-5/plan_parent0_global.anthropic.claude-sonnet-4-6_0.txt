## Analysis of the Current Code

Looking at the current solution, I can identify a clear inefficiency related to the selected strategy: **simplify or remove unnecessary code**.

### Key Inefficiency: Unnecessary `gemmini_flush(0)` Inside the Hot Loop

The code calls `gemmini_flush(0)` inside the inner loop (for every `i0` block):

```c
for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    // ... mvin B tiles ...
    for (int i0 = 0; i0 < BLOCKS_M; i0++) {
        // PROF accel
        gemmini_flush(0);  // ← THIS IS INSIDE THE HOT LOOP
        gemmini_extended3_config_ex(...);
        ...
    }
}
```

`gemmini_flush` is a full pipeline drain that waits for all in-flight instructions to complete and resets the Gemmini state machine. Calling it on every `(i0, j0)` block iteration is extremely expensive because:

1. It stalls the entire accelerator pipeline on every tile block
2. It resets Gemmini state unnecessarily — the configuration (`gemmini_extended3_config_ex` with the same arguments) doesn't change across iterations
3. It invalidates any potential instruction-level pipelining between iterations

### Additional Redundancy: `gemmini_extended3_config_ex` Called Every Iteration

The `gemmini_extended3_config_ex` call uses the **same arguments every iteration** (same dataflow, same MX format fields, same strides). Configuration registers persist until changed, so this only needs to be called **once** before the loop nest.

## Plan

1. **Move `gemmini_flush(0)` to before the outer loop nest** — call it exactly once at the start of `solution()`, not inside the `(j0, i0)` loop. This eliminates `BLOCKS_M * BLOCKS_N - 1` unnecessary flush stalls.

2. **Move `gemmini_extended3_config_ex(...)` to before the outer loop nest** — since all arguments are constant across all tile blocks, issue it once. Configuration state persists, so this is semantically equivalent per the hardware spec.

3. **Remove the `// PROF accel` comment** (cosmetic cleanup alongside the moved flush).

The pre-transposition of scale arrays (the two `for`/`memcpy` loops) stays as-is since it's already outside the hot loop and eliminates per-iteration memcpy. The B-tile mvin hoist at the `j0` level is also preserved. Only the flush and config-ex are moved/deduplicated.

This directly addresses "simplify or remove unnecessary code": the flush and config-ex inside the loop are genuinely unnecessary repeated work that can be hoisted out with no change in correctness or semantics.
