## Analysis

The original code has **CPU/host data staging inefficiency**: for each `(i0, j0)` tile pair, it copies scale factors into intermediate buffers `A_s` and `B_s` via `memcpy`, then passes those buffers to `gemmini_mx_load_scales`. Strategy 4 directly addresses this.

## Strategy Selection: **Strategy 4 — Eliminate memcpy staging by passing direct pointer arithmetic**

### Current Inefficiency

```c
// A scales: memcpy GK times per i0 (hoisted outside j0 loop)
for (int g = 0; g < GK; g++)
    memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);

// B scales: memcpy GK times per (i0, j0)
for (int g = 0; g < GK; g++)
    memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);

gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
```

The arrays `A_scales_row[GK][M]` and `B_scales_col[GK][N]` are row-major. The `gemmini_mx_load_scales` intrinsic streams `len` bytes from a DRAM base address into the scale memory. For a given `i0` block, we need `BLK` contiguous scale bytes starting at `&A_scales_row[g][i0 * BLK]` — **but only if those `BLK` bytes per row are contiguous in DRAM**.

### Layout Check

`A_scales_row[GK][M]` is a 2D C array with `M` columns. Row `g` has all `M` values contiguous. The slice for block `i0` is `&A_scales_row[g][i0 * BLK]` — this is `BLK` contiguous bytes within row `g`, but row `g+1` starts `M - BLK` bytes later. So the `GK` groups are **not** contiguous in memory when `M > BLK`.

### The Correct Fix

Instead of streaming all GK groups as one flat load, we call `gemmini_mx_load_scales` **once per group `g`** with:
- Address: `&A_scales_row[g][i0 * BLK]`
- Length: `BLK` bytes

The scale memory fills sequentially, so GK successive `gemmini_mx_load_scales` calls each loading `BLK` bytes reconstruct the same layout that was previously copied into `A_s`. This eliminates all `memcpy` calls entirely.

### Plan

1. **Remove** `A_s`, `B_s` intermediate staging arrays and all `memcpy` loops.
2. **Replace** the single `gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0)` call with a loop over `g` that issues `gemmini_mx_load_scales((uint64_t)&A_scales_row[g][i0 * BLK], BLK, 0)` for each `g` from `0` to `GK-1`. The hardware scale memory is filled in order, matching the layout previously assembled by memcpy.
3. **Replace** the single `gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1)` call with a loop over `g` that issues `gemmini_mx_load_scales((uint64_t)&B_scales_col[g][j0 * BLK], BLK, 1)` for each `g`.
4. Keep the A-scale load hoisted outside the `j0` loop (since A scales don't depend on `j0`), and keep the B-scale load inside the `j0` loop.
5. All other code (mvin, compute, read_smem) remains unchanged.

## Rewritten Code

```c
void solution(void) {
  const int GK = MATMUL_K / 32;

  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;

    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

      // Load A scales directly from source array using pointer arithmetic — no memcpy
      for (int g = 0; g < GK; g++)
        gemmini_mx_load_scales((uint64_t)&A_scales_row[g][i0 * BLK], BLK, 0);

      // Load B scales directly from source array using pointer arithmetic — no memcpy
      for (int g = 0; g < GK; g++)
        gemmini_mx_load_scales((uint64_t)&B_scales_col[g][j0 * BLK], BLK, 1);

      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);

      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
  }
}
```
