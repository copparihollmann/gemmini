## Analysis of the Current Code

Looking at the current code, I can identify the key inefficiency targeted by **strategy 7**: `gemmini_flush(0)` is called **inside the outer `(i0, j0)` loop**, meaning it executes once per output tile block. For a matrix with `BLOCKS_M × BLOCKS_N` output tiles, this is catastrophically expensive since `gemmini_flush` resets hardware state and is very costly.

The flush is only needed once to initialize the hardware state before the first computation begins. Subsequent iterations don't need it because the `gemmini_extended3_config_ex`, `gemmini_mx_load_scales`, etc. instructions properly configure all necessary state before each tile's computation.

## Plan: Hoist `gemmini_flush(0)` Outside All Loops

**What to change:**
1. Remove `gemmini_flush(0)` from inside the `for (int i0...) for (int j0...)` loop body.
2. Add a single `gemmini_flush(0)` call **before** the outermost `for (int i0 = 0; ...)` loop begins.

**Why this is correct:**
- The flush resets hardware state (scratchpad, accumulator, scale memory, etc.), but every iteration of the loop already re-issues `gemmini_extended3_config_ex`, `gemmini_mx_load_scales` (for both A and B), `gemmini_config_ld`, `gemmini_config_st`, `gemmini_mxquant_config_mvout`, and `gemmini_loop_ws_spad` — fully re-establishing all required hardware state from scratch each iteration.
- Therefore the per-iteration flush provides no correctness benefit after the first iteration; it only wastes cycles.
- A single flush before the loop initializes the hardware once, and then each tile's configuration sequence correctly sets up all state needed for that tile.

**Concrete code change:**

Move `gemmini_flush(0);` from:
```c
for (int i0 = 0; i0 < BLOCKS_M; i0++)
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    ...
    gemmini_flush(0);   // ← REMOVE from here
    gemmini_extended3_config_ex(...);
    ...
  }
```

To:
```c
gemmini_flush(0);       // ← ADD exactly once here, before all loops
for (int i0 = 0; i0 < BLOCKS_M; i0++)
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    ...
    gemmini_extended3_config_ex(...);
    ...
  }
```

This eliminates `BLOCKS_M × BLOCKS_N - 1` redundant flush calls, which for a 113×256×256 matrix with `BLK=16` gives `BLOCKS_M = ceil(113/16) = 8`, `BLOCKS_N = 256/16 = 16`, so **127 redundant flushes are eliminated** out of 128 total, directly reducing latency proportionally to the flush cost.
