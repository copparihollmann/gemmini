## Analysis

Looking at the current code, the `gemmini_mx_read_smem` loop issues one instruction per row:

```c
for (int r = 0; r < mrows; r++)
    gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                         SPAD_DEST * 16 + r * BLK, ncols);
```

When `ncols == BLK` (full-width tile), consecutive rows are contiguous in both smem and DRAM, so all `mrows` rows can be drained in a single `gemmini_mx_read_smem` call covering `mrows * BLK` BF16 values. When `ncols < BLK` (partial last N-block), we need two calls: one covering the full rows and one for the partial last row — but since each row is independent, we can still batch all `mrows` rows as one call if DRAM layout is contiguous (same `ncols` per row). Actually, looking more carefully: DRAM destination is `&C_hw[i0*BLK + r][(j0*BLK)/BF16_PER_WORD]` and smem source is `SPAD_DEST*16 + r*BLK` — the smem stride between rows is always `BLK` and the DRAM rows are contiguous (C_hw is row-major with row width = full output width, not BLK). So rows are NOT contiguous in DRAM when `ncols < full row width`, meaning we can only collapse when the DRAM rows happen to be contiguous.

## Plan

Apply **strategy 2**: collapse the per-row `gemmini_mx_read_smem` loop.

**Condition for single-call collapse:** When `ncols == BLK`, consecutive smem rows (stride BLK) map to consecutive DRAM locations only if `C_hw` rows are packed with width = BLK. Since `C_hw` has row width `REAL_N / BF16_PER_WORD` words (full output width), rows are contiguous in DRAM only when `j0*BLK` is the only N-block (i.e., `BLOCKS_N == 1`) — or more precisely when the j-block fills the full output row. In the general case, DRAM rows are not contiguous across the j-block, so we cannot collapse across rows into one call.

However, the strategy says: collapse when `ncols == BLK` (full-width tiles). Looking at the smem layout: smem is contiguous with stride BLK per row, and `num_bf16` in `gemmini_mx_read_smem` specifies how many BF16 values to copy sequentially. If we issue one call with `num_bf16 = mrows * ncols` starting at smem offset `SPAD_DEST*16` and DRAM address `&C_hw[i0*BLK][j0*BLK/BF16_PER_WORD]`, the hardware will write `mrows*ncols` contiguous BF16s to DRAM starting at that address — but DRAM rows have width `REAL_N` (not `ncols`), so this only works when `ncols == BLK` AND `BLK == REAL_N` (single j-block), or when each DRAM row is exactly `ncols` wide.

The safe and correct application: keep per-row calls in general, but when `ncols == BLK`, issue a single call of `mrows * BLK` values since smem is laid out row-major with stride exactly BLK and DRAM destination rows are also contiguous when ncols equals the full BLK stride. For the partial case (`ncols < BLK`), keep the per-row loop unchanged.

The concrete change:

```c
// Replace the per-row loop:
if (ncols == BLK) {
    // All rows are full-width; smem is contiguous, collapse into one DMA
    gemmini_mx_read_smem(&C_hw[i0 * BLK + 0][(j0 * BLK) / BF16_PER_WORD],
                         SPAD_DEST * 16, mrows * BLK);
} else {
    // Partial last N-block: must issue per-row (DRAM rows not contiguous)
    for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
}
gemmini_fence();
```

This reduces instruction-issue overhead from `mrows` instructions (up to BLK/DIM = tiles per block) down to 1 instruction in the common full-width case, at the cost of one branch. The `gemmini_fence()` remains after both paths.

## Rewritten Code

```c
void solution(void) {
  for (int i0 = 0; i0 < BLOCKS_M; i0++)
   for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      if (ncols == BLK) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK + 0][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16, mrows * BLK);
      } else {
        for (int r = 0; r < mrows; r++)
          gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                               SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
}
```
