1. **Scratchpad size**: The problem states 4 banks × 2048 rows = 8192 rows, each 16 bytes = 128KB total (not 256KB). Let me recheck - actually 8192 × 16 = 131072 = 128KB. The accumulator is 256 rows × 128 bytes = 32KB (not 64KB as rule 3 says, but rule 7 takes precedence with specific values).

2. **`gemmini_mx_load_scales` sel convention**: sel=0 for A (activations), sel=1 for B (weights). The original code has this correct.

3. **B mvin outside i-loop**: B is loaded once per j-tile but A scales change per i-block. The scale load happens inside the i-loop which is correct, but B scales are staged outside - this should be fine.

4. **`gemmini_flush` placement**: Should be before config_ex in the sequence, but the flush is called before config_ex which seems okay.

5. **A scale layout**: `A_scales_row[g][row]` - the scale memory layout should match `scale_dram + m*N_blocks + bi`. The A scales staging and loading needs careful attention.

6. **`SPAD_DEST` and `gemmini_mx_read_smem` offset**: `smem_off_bf16 = SPAD_DEST * 16`. The C spad word offset = `SPAD_DEST * 16` in 16-bit units.

  // Step 1: Configure execution (FP8 E4M3, BF16 output)
