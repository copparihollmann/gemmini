## Analysis

Looking at the current code, I identify the following inefficiency related to strategy 8:

**Current behavior:** The output readout uses a per-row loop:
```c
for (int r = 0; r < mrows; r++)
    gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                         SPAD_DEST * 16 + r * BLK, ncols);
gemmini_fence();
```
This issues `mrows` separate `gemmini_mx_read_smem` instructions (up to BLK/DIM = several iterations), each transferring only `ncols` BF16 elements from a different row offset in smem.

**The problem:** The smem layout after `gemmini_loop_ws_spad` stores the output block in row-major order with stride `BLK` BF16 elements per row (matching the tile's J dimension). If the output rows in smem are contiguous and the destination DRAM rows are also contiguous (i.e., C_hw is row-major with stride BLK/BF16_PER_WORD words per row), a single `gemmini_mx_read_smem` call with `mrows * BLK` total BF16 elements can replace the entire loop — but only when `ncols == BLK` (no partial last column block, i.e., `ncols == BLK`).

However, for correctness when `ncols < BLK`, we still need per-row calls. But we can collapse the full-block case into one call, and reduce overhead in all cases.

**Strategy 8 plan:** Replace the per-row `gemmini_mx_read_smem` loop with a single whole-block call when the output block is full (`ncols == BLK`), and keep the row loop only for the partial case. Since smem stores a full `mrows × BLK` BF16 region starting at `SPAD_DEST * 16`, and C_hw rows are packed with stride `MATMUL_N / BF16_PER_WORD` words, when `ncols == BLK` the destination is contiguous and we can issue one call for `mrows * BLK` elements. For the partial case (last column block), keep the row loop but with the correct `ncols` count.

**Concrete change:**
```c
// Replace:
for (int r = 0; r < mrows; r++)
    gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                         SPAD_DEST * 16 + r * BLK, ncols);

// With:
if (ncols == BLK) {
    // Full block: single call, smem is contiguous mrows*BLK BF16 elements
    gemmini_mx_read_smem(&C_hw[i0 * BLK + 0][(j0 * BLK) / BF16_PER_WORD],
                         SPAD_DEST * 16, mrows * BLK);
} else {
    // Partial last column block: must do per-row
    for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
}
```

This reduces the instruction count from `mrows` (e.g., 7 for the last partial M block, or BLK/DIM for full blocks) down to 1 for the common full-block case, eliminating loop overhead and reducing RoCC instruction dispatch cost.
