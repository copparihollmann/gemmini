## Analysis

The current code calls `gemmini_flush(0)` inside the outer `i0`/`j0` loop, once per block pair. This destroys pipeline state and forces full re-initialization on every iteration. Strategy 5 directly targets this: move `gemmini_flush(0)` to a one-time call before all loops.

## Plan: Apply Strategy 5 — Move `gemmini_flush(0)` Outside All Loops

### What the current code does wrong

In the current code, `gemmini_flush(0)` appears as the first accelerator instruction inside the `for (i0) for (j0)` double loop. For a 113×256×256 matmul with `BLK=256`, `BLOCKS_M` and `BLOCKS_N` are computed from ceiling divisions, so this flush executes on every `(i0, j0)` block pair — multiple times total. Each flush:

1. Drains the entire accelerator command queue
2. Invalidates all pipeline state (scratchpad controller, DMA engines, systolic array)
3. Forces the subsequent `gemmini_extended3_config_ex`, scale loads, and mvin sequences to start from a cold pipeline

This is catastrophic for throughput: every block re-pays the full pipeline warm-up cost.

### What to change

1. **Move `gemmini_flush(0)` to before the outer `i0` loop**, so it executes exactly once as a one-time initialization.
2. **Remove `gemmini_flush(0)` from inside the loop body**, replacing that line with nothing (the subsequent `gemmini_extended3_config_ex` on each iteration is sufficient to reconfigure format/dataflow state, which persists correctly across iterations without a flush).

### Why this is safe and correct

- The programming model sequence (`config_ex → load_scales → mvin → config_mvout → loop_ws_spad → read_smem → fence`) is preserved within each `(i0, j0)` iteration.
- Each iteration loads fresh A/B scales for its specific block, then does its own mvin, compute, and readout — so there is no stale state between iterations.
- The `gemmini_fence()` at the end of each iteration already ensures the accelerator has completed before the next iteration's `config_ex` is issued, providing the necessary ordering guarantee without a flush.
- `gemmini_flush` is only needed once at program start to ensure the accelerator begins from a clean reset state.

### Specific code change

**Before (inside the loop):**
```c
for (int i0 = 0; i0 < BLOCKS_M; i0++)
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    ...
    // PROF accel
    gemmini_flush(0);
    gemmini_extended3_config_ex(...);
    ...
  }
```

**After (flush moved before loops):**
```c
gemmini_flush(0);  // one-time initialization only
for (int i0 = 0; i0 < BLOCKS_M; i0++)
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    ...
    // PROF accel
    gemmini_extended3_config_ex(...);
    ...
  }
```

## Rewritten Code

```c
void solution(void) {
  gemmini_flush(0);  // one-time initialization: reset accelerator pipeline once before all tiles

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      // Partial last M/N block: compute only the real rows/cols, pad the rest.
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;
      // PROF cpu_stage
      // Stage only the tiny per-32-group scales; A/B data is mvin'd DIRECTLY
      // from DRAM (no host-side block memcpy — that was 98% of the cycles).
      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;
      // PROF accel
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K (full block-aligned tiles)
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
      for (int j = 0; j < tiles; j++)                    // B[k][j0*BLK+j] -> slot (k*tiles + j)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      // Accelerator-centric readout: per-row hardware DMA from smem straight into the
      // bf16-packed row-major output (block-internal smem row stride is BLK).
      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
}
```
