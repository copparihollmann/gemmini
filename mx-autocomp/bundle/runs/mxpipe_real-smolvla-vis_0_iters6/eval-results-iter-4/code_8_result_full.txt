Plan: ## Plan: Fast-Path Branch for Full Tiles (No Padding)

### Analysis of the Strategy

The strategy targets the observation that for most `(i0, j0)` iterations — specifically all except those involving the last block in M or N — `mrows == BLK` and `ncols == BLK`, meaning `pad_i == 0` and `pad_j == 0`. In the current code, `pad_i` and `pad_j` are computed every iteration and passed to `gemmini_loop_ws_spad`, but when they're zero the hardware doesn't need to mask any partial tile. By adding an explicit branch, we allow the common case to follow a simplified, constant-expression path with `pad_i=0, pad_j=0` hard-coded, eliminating runtime conditional checks for dominant iterations.

### Specific Changes

1. **Compute `mrows` and `ncols` first** (as the original does), then branch:
   - **Fast path**: `if (mrows == BLK && ncols == BLK)` — call `gemmini_loop_ws_spad` with literal `0, 0` for `pad_I` and `pad_J`. The compiler can constant-fold these zeros into the packed RS1 immediate, removing the runtime `pad_i`/`pad_j` variable computation and any conditional masking logic inside the fused loop.
   - **Slow path**: `else` — keep the existing code with computed `pad_i`/`pad_j` for the partial-tile boundary case.

2. **Hoist redundant setup out of the slow path**: Since both paths share identical setup (scale loads, mvin loops, config calls), those remain common. Only the `gemmini_loop_ws_spad` call and `pad_i`/`pad_j` variables differ between the two paths.

3. **Eliminate `pad_i`/`pad_j` variables in the fast path**: In the fast-path call, pass `0, 0` directly as integer literals for `pad_I` and `pad_J` arguments to `gemmini_loop_ws_spad`. This lets the compiler encode them as compile-time constants in the RoCC instruction encoding rather than reading them from registers.

### Why This Helps

- The majority of `(i0, j0)` pairs satisfy `mrows == BLK && ncols == BLK` since `REAL_M=113` with `BLK` tiles means only the last row-block is partial (and similarly for N). Almost all iterations take the fast path.
- Passing `pad_I=0, pad_J=0` as literals removes the need for the hardware fused loop to track and apply per-tile padding masks for those iterations, reducing instruction overhead.
- The branch itself is highly predictable (almost always taken for the fast path), so branch misprediction cost is negligible.

void solution(void) {
  for (int i0 = 0; i0 < BLOCKS_M; i0++)
   for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;

      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);

      if (mrows == BLK && ncols == BLK) {
        // Fast path: full tile, no padding needed — pass literal zeros
        gemmini_loop_ws_spad(tiles, tiles, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                             SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      } else {
        // Slow path: partial boundary tile, compute padding
        int pad_i = BLK - mrows, pad_j = BLK - ncols;
        gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                             SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      }

      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
}
