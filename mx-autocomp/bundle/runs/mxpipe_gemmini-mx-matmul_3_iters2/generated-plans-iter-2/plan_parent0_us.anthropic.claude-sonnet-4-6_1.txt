## Analysis

Looking at the original code, the A and B tiles are loaded with separate loops:
- A loop: stride = `MATMUL_K * sizeof(elem_t)` = 256 bytes
- B loop: same stride = 256 bytes

Each `gemmini_extended_mvin` loads exactly one DIM×DIM (16×16) tile. For this problem:
- `tiles_I = 128/16 = 8`
- `tiles_J = 128/16 = 8`  
- `tiles_K = 256/16 = 16`

Total mvin instructions: `8*16 + 8*16 = 256` instructions.

**Strategy 13** is directly applicable: use `gemmini_extended_mvin` with `rows > DIM` (up to `MAX_BLOCK_LEN * DIM = 64` rows) to batch-load multiple contiguous K-slices in one instruction, reducing total mvin instruction count by up to 4×.

## Plan

For each row of A tiles (fixed `i`, varying `k`), the tiles are stored contiguously in the scratchpad at `a_base + (i*tiles_K + k)*DIM`. In DRAM, with stride `MATMUL_K * sizeof(elem_t) = 256`, each successive k-slice is at `A_in + i*DIM*MATMUL_K + k*DIM`, meaning consecutive k tiles are 16 bytes apart in a row of 256 bytes — they are **not** contiguous in DRAM in the row direction, so we cannot trivially batch them across K with a single stride.

Wait — let me reconsider. The DRAM pointer is `((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM`. With `gemmini_config_ld(MATMUL_K * sizeof(elem_t))` = 256 byte stride (row stride), a single mvin with `rows=4` would load 4 consecutive rows of the same column-block. That means batching across 4 rows of the DIM×DIM tile — which for A would mean loading 4 consecutive `k`-blocks' worth of rows simultaneously, but those rows are separated by the full MATMUL_K stride in DRAM.

Actually: the mvin with `rows=R` loads `R` rows, each row being `cols` elements wide, with each successive row offset by the configured stride. So `gemmini_extended_mvin(ptr, spad_addr, DIM, 4*DIM)` loads 64 rows of DIM columns, each row DIM=16 bytes, with stride 256 bytes — this loads 4 complete DIM×DIM tiles (4 K-slices of the same I-row). The scratchpad addresses are consecutive: `spad_addr, spad_addr+16, spad_addr+32, spad_addr+48`.

Since `tiles_K = 16` is divisible by `MAX_BLOCK_LEN = 4`, we can batch 4 K-tiles per mvin instruction.

**Changes:**
1. In the A mvin loop, change the inner K loop to step by 4, loading 4 tiles at once with `rows = 4*DIM = 64`.
2. In the B mvin loop, same transformation.
3. This reduces total mvin instructions from 256 to 64 (4× reduction).

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Batch-load 4 K-slices of A per mvin (MAX_BLOCK_LEN=4, rows=4*DIM=64)
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++)
    for (int k = 0; k < tiles_K; k += 4)
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, 4 * DIM);

  // Batch-load 4 K-slices of B per mvin (MAX_BLOCK_LEN=4, rows=4*DIM=64)
  for (int j = 0; j < tiles_J; j++)
    for (int k = 0; k < tiles_K; k += 4)
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                            b_base + (j * tiles_K + k) * DIM, DIM, 4 * DIM);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```

**Verification of correctness:**
- `tiles_K = 16`, divisible by 4 — no partial batches.
- Each batch of 4 tiles: DRAM pointer advances by `k*DIM` within a row of stride `MATMUL_K=256`. The 4 rows loaded are at offsets `k*DIM, k*DIM+256, k*DIM+512, k*DIM+768` in bytes — exactly the 4 consecutive K-tile rows for fixed `i`.
- Scratchpad addresses: `(i*tiles_K + k)*DIM` through `(i*tiles_K + k)*DIM + 63` — 64 contiguous rows, matching the 4 consecutive K-tiles.
- Scratchpad capacity: `(8*16 + 8*16)*16 = 4096 ≤ 8192` rows ✓
- The `gemmini_loop_ws_spad` call and all other parameters remain unchanged.
