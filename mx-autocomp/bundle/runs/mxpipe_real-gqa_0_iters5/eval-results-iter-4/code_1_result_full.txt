### Analysis of the Bottleneck
In the current implementation, Step 2 (the float-free integer softmax pass) is executed entirely on the host CPU. For every element in the attention matrix ($S \times S = 64 \times 64 = 4096$ elements per head), the CPU must compute `mx_iexp(q[j] - mq)`.
* `q[j] - mq` is always a non-positive integer because `mq` is the maximum value of the row.
* `mx_iexp` is a mathematically intensive function approximating the natural exponential function using integer arithmetic (shifts, multiplications, and divisions). Computing this $4096 \times \text{ATT\_H}$ times per invocation consumes a massive number of CPU cycles.
* Because the exponential function decays extremely rapidly, `mx_iexp(x)` becomes exactly `0` once `x` drops below a relatively small negative threshold (typically within a few thousands in Q-format representation).

---

### Optimization Plan: Host-side LUT for `mx_iexp`

We will implement a cache-aligned, L1-resident static lookup table (LUT) to completely eliminate the runtime arithmetic overhead of `mx_iexp`.

1. **Define a Local Lookup Table (LUT):**
   We will create a static table `iexp_lut` with a size of `16384` entries. Each entry will store an `int64_t` value.
   ```c
   #define LUT_SIZE 16384
   static int64_t iexp_lut[LUT_SIZE];
   static int lut_initialized = 0;
   ```

2. **One-Time Lazy Initialization:**
   At the very beginning of the `solution()` function, we will check if the LUT has been initialized. If not, we will populate the table by calling the original `mx_iexp` function for negative index offsets:
   ```c
   if (!lut_initialized) {
       for (int i = 0; i < LUT_SIZE; i++) {
           iexp_lut[i] = mx_iexp(-i);
       }
       lut_initialized = 1;
   }
   ```
   This guarantees **bit-exact equivalence** to the original math function because the LUT is populated directly using the golden `mx_iexp` implementation.

3. **Replace the Inner-Loop Execution with $O(1)$ Lookup:**
   Since the input argument to `mx_iexp` is `diff = q[j] - mq` (which is always $\le 0$):
   * If `diff <= -LUT_SIZE`, we can immediately return `0` (since the exponential value has decayed to zero).

   int64_t diff = q[j] - mq;

   ```
