**Selected Strategy:** Strategy 9 (Accelerate the `mx_ilog2` function by replacing the software bit-scanning loop with the RISC-V Zbb `clz` instruction).

#### Inefficiency Analysis
In the CPU-bound I-BERT softmax step, the log-2 of 64-bit integer values (`sm` and `gmax`) is calculated for every row using the `mx_ilog2` function. The baseline implementation of `mx_ilog2` relies on a software-based bit-scanning loop that repeatedly shifts the value and increments a counter. This introduces substantial branch and instruction overhead inside the critical path of the softmax function.

Since the underlying RISC-V processor supports the Bitmanip (Zbb) extension (as evidenced by the existing `zext.h` inline assembly), we can replace the software loop with a native `clz` (count leading zeros) hardware instruction. For a non-zero 64-bit unsigned integer $x$, its floor log2 is exactly `63 - clz(x)`. This reduces the log2 calculation from a multi-cycle loop to just one hardware instruction plus a subtraction.

#### Refactoring Steps
1. **Implement `mx_ilog2_fast`**: Create an inline helper function that checks if the input is `0` (returning `0` to match the baseline behavior) and otherwise uses inline assembly to execute the RISC-V Zbb `clz` instruction.
2. **Replace calls in softmax**: Substitute all occurrences of `mx_ilog2` with `mx_ilog2_fast` inside the softmax loop.

// Fast hardware-accelerated ilog2 using RISC-V Zbb 'clz' instruction
static inline int mx_ilog2_fast(uint64_t x) {
  if (x == 0) return 0;
  uint64_t leading_zeros;
  asm ("clz %0, %1" : "=r"(leading_zeros) : "r"(x));
  return 63 - leading_zeros;
}
