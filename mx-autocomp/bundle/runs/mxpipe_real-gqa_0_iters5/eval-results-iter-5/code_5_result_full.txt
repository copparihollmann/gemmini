### Inefficiency Analysis
In the integer softmax and requantization step (Step 2), the host CPU processes every row by computing a 64-bit integer division:
```c
uint64_t inv_sm = (((uint64_t)1 << (ls + MX_FRAC)) + ((uint64_t)sm >> 1)) / (uint64_t)sm;
```
Because the host RISC-V CPU lacks a floating-point unit and typically relies on a multi-cycle iterative integer divider, executing a 64-bit division for every single row of the attention matrix incurs a massive instruction latency penalty.

### Optimization Plan
We will replace the slow 64-bit division with a fixed-point reciprocal lookup table. 
1. **Normalize the Divisor**: The sum `sm` has its highest active bit at index `ls = mx_ilog2(sm)`. We can normalize `sm` into a fixed 9-bit range $[512, 1023]$ by shifting it left or right based on `ls`.

3. **Approximation**: We index the table using `norm - 512`. Since the lookup table yields the reciprocal scaled correctly relative to the exponent, we obtain a bit-exact or nearly bit-exact `inv_sm` using a single fast memory lookup instead of an expensive hardware division.
