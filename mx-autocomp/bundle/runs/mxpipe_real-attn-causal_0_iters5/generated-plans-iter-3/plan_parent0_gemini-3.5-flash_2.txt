An elegant optimization plan to significantly reduce the execution time of the attention kernel by implementing **Strategy 2**.

### Optimization Plan: Causal Tile Pruning for $Q \times K^T$

Under causal masking (`ATT_CAUSAL`), any element in the attention matrix $S1[row][col]$ where $col > row$ is masked out (set to $-\infty$ before softmax, yielding $e^{-\infty} = 0$). In terms of $16 \times 16$ Gemmini tiles, any tile at tile-row $i$ and tile-column $j$ where $j > i$ contains only causal-masked elements. We can prune these entirely from execution, saving both DMA transfer and systolic array compute cycles.

We will restructure the $Q \times K^T$ matmul to execute row-by-row of tiles in software:
1. **Outer Loop over Tile Rows:** Loop $i$ from $0$ to $tiles\_I - 1$ (where $tiles\_I = 8$).
2. **Dynamic Tile Column Bound:** For a given tile row $i$, the number of active columns of tiles is $tiles\_J_{curr} = i + 1$. All columns $j > i$ are causal-masked and will be skipped.
3. **Scratchpad Allocation:** 
   - $Q$ tile row $i$ is loaded into scratchpad at `a_base = 0`.
   - $K^T$ active tile columns $0 \dots i$ are loaded into scratchpad at $b\_base = BANK\_NUM \times BANK\_ROWS - tiles\_K \times tiles\_J_{curr} \times DIM$.
4. **Compute:** 
   - Execute a $1 \times (i + 1) \times tiles\_K$ matmul using `gemmini_loop_ws_spad`.
5. **Strided SMEM Drain:** 
   - Because `gemmini_mx_read_smem` writes contiguously to DRAM, reading the entire $(i+1)$ block in one call would violate the 2D row-stride (`ATT_S`) of `S1_hw`. We will perform $16$ small, contiguous reads (one per row) to correctly place the computed elements in `S1_hw` while leaving the causal-masked elements untouched.

This strategy reduces the number of processed $Q \times K^T$ tiles from $64$ to $36$ (a **$43.75\%$ reduction in compute and weight loads**).
