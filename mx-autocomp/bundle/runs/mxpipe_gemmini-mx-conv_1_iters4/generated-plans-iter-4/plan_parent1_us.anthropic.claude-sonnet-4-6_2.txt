## Analysis

Looking at the original code, I need to identify the key inefficiency to target with exactly one strategy.

**Current code structure:**
1. im2col to fill `A_buf`
2. Configure execution
3. Load scales (once, good)
4. Configure both mvin ports with stride
5. Load tiles: outer loop over `k`, inner loops over `i` (mvin A) and `j` (mvin2 B)
6. Configure mvout once
7. Single `gemmini_loop_ws_spad` call
8. Read results

**Key observation:** The mvin loop structure loads all A and B tiles before compute begins. All tiles go into scratchpad, then a single fused `gemmini_loop_ws_spad` handles the entire matmul. This is the correct pattern for the fused loop.

**Strategy 5: Reuse loaded B (weight) tiles across multiple I-tile iterations without re-mvin**

Looking at the current loop:
```c
for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++) { mvin A }
    for (int j = 0; j < tiles_J; j++) { mvin2 B }
}
```

The B tiles are loaded once per k-slice, and A tiles are loaded once per (k, i). Since the fused `gemmini_loop_ws_spad` already handles the entire I×J×K computation internally, **all tiles need to be present in the scratchpad simultaneously anyway** — so reordering the mvin loop doesn't reduce the number of mvin commands here.

**Strategy 2: Loop reordering and restructuring** — The current k-outer, i-inner, j-inner ordering issues all A tiles for a given k, then all B tiles. Reordering to j-outer, k-inner for B loads vs i-outer, k-inner for A loads can improve DMA pipelining.

**Strategy 7: Use mvin2/mvin3 ports to parallelize A and B tile loads** — This is already partially done (mvin for A, mvin2 for B), but they're serialized within the loop. The key improvement is to **interleave individual A and B tile loads** more tightly so DMA can overlap them, rather than loading all A tiles then all B tiles for each k.

Looking more carefully: the current loop for each k loads ALL i tiles of A, then ALL j tiles of B. A better interleaving would alternate single A and B loads, maximizing DMA port overlap.

**Strategy 6: Amortize `gemmini_mxquant_config_mvout`** — currently called once, already optimal.

**Best choice: Strategy 2 (loop reordering)** — Reorder the mvin loops so that for each k-slice, we interleave one A tile load and one B tile load per iteration, maximizing overlap between the two DMA ports and improving memory-level parallelism.

## Plan

**Strategy: Loop reordering and restructuring (Strategy 2)**

Change the mvin loop from:
- Outer: k → inner: all-i A-tiles → then all-j B-tiles

To a structure that separates A and B loads into independent, maximally-batched sequences, ordered to better pipeline DMA activity:

**Specifically:** Restructure to loop `j` outer, `k` inner for B loads (mvin2), and separately `i` outer, `k` inner for A loads (mvin), issuing them in alternating fashion so the two DMA ports can work in parallel. Better: issue B tiles first (all j,k combinations), then A tiles (all i,k), or interleave at the (k,i) and (k,j) granularity to maximize parallel DMA throughput.

The most effective restructuring: change to `i`-outer, `k`-inner for A and `j`-outer, `k`-inner for B, issuing all B tiles first (since B is weight-stationary and accessed by all I tiles), then all A tiles — or vice versa — allowing the DMA engine to pipeline both ports without the alternating stall pattern.

```c
void solution(void) {
  // im2col
  for (int pi = 0; pi < CONV_H / CONV_KSZ; pi++)
    for (int pj = 0; pj < PATCHES_X; pj++)
      for (int c = 0; c < CONV_C; c++)
        for (int dy = 0; dy < CONV_KSZ; dy++)
          for (int dx = 0; dx < CONV_KSZ; dx++)
            A_buf[pi * PATCHES_X + pj][c * CONV_KSZ * CONV_KSZ + dy * CONV_KSZ + dx] =
                X_in[c][pi * CONV_KSZ + dy][pj * CONV_KSZ + dx];

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Load A tiles: i-outer, k-inner (port 0)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Load B tiles: j-outer, k-inner (port 1)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Issue all B tile loads first (j-outer, k-inner), then all A tile loads (i-outer, k-inner)
  // This groups all mvin2 commands together and all mvin commands together,
  // allowing the DMA arbiter to pipeline B-port and A-port transfers with
  // minimal port-switching overhead and better command queue utilization.
  for (int j = 0; j < tiles_J; j++) {
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
          b_base + (j * tiles_K + k) * DIM, DIM, DIM);
    }
  }
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin(
          (void*)(((elem_t*)A_buf) + i * DIM * MATMUL_K + k * DIM),
          a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
