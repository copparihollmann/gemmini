## Analysis of the Current Code

The current code issues all A `gemmini_block_mvin` calls first (port 0), then all B `gemmini_block_mvin` calls (also port 0 implicitly via `gemmini_block_mvin`). This means the two DMA engines are serialized: B loading only begins after A loading completes.

Looking at the code:
```c
// MVIN A: port 0 (mvin)
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int i = 0; i < tiles_I; i++) {
    gemmini_block_mvin(...);  // port 0
}

// MVIN B: port 0 (mvin) — same port, serialized!
gemmini_config_ld(MATMUL_N * sizeof(elem_t));
for (int k = 0; k < tiles_K; k++) {
    gemmini_block_mvin(...);  // port 0
}
```

Both use `gemmini_block_mvin` (funct `k_MVIN`, port 0). The B tiles could instead use `gemmini_extended_mvin2` (port 1), and if we interleave A and B issues, both DMA engines run concurrently.

## Strategy: Exploit `mvin2` Port for B Tiles Concurrently with `mvin` for A Tiles (Strategy 6)

### Plan

**Step 1: Switch B tile loads to `gemmini_block_mvin2`**

Define or use `gemmini_block_mvin2` (which maps to `k_MVIN2`) for B tile loads. This requires a separate `gemmini_extended3_config_ld` (or `gemmini_config_ld` with id=1) for port 1's stride. Looking at `gemmini_extended4_config_ld`, the `id` parameter selects the port (0=mvin, 1=mvin2, 2=mvin3).

**Step 2: Configure both ports' strides before issuing interleaved loads**

- Issue `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0)` for port 0 (A tiles, stride = K bytes per row)
- Issue `gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), SCALE_IDENTITY, false, 1)` for port 1 (B tiles, stride = N bytes per row)

**Step 3: Interleave A and B mvin issues**

Instead of completing all A loads then all B loads, interleave them so port 0 and port 1 can pipeline. Since `tiles_I=4` and `tiles_K=4` (for 64×64), there are 4 A block-mvins and 4 B block-mvins. Issue them in pairs:

```
A[i=0] via mvin (port 0)
B[k=0] via mvin2 (port 1)
A[i=1] via mvin (port 0)
B[k=1] via mvin2 (port 1)
...
```

This allows the hardware to overlap A and B DMA transfers, effectively halving tile-load time.

**Step 4: Define `gemmini_block_mvin2` macro**

```c
#define gemmini_block_mvin2(dram_addr, spad_addr, len) \
  gemmini_extended_mvin2(dram_addr, spad_addr, (len) * DIM, DIM)
```

The B tile addressing must remain unchanged: `b_base + (k * tiles_J) * DIM` with `tiles_J` tiles per block via `gemmini_block_mvin2(..., tiles_J)`.

The result is that both DMA ports are active simultaneously during the load phase, overlapping A and B transfers and reducing total mvin latency before `gemmini_loop_ws_spad` can begin.
