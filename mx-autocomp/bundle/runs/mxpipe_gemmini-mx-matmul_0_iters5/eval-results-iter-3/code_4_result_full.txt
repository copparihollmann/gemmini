## Strategy: Hoist Pointer Arithmetic + Use `gemmini_block_mvin`

**For A tiles**: The inner loop over k iterates `tiles_K = 4` times. So we swap the loop order to outer-k, inner-j, and batch the j-loop with `gemmini_block_mvin(..., tiles_J)` — reducing 16 mvin commands to 4 (one per k-tile).

This reduces total DMA command count from 32 to 8 (4 for A + 4 for B), and eliminates ~48 multiply operations from the hot setup path.

    // tiles_I == tiles_K == 4, so we pair them: iteration t loads
    //   - A row-group t (all tiles_K k-tiles) via port 0
    //   - B k-group t   (all tiles_J j-tiles) via port 1
    // Both pairs are independent and can be pipelined by the hardware.
    {
        const elem_t *A_ptr = (const elem_t *)A_in;
        const elem_t *B_ptr = (const elem_t *)B_in;

        #pragma GCC unroll 4
        for (int t = 0; t < tiles_I; t++) {
            // A: row-group t — all k-tiles contiguous, batch via block_mvin (port 0)
            const void *a_dram = (const void *)(A_ptr + (t * DIM) * MATMUL_K);
            uint32_t    a_sp   = a_base + t * tiles_K * DIM;
            gemmini_block_mvin(a_dram, a_sp, tiles_K);

            // B: k-group t — all j-tiles contiguous, batch via mvin2 (port 1)
            const void *b_dram = (const void *)(B_ptr + (t * DIM) * MATMUL_N);
            uint32_t    b_sp   = b_base + t * tiles_J * DIM;
            gemmini_extended_mvin2(b_dram, b_sp, tiles_J * DIM, DIM);
        }
    }

    // -----------------------------------------------------------------------
    // 4. Configure output store and requantizer
    //    i_bound/j_bound/k_bound must exactly match tiles_I/tiles_J/tiles_K
    //    used in the subsequent gemmini_loop_ws_spad call.
    // -----------------------------------------------------------------------
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors,
        tiles_I, tiles_J, tiles_K,
        /*scale_act_sel*/0, /*scale_w_sel*/0,
        /*lut_update_granularity*/1);

    // -----------------------------------------------------------------------
    // 5. Execute fused weight-stationary tiled matmul
    //    LOOP_WS_CONFIG_SPAD_AB (funct 24) is re-issued inside the macro
    //    (mx_loop_spad_marker is one-shot and must be set before every call).
    //    skip_mask=0x38: skip ldA + ldB + ldD (already in spad).
    // -----------------------------------------------------------------------
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0,
        a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST,
        false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

    // -----------------------------------------------------------------------
    // 6. Drain BF16 results from shared memory to DRAM, then fence
    // -----------------------------------------------------------------------
    gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
}
