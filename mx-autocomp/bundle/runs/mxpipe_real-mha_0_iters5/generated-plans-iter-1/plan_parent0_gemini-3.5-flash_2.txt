An elegant and highly effective optimization plan to significantly reduce the execution time of the MHA kernel is to implement **Strategy 4: SWAR (SIMD-within-a-register) techniques on the host CPU to pack and write multiple quantized FP8 elements to `P_q` simultaneously.**

### Analysis of the Bottleneck

In the baseline kernel, step 2 performs float-free integer softmax and fp8 requantization on the host CPU. Within this loop, the quantized results are written back to `P_q[i][j]` one byte at a time:
```c
for (int j = g * 32; j < (g + 1) * 32; j++) 
    P_q[i][j] = mx_ienc_fp8(p[j], inv_sm, ls, e);
```
Since `P_q` holds 1-byte elements (`elem_t` / `uint8_t`), writing row-by-row element-by-element triggers thousands of 8-bit store instructions on the host CPU. Because the host CPU does not have a vector unit, we can use SWAR to manually pack multiple 8-bit values into a wider register (e.g., `uint64_t`) and write them to memory in a single 64-bit store instruction. This reduces store instruction counts by **8x** and greatly improves cache write-buffer efficiency.

### Optimization Plan

1. **Leverage Alignment and Dimensions**:
   * `ATT_S` is 64, meaning each row in `P_q` starts at a 64-byte aligned boundary.
   * The sub-group loop iterates in steps of 32 (`g * 32`), which is a multiple of 8.
   * This guarantees that any address `&P_q[i][j]` where `j` is a multiple of 8 is perfectly aligned for a 64-bit (8-byte) write, avoiding any unaligned access penalties on the RISC-V host.

2. **Unroll and Pack**:
   * Change the loop increment for `j` from `1` to `8`.
   * Unroll the loop body by a factor of 8, calling `mx_ienc_fp8` for 8 consecutive elements.
   * Shift and OR these 8 bytes into a single `uint64_t` register.
   * Write the fully packed `uint64_t` register to memory by casting the destination pointer: `*(uint64_t*)&P_q[i][j] = packed_val;`

3. **Retain Gemmini Correctness**:
   * Keep all Gemmini configurations, scale loads, computations, and fences intact to guarantee bit-exact outputs matching the baseline execution.

### Target Code Transformation

We will transform the inner requantization loop in Step 2:

```c
// ---- OLD PATH ----
for (int j = g * 32; j < (g + 1) * 32; j++) {
  P_q[i][j] = mx_ienc_fp8(p[j], inv_sm, ls, e);
}

// ---- NEW SWAR PATH ----
for (int j = g * 32; j < (g + 1) * 32; j += 8) {
  uint64_t packed = 0;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 0], inv_sm, ls, e);
  packed |= (uint64_t)mx_ienc_fp8(p[j + 1], inv_sm, ls, e) << 8;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 2], inv_sm, ls, e) << 16;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 3], inv_sm, ls, e) << 24;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 4], inv_sm, ls, e) << 32;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 5], inv_sm, ls, e) << 40;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 6], inv_sm, ls, e) << 48;
  packed |= (uint64_t)mx_ienc_fp8(p[j + 7], inv_sm, ls, e) << 56;
  
  *((uint64_t *)&P_q[i][j]) = packed;
}
```

This simple, targeted optimization reduces CPU store instruction overhead in the critical path, preparing the workload for subsequent hardware pipeline and memory hierarchy tiling improvements.
