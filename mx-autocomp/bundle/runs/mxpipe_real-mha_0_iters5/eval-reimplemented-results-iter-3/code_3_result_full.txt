### Optimization Plan: Grouped-Query Scale Factor Memory Reuse

#### 1. Inefficiency Analysis
In Grouped-Query Attention (GQA) configurations where $H_{kv} < H$, multiple query heads share the same Key and Value heads. This means consecutive query heads $h$ in the outer loop share the same key scale factors (`KT_sc`) and value scale factors (`V_sc`). 

In the baseline implementation, the outer loop iterates over every query head $h$, loading `KT_sc` and `V_sc` on *every single iteration*. This results in redundant scale loads, stalling the host CPU and wasting off-chip DRAM bandwidth.

#### 2. Grouping Strategy
We will restructure the computation by grouping heads that share the same `kv` index. 
Let `GROUP_SIZE = ATT_H / ATT_HKV`. We will loop over each of the $H_{kv}$ groups. Within each group:
1. **Compute 1 (S1 = Q @ K^T)**: Load the shared `KT_sc` scale factor *once* into `mx_scale_b_mem` (sel=1). Then, iterate over the query heads $gh$ within the current group, load their individual $Q$ scale factors, compute $S1$, and store the results into a local group buffer `S1_hw_local[gh]`.
2. **Softmax + FP8 Requantization**: Run the integer softmax and FP8 requantization sequentially for all heads in the group, saving outputs into local buffers `P_q_local[gh]` and `P_scales_local[gh]`.
3. **Compute 2 (O = P @ V)**: Load the shared `V_sc` scale factor *once* into `mx_scale_b_mem` (sel=1). Then, iterate over the query heads $gh$ within the group, load their individual $P$ scale factors, and compute $O$ directly into the global output `O_hw`.

#### 3. Memory Allocation
To support processing a group of heads together without interference, we will define local stack-allocated buffers:
- `S1_hw_local[GROUP_SIZE][ATT_S][ATT_S / 4]` (8 KB per head)
- `P_q_local[GROUP_SIZE][ATT_S][ATT_S]` (4 KB per head)
- `P_scales_local[GROUP_SIZE][GROUPS_S][ATT_S]` (128 bytes per head)

These buffers are extremely compact and fit comfortably on the stack.
