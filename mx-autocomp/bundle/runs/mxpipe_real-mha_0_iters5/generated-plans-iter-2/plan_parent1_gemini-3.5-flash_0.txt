An elegant way to optimize the performance of this multi-head attention kernel is to address the stack allocation overhead and data cache locality of the host CPU during the softmax calculation. 

### Optimization Plan: Strategy 6 — Reuse Local Memory Buffers

#### Inefficiency Analysis
In the baseline code, the intermediate arrays `int64_t q[ATT_S]`, `int64_t p[ATT_S]`, and `int64_t gmax_arr[GROUPS_S]` are allocated on the stack inside the row-wise loop (`for (int i = 0; i < ATT_S; i++)`). 
For each attention head $H$ and each row $S$, the host CPU must repeatedly adjust the stack pointer, allocate these arrays, write to them, and then tear down the stack frame. This happens $ATT\_H \times ATT\_S = 4 \times 64 = 256$ times. This frequent stack manipulation destroys L1 data cache locality because different stack offsets might be used, and the memory footprint is unnecessarily re-evaluated, leading to stack-related CPU overhead.

#### Proposed Changes
We will apply **Strategy 6** to reuse a single set of local memory buffers:
1. Move the declarations of `q`, `p`, and `gmax_arr` out of the nested loops to the very top of the `solution()` function.
2. Allocate them once at the function level:
   ```c
   int64_t q[ATT_S];
   int64_t p[ATT_S];
   int64_t gmax_arr[GROUPS_S];
   ```
3. Remove the local inner declarations `int64_t q[ATT_S]`, `int64_t p[ATT_S]`, and `int64_t gmax_arr[GROUPS_S]` from the loop.
4. Keep all processing logic, including causal masking and SWAR packing, exactly the same to preserve bit-exact numerical equivalence.

By reusing the same memory addresses across all iterations of the rows and heads, these buffers will reside permanently in the L1 data cache of the host, eliminating cache thrashing and reducing the CPU instruction count associated with stack allocation.
