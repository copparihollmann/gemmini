### Optimization Plan: Multi-Query/Grouped-Query Attention KT and V Reuse Across Heads (Strategy 9)

#### Inefficiency Analysis
In the baseline implementation, the outer loop iterates over the query heads $h \in [0, \text{ATT\_H})$. For every head $h$, the corresponding Key ($KT$) and Value ($V$) projections are loaded into the Gemmini scratchpad:
1. $KT$ is loaded to compute $S1 = Q \times KT$.
2. $V$ is loaded to compute $O = P \times V$.

In Multi-Query Attention (MQA) or Grouped-Query Attention (GQA), multiple query heads share the same Key/Value head ($\text{ATT\_HKV} \le \text{ATT\_H}$). The index mapping is given by `kv = h / (ATT_H / ATT_HKV)`. 
Loading $KT$ and $V$ for every head $h$ results in redundant DRAM-to-scratchpad transfers. This dominates the execution latency since DRAM scale/matrix loads are highly latency-sensitive.

#### Optimization Strategy
We will restructure the computation by grouping the query heads according to their associated KV head:
1. **Outer loop over `kv`** ($\text{kv} \in [0, \text{ATT\_HKV})$):
   - **Phase 1: $Q \times KT$ stage**:
     * Load the matrix $KT_{\text{kv}}$ **once** into the B-matrix region of the scratchpad (`b_base`).
     * Loop through the query heads $h$ belonging to this `kv` group. For each head, load its unique $Q$ matrix into `a_base` and execute $Q \times KT$. Since $KT$ is already present in `b_base`, we skip the B matrix transfer entirely (`skips = 0x38`), saving substantial DRAM bandwidth. Store the intermediate $S1$ results in a temporary head-group buffer.
   - **Phase 2: Integer Softmax stage**:
     * Run the software softmax pipeline sequentially for all query heads in the current group, outputting the scaled probabilities into a temporary group buffer $P\_q$.
   - **Phase 3: $P \times V$ stage**:
     * Load the matrix $V_{\text{kv}}$ **once** into the B-matrix region of the scratchpad (`b_base`).
     * Loop through the query heads $h$ in the group. Load each head's unique $P\_q$ into `a_base` and compute $P \times V$. Again, $V$ is reused directly from the scratchpad, bypassing the redundant B-mvin.

This approach amortizes the cost of loading $KT$ and $V$ across $\text{HEADS\_PER\_KV} = \text{ATT\_H} / \text{ATT\_HKV}$ heads.
