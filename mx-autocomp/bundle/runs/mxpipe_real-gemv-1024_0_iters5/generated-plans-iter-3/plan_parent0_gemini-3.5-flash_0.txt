An elegant and highly effective optimization strategy for this code is **Monolithic Global Tiling (Single-Shot Matrix Execution)**.

### Optimization Strategy: Monolithic Global Tiling (Single-Shot Matrix Execution)

The original code partitions the $64 \times 64$ matrix multiplication into smaller sub-blocks of size `BLK` using host-side loops. This approach incurs severe performance penalties:
1. **Control Flow Overhead**: Multiple iterations of configuring the accelerator, loading scale factors, and initiating memory transfers.
2. **Host-Side Data Copying**: Time spent copying and restructuring scale factors into static contiguous buffers (`A_scales_preformatted` and `B_scales_preformatted`).
3. **Underutilization of Hardware**: It leaves the $256\text{ KB}$ scratchpad and $64\text{ KB}$ accumulator almost entirely empty.

Since the entire $64 \times 64$ problem is small enough to fit completely in the scratchpad and accumulator at once, we can eliminate the outer block loops (`i0`, `j0`) and the temporary scale formatting buffers entirely. 

#### Resource Layout Verification:
* **Scratchpad Space**: Loading the entire $A$ matrix requires $4 \times 4 \times 16 = 256$ rows. Loading the entire $B$ matrix also requires $256$ rows. The combined total of $512$ rows fits comfortably within the $8192$ rows available.
* **Accumulator Space**: The $C$ matrix occupies $4 \times 4 \times 16 = 256$ rows, matching the maximum limit of $256$ accumulator rows perfectly.
* **Overlapping**: Placing $B$ at $8192 - 256 = 7936$ ensures it never overlaps with $A$ (which starts at row $0$ and goes up to $256$).

By executing the entire matrix multiplication in a single monolithic hardware sweep, we completely bypass CPU staging overhead, load scale factors directly from global memory only once, and maximize hardware resource saturation.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"
#include "include/matmul_fp8_64x64.h"

#define DIM 16
#define ADDR_LEN 32
#define BF16_PER_WORD 4
#define OUT_COLS (MATMUL_M / BF16_PER_WORD)

typedef uint8_t  elem_t;
typedef uint64_t out_t;

void solution(void) {
  // Compute global tile dimensions
  const int tiles_I = MATMUL_M / DIM; // 4 tiles
  const int tiles_J = MATMUL_N / DIM; // 4 tiles
  const int tiles_K = MATMUL_K / DIM; // 4 tiles

  const uint32_t a_base = 0;
  const uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
  const int SPAD_DEST = 128;

  // 1. Flush and configure execution format (FP8: E4M3 inputs, BF16 output)
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 
                              1, 1, 0, 0, false, 0, 0, 3, 0);

  // 2. Stream scale factors directly from their original DRAM locations
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. MVIN entire A matrix directly from source DRAM (with K-stride)
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
  }

  // 4. MVIN entire B matrix directly from source DRAM (with N-stride)
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));
  for (int k = 0; k < tiles_K; k++) {
    for (int j = 0; j < tiles_J; j++) {
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + k * DIM * MATMUL_N + j * DIM),
                            b_base + (k * tiles_J + j) * DIM, DIM, DIM);
    }
  }

  // 5. Configure store stride and requantization parameters
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // 6. Compute monolithic fused weight-stationary matmul
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, 
                       a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST, 
                       false, false, false, false, false, NO_ACTIVATION, 
                       0, 0, false, 0x38);

  // 7. Drain the entire shared memory output buffer directly to C_hw and fence
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
