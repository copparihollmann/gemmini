An analysis of the original code reveals a massive performance bottleneck due to **CPU data staging**. Specifically, the code tiles the 64x64 matrix into smaller blocks (`BLOCKS_M` and `BLOCKS_N`) and performs host-side scale factor formatting using `memcpy`. This design results in:
1. Significant CPU overhead on the hot path due to sequential `memcpy` copies.
2. Redundant configuration (`gemmini_extended3_config_ex`) and scale factor loads inside the outer loops.
3. Extremely low scratchpad and accumulator utilization.

### Optimization Plan
We will apply **Strategy 5: rewrite the algorithm to reduce total work** by performing the entire $64 \times 64 \times 64$ matrix multiplication in a single, monolithic hardware invocation. 

Since the target size ($M=64, N=64, K=64$ with $DIM=16$) fits perfectly inside the 256KB scratchpad and 64KB accumulator:
- **Scratchpad Capacity**: $A$ requires 256 rows and $B$ requires 256 rows. The total of 512 rows is well below the hardware's 8192-row capacity.
- **Accumulator Capacity**: $C$ requires 256 rows, which perfectly matches the 256-row capacity.

By restructuring the algorithm to operate on the full matrix directly:
1. We **completely eliminate the CPU loops and `memcpy` staging**.
2. We load scale factors directly from DRAM via `gemmini_mx_load_scales` once.
3. We perform high-throughput strided MVINs directly from source DRAM.
4. We invoke the fused hardware loop `gemmini_loop_ws_spad` exactly once to maximize hardware utilization and minimize command latency.

### Optimized Code

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include "include/gemmini_testutils.h"
#include "include/matmul_fp8_64x64.h"

#define GEMMINI_SF_MEM 0x40088000
#define GEMMINI_SF_MEM_A (GEMMINI_SF_MEM + 0x2000)
#define GEMMINI_SF_MEM_B GEMMINI_SF_MEM
#define SMEM 0x40000000

#define DIM 16
#define ADDR_LEN 32

// BF16 values packed 4 per uint64_t output word
#define BF16_PER_WORD 4

typedef uint8_t  elem_t;   // fp8:e4m3 input elements
typedef uint8_t  welem_t;  // fp8:e4m3 weight elements
typedef uint64_t out_t;    // 4x bf16 packed per word

// Optimized MX matmul avoiding CPU-side loops and staging overhead
void solution(void) {
  int tiles_I = MATMUL_M / DIM;
  int tiles_J = MATMUL_N / DIM;
  int tiles_K = MATMUL_K / DIM;

  uint32_t a_base = 0;
  uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
  int SPAD_DEST = 128;
  int OUT_COLS = MATMUL_M / BF16_PER_WORD;

  // 1. Flush and configure execution format for FP8 MX weight-stationary mode
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  // 2. Load scale factors directly from source DRAM arrays
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. MVIN A tiles directly from strided source DRAM
  gemmini_config_ld(MATMUL_M * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      elem_t *dram_ptr = ((elem_t*)A_in) + i * DIM * MATMUL_M + k * DIM;
      uint32_t sp_addr = a_base + (i * tiles_K + k) * DIM;
      gemmini_extended_mvin((void *) dram_ptr, sp_addr, DIM, DIM);
    }
  }

  // 4. MVIN B tiles directly from strided source DRAM
  for (int j = 0; j < tiles_J; j++) {
    for (int k = 0; k < tiles_K; k++) {
      elem_t *dram_ptr = ((elem_t*)B_in) + j * DIM * MATMUL_M + k * DIM;
      uint32_t sp_addr = b_base + (j * tiles_K + k) * DIM;
      gemmini_extended_mvin((void *) dram_ptr, sp_addr, DIM, DIM);
    }
  }

  // 5. Configure store and requantizer parameters for the whole block
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // 6. Compute the monolithic fused weight-stationary loop
  gemmini_loop_ws_spad(
    tiles_I, tiles_J, tiles_K,
    0, 0, 0,
    a_base,
    BANK_NUM * BANK_ROWS,
    0,
    SPAD_DEST,
    false, false,
    false, false, false,
    NO_ACTIVATION,
    0, 0,
    false,
    0x38);

  // 7. Drain output results from MX shared memory to DRAM and synchronize
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
