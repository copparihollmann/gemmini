## Analysis

Looking at the code, I need to identify the most impactful single strategy to apply.

**Current structure:**
- Outer loops over `i0` (BLOCKS_M) and `j0` (BLOCKS_N)
- For each `(i0, j0)` pair: load scales, mvin A tiles, mvin B tiles, compute, read smem
- `BLK` tiles of A are re-loaded for **every** j0 iteration — A tiles are not reused
- `BLK` tiles of B are re-loaded for **every** i0 iteration — B tiles are not reused
- `tiles = BLK/DIM`, `tiles_K = MATMUL_K/DIM`

**Strategy 4: Assign B tiles to fixed high-address scratchpad region to enable weight-stationary reuse across I tiles**

The key insight is: in weight-stationary mode, B (weights) are stationary. If we loop `j0` in the outer loop and `i0` in the inner loop, we can load B once per `j0` and reuse it across all `i0` iterations. This eliminates `BLOCKS_M - 1` redundant B loads per `j0`.

**Current loop order:** `i0 → j0` (B reloaded BLOCKS_M times per j0 value)
**Proposed loop order:** `j0 → i0` (B loaded once per j0, reused across all i0)

With the outer loop swapped to `j0`, B tiles stay fixed in the high scratchpad region. A tiles change per `i0` but use the low scratchpad region (`a_base = 0`). Scales also need updating: A scales change per `i0`, B scales change per `j0`.

**Scratchpad feasibility check:**
- `tiles = BLK/DIM`, `tiles_K = MATMUL_K/DIM`
- A occupies: `tiles * tiles_K * DIM` rows
- B occupies: `tiles * tiles_K * DIM` rows
- Total: `2 * tiles * tiles_K * DIM ≤ 8192` — same as before, just reuse B

The B mvin is moved outside the `i0` loop. The A mvin, scale loads, config, compute, and readout stay inside `i0`. Only `gemmini_extended3_config_ex` is hoisted out entirely (strategy 6 is complementary but we apply only one — however strategy 4 implicitly requires careful ordering, and we can naturally hoist config_ex too as it's part of enabling the reuse cleanly; we'll focus on strategy 4).

## Plan

**Apply Strategy 4: outer-j0, inner-i0 loop order with B tiles loaded once per j0 block.**

Changes:
1. Swap loop order to `j0` outer, `i0` inner.
2. Move B-scale loading (`gemmini_mx_load_scales` for sel=1) and B mvin outside the `i0` loop (after computing `b_base`).
3. Keep A-scale loading (`gemmini_mx_load_scales` for sel=0) and A mvin inside the `i0` loop since A changes per row block.
4. The programming model sequence must be preserved per invocation of `gemmini_loop_ws_spad`: inside `i0`, we issue config_ex, load A scales, load B scales (but B scales already loaded — however per rule 15, scales must be loaded before the loop that consumes them; since they persist until overwritten, we re-load B scales once per j0 before the i0 loop and re-load A scales per i0 before each compute). Actually since `gemmini_loop_ws_spad` is issued once per `(i0,j0)`, and both scale buffers must be valid at that point, we load B scales once per j0, and A scales once per i0 — both before the compute inside i0.
5. The `scale_factors` pointer used in `gemmini_mxquant_config_mvout` must also index correctly per `(i0,j0)`.
6. Hoist `gemmini_extended3_config_ex` and `gemmini_flush` before both loops (loop-invariant, and flush once before all work).

This reduces B mvin cost by factor of `BLOCKS_M` and eliminates redundant B scale loads.

```c
void solution(void) {
  // Hoist loop-invariant configuration outside all loops
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
                               1, 1, 0, 0, false, 0, 0, 3, 0);

  // Outer loop over J (weight columns) — B tiles are weight-stationary across I
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    int ncols = REAL_N - j0 * BLK;
    if (ncols > BLK) ncols = BLK;
    if (ncols <= 0) continue;

    int tiles    = BLK / DIM;
    int tiles_K  = MATMUL_K / DIM;
    uint32_t a_base = 0;
    uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
    int SPAD_DEST   = 128;
    int pad_j = BLK - ncols;

    // Load B scales once for this j0 block (reused across all i0)
    for (int g = 0; g < MATMUL_K / 32; g++)
      memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
    gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);

    // Load B tiles into fixed high scratchpad region once for this j0
    gemmini_config_ld(MATMUL_N * sizeof(elem_t));
    for (int j = 0; j < tiles; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
          b_base + (k * tiles + j) * DIM, DIM, DIM);

    // Inner loop over I (activation rows) — A tiles change, B tiles reused
    for (int i0 = 0; i0 < BLOCKS_M; i0++) {
      int mrows = REAL_M - i0 * BLK;
      if (mrows > BLK) mrows = BLK;
      if (mrows <= 0) continue;

      int pad_i = BLK - mrows;

      // Stage A scales for this i0 block
      for (int g = 0; g < MATMUL_K / 32; g++)
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);

      // Load A scales (sel=0) — must be loaded before compute
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      // Reload B scales (sel=1) — reaffirm for this compute invocation
      // (B scales already in hardware from outer loop load, but
      //  per the sequence requirement both must be valid before loop_ws_spad;
      //  since sel=1 persists and hasn't changed, we do NOT reload here —
      //  B scales loaded once per j0 above remain valid)

      // Load A tiles for this i0 block
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
            a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      // Configure output and requantizer
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors,
                                   tiles, tiles, tiles_K, 0, 0, 1);

      // Compute fused tiled matmul
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0,
                           a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST,
                           false, false, false, false, false,
                           NO_ACTIVATION, 0, 0, false, 0x38);

      // Drain results from smem to DRAM
      if (mrows == BLK && ncols == BLK) {
        gemmini_mx_read_smem(
          &C_hw[i0 * BLK + 0][(j0 * BLK) / BF16_PER_WORD],
          SPAD_DEST * 16, BLK * BLK);
      } else {
        for (int r = 0; r < mrows; r++)
          gemmini_mx_read_smem(
            &C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
            SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
  }
}
```

**Key changes summarized:**
- Loop order swapped to `j0` outer, `i0` inner
- B tile mvin and B scale staging moved outside `i0` loop — loaded once per `j0`
- A tile mvin and A scale staging remain inside `i0` loop
- `gemmini_flush` and `gemmini_extended3_config_ex` hoisted before all loops
- B tiles still placed at `b_base = BANK_NUM*BANK_ROWS - tiles*tiles_K*DIM` (rule 12 satisfied)
- Both scale buffers are valid before each `gemmini_loop_ws_spad` (B loaded once per j0 and persists; A loaded each i0)
- Strategy 7 (single smem read for full blocks) applied as a minor addition for the full-block case
