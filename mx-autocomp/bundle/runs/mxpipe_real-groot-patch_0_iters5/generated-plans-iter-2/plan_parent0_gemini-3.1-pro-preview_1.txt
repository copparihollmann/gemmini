### Optimization Plan

The most significant bottleneck in the given code is the redundant loading of the A matrix and its scale factors from DRAM. The outer block loops are structured such that `i0` controls the M dimension (A matrix blocks) and `j0` controls the N dimension (B matrix blocks). Currently, the `gemmini_mx_load_scales` and `gemmini_extended_mvin` commands for the A matrix are placed **inside** the inner `j0` loop. Since A tiles depend only on `i0` and the K dimension is fully consumed in one pass (`tiles_K = MATMUL_K / DIM`), the exact same A tiles and scales are loaded into the scratchpad repeatedly for every `j0` iteration (8 times in this 41x512x512 shape).

We will apply **Strategy 1: reduce data movement** by hoisting the A matrix memory transfers out of the inner loop, along with invariant accelerator configurations:

1. **Hoist Invariant Configurations:** `gemmini_flush`, `gemmini_extended3_config_ex`, `gemmini_config_st`, and `gemmini_mxquant_config_mvout` rely entirely on constants. They will be hoisted outside both loops to avoid issuing redundant RoCC instructions.
2. **Hoist A Matrix DMA:** We will move the `gemmini_config_ld(MATMUL_K ...)` and `gemmini_extended_mvin` loops for A out of the `j0` loop so they execute exactly once per `i0`.
3. **Hoist A Scale Factors:** `gemmini_mx_load_scales` for `pre_A_s[i0]` will similarly be moved to the `i0` loop.

Because A tiles occupy scratchpad rows `0` to `2047` and B tiles are independently placed at the top of the scratchpad (rows `6144` to `8191`), A's data safely persists in the scratchpad across all `j0` iterations without being clobbered by B. This transformation cuts the DRAM bandwidth required for the A matrix by an 8x factor.

#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// AUTO-GENERATED outer-tiled MX matmul baseline (41x512x512).
void solution(void) {
  // Pre-stage scale buffers once for all blocks, amortizing the restriding
  // cost across all BLOCKS_M * BLOCKS_N iterations.
  const int GK = MATMUL_K / 32;

  // Static pre-staged scale arrays: [block_idx][scale_group][elem_in_block]
  // Sized for the maximum number of blocks along each dimension.
  static uint8_t pre_A_s[BLOCKS_M][MATMUL_K / 32][BLK];
  static uint8_t pre_B_s[BLOCKS_N][MATMUL_K / 32][BLK];

  // One-time restride: copy from strided A_scales_row[g][i0*BLK] into
  // contiguous pre_A_s[i0][g][0..BLK-1], done once before the main loop.
  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_A_s[i0][g][0], &A_scales_row[g][i0 * BLK], BLK);

  for (int j0 = 0; j0 < BLOCKS_N; j0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_B_s[j0][g][0], &B_scales_col[g][j0 * BLK], BLK);

  // Global tile counts are invariant for the full hardware sweep shape
  int tiles = BLK / DIM;
  int tiles_K = MATMUL_K / DIM;

  // PROF accel: Hoist invariant configuration outside the double loop
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_config_st(BLK_OUTC * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);

  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    // Partial last M block: compute only the real rows, pad the rest.
    int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
    
    uint32_t a_base = 0;
    int pad_i = BLK - mrows;

    // --- HOISTED A MATRIX LOADS ---
    // A matrix and its scale factors depend only on i0. Load them once per M-block sweep.
    gemmini_mx_load_scales((uint64_t)pre_A_s[i0], A_S_BYTES, 0);

    gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K (full block-aligned tiles)
    for (int i = 0; i < tiles; i++) {
      for (int k = 0; k < tiles_K; k++) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      }
    }

    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      // Partial last N block: compute only the real cols, pad the rest.
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_j = BLK - ncols;

      // No per-iteration memcpy: use pre-staged contiguous scale pointers directly.
      gemmini_mx_load_scales((uint64_t)pre_B_s[j0], B_S_BYTES, 1);

      gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
      for (int j = 0; j < tiles; j++) {                  // B[k][j0*BLK+j] -> slot (k*tiles + j)
        for (int k = 0; k < tiles_K; k++) {
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
        }
      }

      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      // Accelerator-centric readout: per-row hardware DMA from smem straight into the
      // bf16-packed row-major output (block-internal smem row stride is BLK).
      for (int r = 0; r < mrows; r++) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
  }
}
