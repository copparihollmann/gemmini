## Analysis of the Original Code

The original code loads B tiles using `gemmini_block_mvin` (which uses the `k_MVIN` port) for **both** A and B tiles sequentially:

```c
// A tiles via mvin (port 0)
for (int i = 0; i < tiles_I; i++)
    gemmini_block_mvin(...A..., a_base + i * tiles_K * DIM, tiles_K);
// B tiles via mvin (port 0) — sequential, no overlap
for (int j = 0; j < tiles_J; j++)
    gemmini_block_mvin(...B..., b_base + j * tiles_K * DIM, tiles_K);
```

Both loops use the same DMA port (`k_MVIN`), so they execute **serially**. The hardware has independent `mvin` and `mvin2` ports that can be issued back-to-back without waiting for each other.

## Selected Strategy

**Strategy 8/5: Use `gemmini_extended_mvin2` for B-tile loads and `gemmini_extended_mvin` for A-tile loads simultaneously, exploiting independent mvin/mvin2 DMA ports to overlap A and B scratchpad fills.**

## Plan

1. **Keep A-tile loads on `mvin` (port 0)** using `gemmini_extended_mvin` with stride `MATMUL_K * sizeof(elem_t)`.

2. **Move B-tile loads to `mvin2` (port 1)** using `gemmini_extended_mvin2` with stride `MATMUL_K * sizeof(elem_t)`.

3. **Interleave the A and B mvin instructions** in a single combined loop over the tile indices, issuing one A-mvin and one B-mvin back-to-back per iteration. This allows the hardware's two independent DMA engines to overlap their DRAM fetches concurrently.

4. **Fix the B-tile scratchpad addressing** to match the correct reference pattern `b_base + (j*tiles_K + k)*DIM` (per strategy 9). The original code uses `b_base + j*tiles_K*DIM` (the start of row `j`) and then relies on `gemmini_block_mvin` to lay down `tiles_K` consecutive rows — which is equivalent only if tiles_K tiles are contiguous. With `gemmini_extended_mvin2` we issue individual (i,k) and (j,k) tile loads explicitly, using the canonical address formula.

5. **Configure `mvin2` stride** via `gemmini_extended4_config_ld` with `id=1` before the B-tile loads (or interleaved loop), setting stride = `MATMUL_K * sizeof(elem_t)` for port 1.

6. **Interleaving structure**: iterate over the larger of `tiles_I` and `tiles_J` in the outer loop, and over `tiles_K` in the inner loop. For each (i, k) pair issue an A-mvin, and for each (j, k) pair issue a B-mvin2 — pairing them so that both DMA engines receive work at the same rate.

The key change is that instead of completing all A loads before starting any B loads, the two DMA ports receive interleaved commands and can execute in parallel, cutting the total tile-load latency roughly in half.

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
      1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure port 0 (mvin) stride for A tiles
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  // Configure port 1 (mvin2) stride for B tiles
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Interleave A (mvin/port0) and B (mvin2/port1) tile loads
  // so both DMA engines work in parallel.
  // Outer loop covers max(tiles_I, tiles_J); guard with bounds checks.
  int max_IJ = (tiles_I > tiles_J) ? tiles_I : tiles_J;
  for (int ij = 0; ij < max_IJ; ij++) {
    for (int k = 0; k < tiles_K; k++) {
      if (ij < tiles_I) {
        elem_t *a_ptr = ((elem_t*)A_in) + ij * DIM * MATMUL_K + k * DIM;
        uint32_t a_sp = a_base + (ij * tiles_K + k) * DIM;
        gemmini_extended_mvin((void*)a_ptr, a_sp, DIM, DIM);
      }
      if (ij < tiles_J) {
        elem_t *b_ptr = ((elem_t*)B_in) + ij * DIM * MATMUL_K + k * DIM;
        uint32_t b_sp = b_base + (ij * tiles_K + k) * DIM;
        gemmini_extended_mvin2((void*)b_ptr, b_sp, DIM, DIM);
      }
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors,
      tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0,
      a_base, BANK_NUM * BANK_ROWS, 0,
      0, false, false, false, false, false,
      NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], 0, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
