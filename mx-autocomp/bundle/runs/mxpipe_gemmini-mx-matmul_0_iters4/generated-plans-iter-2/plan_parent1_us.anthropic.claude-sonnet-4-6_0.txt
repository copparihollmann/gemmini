## Analysis of the Current Code

Looking at the original code, I need to identify the B tile DRAM stride issue:

```c
// Port 1 (B tiles) configured with stride MATMUL_K:
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

// B tile pointer:
(void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM)
```

The B matrix is stored as `B_in[MATMUL_K][MATMUL_N]` (K rows × N columns, row-major). When loading a tile at column `j*DIM` and row `k*DIM`, consecutive rows in the tile are separated by `MATMUL_N` bytes (the full row width), **not** `MATMUL_K` bytes. The stride configured for port 1 is wrong — it should be `MATMUL_N * sizeof(elem_t)`.

Similarly, the A matrix is stored as `A_in[MATMUL_M][MATMUL_K]` (M rows × K columns). Tile rows are separated by `MATMUL_K` bytes — so port 0's stride `MATMUL_K * sizeof(elem_t)` is **correct** for A. But port 1's stride for B must be `MATMUL_N * sizeof(elem_t)`.

## Plan: Apply Strategy 10 — Fix DRAM Stride for B Tiles

**The problem:** Port 1 is configured with stride `MATMUL_K * sizeof(elem_t)` for B tiles, but B is laid out row-major as `[MATMUL_K][MATMUL_N]`, so each row of a B tile is `MATMUL_N` bytes apart in DRAM. Using `MATMUL_K` as the stride causes `gemmini_extended_mvin2` to read incorrect (and potentially overlapping) bytes for each tile row, producing silently corrupted weight data fed into the systolic array.

**The fix:** Change the `gemmini_extended3_config_ld` call for port `id=1` to use `MATMUL_N * sizeof(elem_t)` as the stride. The pointer arithmetic for the B tile base address `((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM` correctly computes the start of tile `(k,j)` in a `[MATMUL_K][MATMUL_N]` layout (row `k*DIM`, column `j*DIM`), so **only the stride value needs to change**.

**Concrete code change:**
```c
// Before (wrong):
gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

// After (correct):
gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);
```

This is a one-line change that fixes silent data corruption and ensures the hardware reads the correct B tile bytes, which is a prerequisite for any subsequent performance optimization to produce correct results.

void solution(void) {

  // Configure port 0 (A tiles): A is [MATMUL_M][MATMUL_K], row width = MATMUL_K
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Configure port 1 (B tiles): B is [MATMUL_K][MATMUL_N], row width = MATMUL_N (fixed)
  gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Interleave A loads (port 0) and B loads (port 1) within the same k-loop
  for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++) {

        (void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
        a_base + (i * tiles_K + k) * DIM,
        DIM, DIM);
    }
    for (int j = 0; j < tiles_J; j++) {
      gemmini_extended_mvin2(
        (void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
        b_base + (j * tiles_K + k) * DIM,
        DIM, DIM);
    }
  }

  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
