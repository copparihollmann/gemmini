## Strategy: Overlapping A and B Loads via Independent Mvin Ports (Reduce Data Movement / Loop Restructuring)

**Plan:** Interleave A-tile mvin commands (via `gemmini_extended_mvin`) with B-tile mvin2 commands (via `gemmini_extended_mvin2`) by issuing them in an interleaved loop. This allows the DMA engine to pipeline A and B loads in parallel using separate ports, reducing total load latency before the compute phase begins.

Currently `gemmini_block_mvin` uses `k_MVIN` for both A and B — the B loads cannot begin until all A loads drain the command queue. By switching B loads to `gemmini_extended_mvin2` (port 1) and interleaving the issue of A and B commands within the same loop, the two DMA channels can operate concurrently.
