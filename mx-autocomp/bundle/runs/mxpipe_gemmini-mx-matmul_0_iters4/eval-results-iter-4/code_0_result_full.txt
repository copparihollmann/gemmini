### How This Improves Performance

For this problem, `MATMUL_K` determines `tiles_K`. The A matrix has row stride `MATMUL_K * sizeof(elem_t)` and the B matrix also has row stride `MATMUL_K * sizeof(elem_t)`. They share the same stride, but `mvin` and `mvin2` have **independent configuration registers** — each port maintains its own stride setting via separate `CONFIG_LD` commands (id=0 for mvin, id=1 for mvin2).

1. The hardware can pipeline/overlap DMA transfers for A and B simultaneously, since they use different scratchpad regions and different DMA ports.
2. We eliminate the sequential dependency between A-load completion and B-load start.
3. We correctly split any block larger than `MAX_BLOCK_LEN=4` into chunks to avoid DMA corruption.

The key insight: A tiles go to the **bottom** of the scratchpad (`a_base`), B tiles go to the **top** (`b_base`). These are non-overlapping regions, so concurrent DMA into both is safe.
