## Analysis of the Original Code

The original code uses `gemmini_mxquant_config_mvout` with `lut_update_granularity = tiles_J`. This means the requantizer LUT is refreshed once per row of output tiles (every `tiles_J` tiles). However, since no LUT is loaded (`uselut=0`, FP8 format), the same output quantization configuration applies uniformly to the entire output matrix. There is no need to refresh the LUT more frequently than once for the entire computation.

## Selected Strategy: Strategy 7 — Increase `lut_update_granularity` to `tiles_I * tiles_J`

### Why This Applies

The current call is:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_J);
```

The `lut_update_granularity` parameter `G` controls how often the requantizer's output LUT is refreshed during the post-pass over output tiles. With `G = tiles_J`, the hardware refreshes the LUT once per row of `tiles_J` output tiles — that is `tiles_I` refreshes total. Since the same BF16 output format applies to all `tiles_I * tiles_J` output tiles uniformly (no per-tile LUT variation), the LUT only needs to be loaded once for the entire matmul.

### The Plan

Change the `lut_update_granularity` argument from `tiles_J` to `tiles_I * tiles_J`:

```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_I * tiles_J);
```

This tells the requantizer to perform exactly one LUT refresh for the entire `tiles_I × tiles_J` output tile grid instead of `tiles_I` refreshes. Since the output format is fixed (BF16, `out_mx_fmt=3`) and the same scale configuration applies throughout, this is semantically equivalent while reducing the number of LUT refresh operations from `tiles_I` down to 1.

No other changes are needed. The rest of the kernel — config, scale loads, mvin loops, loop_ws_spad, read_smem, fence — remains identical.

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  for (int i = 0; i < tiles_I; i++)
    gemmini_block_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K),
                       a_base + i * tiles_K * DIM, tiles_K);
  for (int j = 0; j < tiles_J; j++)
    gemmini_block_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K),
                       b_base + j * tiles_K * DIM, tiles_K);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_I * tiles_J);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
