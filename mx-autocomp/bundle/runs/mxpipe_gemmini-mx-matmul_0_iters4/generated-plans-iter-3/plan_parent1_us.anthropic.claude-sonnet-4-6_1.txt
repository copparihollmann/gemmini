## Analysis of the Original Code

Looking at the original code, I need to identify the most impactful inefficiency:

```c
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int i = 0; i < tiles_I; i++)
    gemmini_block_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K),
                       a_base + i * tiles_K * DIM, tiles_K);
for (int j = 0; j < tiles_J; j++)
    gemmini_block_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K),
                       b_base + j * tiles_K * DIM, tiles_K);
```

`gemmini_block_mvin` expands to `gemmini_extended_mvin(..., (len)*DIM, DIM)` — it loads `tiles_K` DIM-wide columns in one instruction **but only loads 1 row at a time** (rows=DIM means one DIM×DIM tile). Looking more carefully: `gemmini_block_mvin(addr, spad, len)` issues a single mvin with `cols = len*DIM` and `rows = DIM`, loading `len` consecutive tiles horizontally in one instruction. This is correct for loading an entire row of K-tiles per call.

**Strategy 9** — use `mvin2`/`mvin3` ports to parallelize A and B tile loads simultaneously — is directly applicable. Currently the code loads all A tiles sequentially, then all B tiles sequentially in two separate loops. By interleaving A loads (via `mvin`) with B loads (via `mvin2`) in a single loop, both DMA ports can operate concurrently, overlapping the two data movements.

## Plan

**Apply Strategy 9: use `mvin2` port to parallelize A and B tile loads simultaneously.**

### Changes:

1. Replace the two separate loops (one for A tiles using `gemmini_block_mvin`/mvin port, one for B tiles) with a **single combined loop** that issues A tile loads via `gemmini_extended_mvin` (mvin port) and B tile loads via `gemmini_extended_mvin2` (mvin2 port) in the same iteration.

2. Since tiles_I and tiles_J may differ, loop over `max(tiles_I, tiles_J)` iterations and guard each mvin/mvin2 with a bounds check — or loop over `tiles_I` for A and `tiles_J` for B within the same loop body (using the larger count and conditionals).

3. Keep the same `gemmini_config_ld` stride (it applies to mvin port; mvin2 uses the same stride register for id=1 — but note that `gemmini_extended3_config_ld` with `id` field controls which port's stride is set). Both A and B have the same stride `MATMUL_K * sizeof(elem_t)`, so a single `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0)` for port 0 and `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 1)` for port 1 must be issued before the combined loop.

4. The loop iterates `max(tiles_I, tiles_J)` times; in each iteration `i`: if `i < tiles_I`, issue mvin for A row `i`; if `i < tiles_J`, issue mvin2 for B row `i`. This maximally overlaps A and B DMA transfers.

### Resulting code:

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure stride for both mvin port 0 (A) and mvin port 1 (B)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  int max_tiles = tiles_I > tiles_J ? tiles_I : tiles_J;
  for (int t = 0; t < max_tiles; t++) {
    if (t < tiles_I)
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + t * DIM * MATMUL_K),
                            a_base + t * tiles_K * DIM,
                            tiles_K * DIM, DIM);
    if (t < tiles_J)
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + t * DIM * MATMUL_K),
                             b_base + t * tiles_K * DIM,
                             tiles_K * DIM, DIM);
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_J);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
