Looking at the failing code, I need to identify the bugs:

1. **B matrix scratchpad layout is wrong**: The B base address passed to `gemmini_loop_ws_spad` should be `b_base + tiles_K*tiles*DIM` (the "top" end address), but the code uses `b_base0 + b_buf_sz` which may not correctly reflect the layout for the current buffer.

2. **B mvin layout mismatch**: B tiles are stored at `b_base + (k * tiles + j) * DIM` but the hardware expects `b_base + (j * tiles_K + k) * DIM` style. Let me re-check the canonical layout: B tile layout is `b_base + (j*tiles_K + k)*DIM`.

3. **Scale loading happens AFTER config but the ordering in the pipeline is broken** - scales for `idx` are loaded as part of the "next block" load phase, but config_ex is re-issued for compute without re-issuing scale loads. The hardware uses whatever is currently in scale memory.

4. **B mvin stride**: B is column-major in the loop - stride should be `MATMUL_N * sizeof(elem_t)`.

5. **The B top address passed to loop_ws_spad**: Should be `b_base + tiles_K*tiles_J*DIM` (the exclusive end, i.e., `BANK_NUM*BANK_ROWS`).
