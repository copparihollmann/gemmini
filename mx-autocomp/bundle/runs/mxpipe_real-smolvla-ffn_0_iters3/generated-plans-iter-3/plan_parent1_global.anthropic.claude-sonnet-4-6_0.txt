## Analysis

The current code has a critical inefficiency: inside the hot `i0`/`j0` loop, it calls `memcpy` to stage scale factors from the full `A_scales_row`/`B_scales_col` arrays into `A_s`/`B_s` staging buffers. This happens **every iteration** of the outer loop (once per output block). The profiler comment confirms this was "98% of the cycles" in an earlier version, and the optimizer output explicitly flags "2 memcpy" in the hot path.

**Strategy 6** directly addresses this: pre-pack all A and B scale slices into contiguous staging buffers **once before the loop**, so the hot path only calls `gemmini_mx_load_scales` pointing directly into those pre-packed buffers without any per-iteration `memcpy`.

## Plan

### What to change

**Before the outer loop**, pre-transpose/pre-pack the scale factors into contiguous per-block buffers:

1. Allocate (or declare as static/global) two flat arrays:
   - `A_s_packed[BLOCKS_M][MATMUL_K/32][BLK]` — for each `i0` block, all `K/32` groups, `BLK` scale values
   - `B_s_packed[BLOCKS_N][MATMUL_K/32][BLK]` — for each `j0` block, all `K/32` groups, `BLK` scale values

2. **One-time pre-pack loop** (before `i0`/`j0`):
   ```
   for each i0: for each g: copy A_scales_row[g][i0*BLK .. i0*BLK+BLK] into A_s_packed[i0][g][0..BLK]
   for each j0: for each g: copy B_scales_col[g][j0*BLK .. j0*BLK+BLK] into B_s_packed[j0][g][0..BLK]
   ```

3. **Inside the hot loop**, replace the per-block `memcpy` calls with a direct pointer:
   - Remove the `for (int g ...) { memcpy(&A_s[g][0], ...); memcpy(&B_s[g][0], ...); }` block entirely
   - Pass `(uint64_t)A_s_packed[i0]` and `(uint64_t)B_s_packed[j0]` to `gemmini_mx_load_scales`

This moves all host-side data movement out of the accelerator's critical path. The `gemmini_mx_load_scales` calls remain (they are DMA loads, not memcpys), so the programming model sequence is preserved exactly. The scale data loaded is identical byte-for-byte to what was loaded before — only the CPU staging cost is eliminated.

### Why this is correct

- The pre-packed buffers contain exactly the same scale values as the old `A_s`/`B_s` per-block copies, just computed once instead of `BLOCKS_M × BLOCKS_N` times.
- `A_S_BYTES` and `B_S_BYTES` remain unchanged (they describe the per-block scale buffer size).
- The programming model sequence (`config_ex → load_scales → mvin → mxquant_config → loop_ws_spad → read_smem → fence`) is unchanged.
- No scratchpad layout, tile dimensions, or accumulator usage changes.

## Rewritten Code

```c
// Pre-packed scale buffers: [block_idx][group][lane]
// Allocated once, filled before the outer loop.
static uint8_t A_s_packed[BLOCKS_M][(MATMUL_K / 32)][BLK];
static uint8_t B_s_packed[BLOCKS_N][(MATMUL_K / 32)][BLK];

void solution(void) {
  // Pre-pack all A and B scale slices once, outside the hot loop.
  // This eliminates the per-(i0,j0) memcpy from the accelerator critical path.
  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
    for (int g = 0; g < MATMUL_K / 32; g++)
      memcpy(&A_s_packed[i0][g][0], &A_scales_row[g][i0 * BLK], BLK);
  }
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;
    for (int g = 0; g < MATMUL_K / 32; g++)
      memcpy(&B_s_packed[j0][g][0], &B_scales_col[g][j0 * BLK], BLK);
  }

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      // PROF accel
      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      // Load pre-packed scale slices directly — no per-block memcpy needed.
      gemmini_mx_load_scales((uint64_t)A_s_packed[i0], A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s_packed[j0], B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
}
```
