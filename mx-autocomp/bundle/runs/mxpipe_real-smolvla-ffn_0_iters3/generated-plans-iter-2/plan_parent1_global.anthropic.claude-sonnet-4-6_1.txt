## Analysis

Looking at the original code, I need to identify which strategy is most applicable.

**Current code structure:**
- Outer loops over `BLOCKS_M × BLOCKS_N` tiles
- Each iteration: `gemmini_flush` + full setup + mvin A + mvin B + compute + read_smem + `gemmini_fence()`
- `gemmini_fence()` is called inside the loop, after every single tile's `gemmini_mx_read_smem`

**Strategy 4: Minimize `gemmini_fence` calls by deferring synchronization**

Currently, `gemmini_fence()` is called at the end of every `(i0, j0)` iteration. This is a full memory barrier that stalls the pipeline after every block. However, the fence is only needed before the host reads the output buffer — not between tiles.

The key insight: the output tiles write to different locations in `C_hw` (different `i0, j0` coordinates), so there's no data dependency between consecutive tiles that would require fencing between them. We can defer all fences to after the entire `BLOCKS_M × BLOCKS_N` loop completes, issuing just **one** `gemmini_fence()` at the end.

**Why this works:** Each `(i0, j0)` block writes to a distinct region of `C_hw` (row `i0*BLK`, col `j0*BLK/BF16_PER_WORD`), so no RAW/WAW hazards exist between iterations that would require inter-iteration fencing. The `gemmini_mx_read_smem` inside the loop queues the DMA transfer; we only need the fence before the host consumes any result.

**Plan:**
1. Remove `gemmini_fence()` from inside the `(i0, j0)` loop body
2. Add a single `gemmini_fence()` after the entire double loop completes

This reduces `BLOCKS_M * BLOCKS_N` fence calls down to 1, eliminating the pipeline stall overhead that occurs between every tile.

```c
void solution(void) {
  for (int i0 = 0; i0 < BLOCKS_M; i0++)
   for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }

      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);

      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);

      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);

      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      if (mrows == BLK && ncols == BLK) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK][j0 * BLK / BF16_PER_WORD],
                             SPAD_DEST * 16, BLK * BLK);
      } else {
        for (int r = 0; r < mrows; r++)
          gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                               SPAD_DEST * 16 + r * BLK, ncols);
      }
      // fence removed from here
    }
  // Single fence after all tiles are issued
  gemmini_fence();
}
```
