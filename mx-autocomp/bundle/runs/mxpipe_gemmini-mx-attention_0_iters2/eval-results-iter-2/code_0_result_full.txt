```c

```

The current code does two separate passes:
1. **Pass 1**: Unpack all BF16 values → store into `q[4][ATT_S]` → find max
2. **Pass 2**: For each `j`, reload `q[r][j]` → compute `mx_iexp(q[r][j] - mq[r])`

The store-then-reload of `q[4][ATT_S]` is wasteful. We can **fuse** these into a single pass by computing `mx_iexp(val - max)` immediately — but we need the max first. The two-pass structure is inherently required for numerical correctness (need max before exp). However, strategy 12 says to eliminate the `q` array by using the **already-unpacked values directly in the exp pass**, which requires storing only the raw BF16 words (already in `S1_hw`) and re-unpacking during the exp pass.

**The change**: Eliminate the `int64_t q[4][ATT_S]` stack array entirely. Instead:

1. **Pass 1 (max-finding)**: Iterate over `S1_hw` words, unpack BF16 values, track per-row max — but do **not** store into `q`. Just update `mq[r]`.

This eliminates:
- The `int64_t q[4][ATT_S]` stack allocation (4 × ATT_S × 8 bytes of stack)
- All stores `q[r][j] = val` and subsequent loads `q[r][j]` in the exp loop
- Replaces them with recomputing the unpack (cheap integer op) a second time

The `p[4][ATT_S]` array is still needed (used later in the scale quantization loop), so it stays. The two-pass structure is preserved for correctness. The net effect is elimination of the large intermediate array and its associated memory traffic.
