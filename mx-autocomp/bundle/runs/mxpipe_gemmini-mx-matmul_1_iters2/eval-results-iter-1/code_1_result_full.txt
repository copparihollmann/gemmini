## Selected Strategy: #11 — Fully Unroll the MVIN Loops

### Plan

For this 32×32×32 kernel, `tiles_I = MATMUL_M/DIM = 2`, `tiles_J = MATMUL_N/DIM = 2`, `tiles_K = MATMUL_K/DIM = 2`. These are small compile-time constants. The two nested mvin loops (one for A, one for B) each have only 4 iterations total. Each loop iteration involves a branch instruction, a counter update, and a comparison — pure overhead with no useful work.

By adding `#pragma GCC unroll 2` (or manually unrolling) to each loop, GCC will eliminate all loop control instructions and emit the 4 mvin instructions for A and 4 mvin instructions for B as straight-line code. This removes 8 branch/compare/increment sequences from the hot path, reduces instruction-cache pressure, and allows the out-of-order pipeline to better overlap the mvin issue with subsequent configuration instructions.

The change is mechanical: add `#pragma GCC unroll 2` before the inner `for (int k ...)` loop in both the A-mvin block and the B-mvin block. Optionally also unroll the outer `for (int i ...)` / `for (int j ...)` loops with the same pragma. No semantic changes are needed — the same 8 mvin instructions are issued, in the same order, with the same addresses and scratchpad destinations.
