## Analysis

Looking at the original code, I need to identify which strategy applies best.

**Current code analysis:**
- `gemmini_mxquant_config_mvout(..., tiles_I, tiles_J, tiles_K, 0, 0, 1)` — the last argument `lut_update_granularity=1` means the requantizer LUT refreshes **every single tile**, i.e., `tiles_I × tiles_J × tiles_K` refreshes total.
- This is FP8 with `uselut=0`, so there's no FP6 LUT being loaded, but there is still an output requantization LUT (the `out_mx_fmt=3` BF16 output path still goes through the requantizer's internal quantization logic controlled by `lut_update_granularity`).
- Strategy 8 says: increase `lut_update_granularity` to `tiles_K` or larger to minimize requantizer LUT refresh overhead across the entire matmul.

**Plan: Apply Strategy 8 — Increase `lut_update_granularity`**

In the original code:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
```

The `lut_update_granularity=1` causes the requantizer to refresh its output LUT after every tile in the K dimension, totaling `tiles_I * tiles_J * tiles_K` refreshes. Since the scale factors are fixed across all K tiles for a given (i,j) output tile, the LUT content doesn't need to change at every K step. Setting `lut_update_granularity=tiles_K` means the LUT refreshes only once per (i,j) output tile — `tiles_I * tiles_J` times total — reducing refresh overhead by a factor of `tiles_K`. For the same reason correctness is preserved: the output scale for each (i,j) tile is determined by the row/col scales of that tile, not by intermediate K accumulations.

The change is minimal: replace `1` with `tiles_K` in the `gemmini_mxquant_config_mvout` call.

```c
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_config_ld(MATMUL_K * sizeof(elem_t));
  #pragma GCC unroll 2
  for (int i = 0; i < tiles_I; i++)
    #pragma GCC unroll 2
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
  #pragma GCC unroll 2
  for (int j = 0; j < tiles_J; j++)
    #pragma GCC unroll 2
    for (int k = 0; k < tiles_K; k++)
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + j * DIM * MATMUL_K + k * DIM),
                            b_base + (j * tiles_K + k) * DIM, DIM, DIM);

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_K);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
  gemmini_fence();
}
```
