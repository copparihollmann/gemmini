An elegant and highly effective optimization plan to address the inefficiencies in the provided code is to apply **Strategy 4: Pre-transpose the weight matrix B offline in DRAM**.

### Inefficiency Analysis
In the original implementation, the weight matrix $B$ is stored in DRAM in its standard row-major layout of shape `[MATMUL_K][MATMUL_N]`. 
1. **Strided DRAM Accesses:** During execution, B tiles are loaded column-by-column along the $K$ dimension. This results in strided DRAM accesses with a large stride of `MATMUL_N` bytes, severely hurting DRAM burst efficiency and bandwidth utilization.
2. **Inefficient Scratchpad Writing:** Because B tiles are loaded individually, the compiler cannot coalesce the `mvin` instructions. This results in a massive number of individual DMA commands being issued, introducing significant control-flow overhead.

### Optimization Plan (Strategy 4)
1. **Offline Transposition:** At the start of the `solution` function, we will transpose $B$ offline in DRAM into a temporary buffer `B_transposed` of shape `[MATMUL_N][MATMUL_K]`.
2. **Contiguous DRAM Layout:** In the transposed matrix `B_transposed`, elements along the $K$ dimension for a fixed $N$ column (specifically, the inner loop dimension $k$) become completely contiguous in memory.
3. **Contiguous Scratchpad Layout:** In accordance with **Rule 12**, we lay out B tiles in the scratchpad at `b_base + (j * tiles_K + k) * DIM`. Under this layout, tiles along the $K$ dimension are stored contiguously in the scratchpad.
4. **Coalesced DMA Transfers:** Since both the DRAM source and the scratchpad destination are now contiguous along the $k$ dimension, we can merge multiple individual tile transfers into a single wide DMA transfer. Using `MAX_BLOCK_LEN = 4`, we can load up to 4 consecutive tiles (64 bytes) in a single `gemmini_extended_mvin` call, cutting the number of `mvin` instructions by $4\times$.
5. **Hardware Transpose Support:** Because the tiles loaded from `B_transposed` are transposed, we set the `B_transpose` hardware flag to `true` (or `1`) in both `gemmini_extended3_config_ex` and `gemmini_loop_ws_spad`. This offloads the tile transposition back to the systolic array's compute unit at zero latency cost.

#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"
#include "include/matmul_data_mx_lut_hw.h"

// Optimized MX matmul solution using offline B matrix transposition
void solution(void) {
  // Transpose B offline in DRAM to convert strided column-wise accesses into contiguous sequential streams
  static elem_t B_transposed[MATMUL_N][MATMUL_K] __attribute__((aligned(64)));
  for (int k = 0; k < MATMUL_K; k++) {
    for (int j = 0; j < MATMUL_N; j++) {
      B_transposed[j][k] = B_in[k][j];
    }
  }

  // Hoist invariant global configurations completely outside all loops
  // Set B_transpose (8th argument) to true (1)
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 1, false, 0, 0, 3, 0);

  for (int i0 = 0; i0 < BLOCKS_M; i0++) {
    // Partial last M block: compute only the real rows, pad the rest.
    int mrows = REAL_M - i0 * BLK; 
    if (mrows > BLK) mrows = BLK; 
    if (mrows <= 0) continue;

    // Hoist row-wise activation scales staging and loading out of the j0 loop
    for (int g = 0; g < MATMUL_K / 32; g++) {
      memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
    }
    gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);

    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      // Partial last N block: compute only the real cols, pad the rest.
      int ncols = REAL_N - j0 * BLK; 
      if (ncols > BLK) ncols = BLK; 
      if (ncols <= 0) continue;

      // Stage and load column-wise weight scales (B) for the current j0 block
      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);

      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      gemmini_flush(0);

      // MVIN A tiles directly from strided DRAM
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++) {
        for (int k = 0; k < tiles_K; k++) {
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
        }
      }

      // MVIN B tiles directly from the contiguous pre-transposed DRAM buffer.
      // Load up to MAX_BLOCK_LEN = 4 contiguous tiles at once to amortize DMA instructions.
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int j = 0; j < tiles; j++) {
        for (int k = 0; k < tiles_K; k += 4) {
          int k_len = (tiles_K - k >= 4) ? 4 : (tiles_K - k);
          gemmini_extended_mvin((void*)(((elem_t*)B_transposed) + (j0 * BLK + j * DIM) * MATMUL_K + k * DIM),
                                b_base + (j * tiles_K + k) * DIM, k_len * DIM, DIM);
        }
      }

      // Configure output store stride
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      
      // Configure requantizer bounds with correct parameters
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);

      // Fused hardware loop computation with B_transpose enabled (12th argument)
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, true, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      // Readout results from shared memory
      for (int r = 0; r < mrows; r++) {
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      }
      gemmini_fence();
    }
  }
}
