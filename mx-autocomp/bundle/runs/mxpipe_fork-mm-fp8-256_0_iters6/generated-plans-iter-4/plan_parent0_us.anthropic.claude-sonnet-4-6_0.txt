## Analysis of the Original Code

Looking at the original code, I can identify the key inefficiency related to strategy **5: increase `lut_update_granularity`**.

In the original code:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
```

The `lut_update_granularity` parameter is set to `1`, meaning the requantizer LUT refreshes after every single output tile. This is the most expensive setting — it triggers a LUT refresh for every one of the `tiles_I * tiles_J` output tiles produced by the fused `gemmini_loop_ws_spad` loop.

## Plan: Increase `lut_update_granularity`

**What to change:** Modify the `gemmini_mxquant_config_mvout` call to pass `tiles_I * tiles_J` as the `lut_update_granularity` argument instead of `1`.

**Why this is safe:** The `lut_update_granularity` parameter `G` controls how often the output LUT refreshes during the requantization post-pass. Since we are using FP8 (not FP6 with `uselut=1`), and a single set of scale factors covers the entire `tiles_I × tiles_J` output tile grid (all A and B scale factors are loaded once before compute), the LUT does not need to refresh between individual output tiles. Setting `G = tiles_I * tiles_J` means the LUT refreshes only once for the entire output, matching the scale block granularity.

**Why this reduces latency:** With `lut_update_granularity = 1`, the hardware performs `tiles_I * tiles_J` LUT refresh operations — one per output tile. With `lut_update_granularity = tiles_I * tiles_J`, it performs only 1 refresh for the entire computation, eliminating `(tiles_I * tiles_J - 1)` redundant refresh cycles inside the fused loop.

**Specific code change:**

Original:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
```

Replace with:
```c
gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_I * tiles_J);
```

No other changes are needed. The `gemmini_loop_ws_spad` call, the mvin loops, the scale loading, the config_ex, and the read_smem/fence all remain identical. This is a single-parameter change that reduces requantizer LUT refresh overhead without affecting correctness, since the same scale factors remain valid across all output tiles in this problem.

void solution(void) {

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

#ifdef SPIKE_SIM
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
#else
  load_scale_factors((volatile uint64_t *) GEMMINI_SF_MEM_A, (uint8_t *) &A_scales_row, MATMUL_M, MATMUL_K);
  load_scale_factors((volatile uint64_t *) GEMMINI_SF_MEM_B, (uint8_t *) &B_scales_col, MATMUL_N, MATMUL_K);
#endif

  // ---- MVIN A: tile (i,k) -> a_base + (i*tiles_K + k)*DIM ----
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));

  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      elem_t *dram_ptr = ((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM;
      uint32_t sp_addr = a_base + (i * tiles_K + k) * DIM;
      gemmini_extended_mvin((void *) dram_ptr, sp_addr, DIM, DIM);
    }
  }

  gemmini_config_ld(MATMUL_N * sizeof(elem_t));

  // ---- MVIN B: tile (k,j) -> b_base + (k*tiles_J + j)*DIM ----
  // Batch up to MAX_BLOCK_LEN=4 consecutive j-tiles per k-row using gemmini_block_mvin
  for (int k = 0; k < tiles_K; k++) {
    for (int j = 0; j < tiles_J; j += MAX_BLOCK_LEN) {
      int batch = (tiles_J - j < MAX_BLOCK_LEN) ? (tiles_J - j) : MAX_BLOCK_LEN;
      elem_t *dram_ptr = ((elem_t*)B_in) + k * DIM * MATMUL_N + j * DIM;
      uint32_t sp_addr = b_base + (k * tiles_J + j) * DIM;
      gemmini_block_mvin((void*)dram_ptr, sp_addr, batch);
    }
  }

  int SPAD_DEST = 0;

  gemmini_config_st(DIM * sizeof(elem_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, tiles_I * tiles_J);

  // ---- Compute ----
  gemmini_loop_ws_spad(
      tiles_I, tiles_J, tiles_K,
      0, 0, 0,
      a_base,
      BANK_NUM * BANK_ROWS,
      0,
      SPAD_DEST,
      false, false,
      false, false, false,
      NO_ACTIVATION,
      0, 0,
      false,
      0x38);

  gemmini_fence();

#ifdef SPIKE_SIM
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
#else
  printf("Moving out:\n");
  for (int i = 0; i < tiles_J*tiles_I*2; i++) {
      gemmini_mvout((void*)((uint64_t*) C_hw + i*2*DIM), SPAD_DEST + i*DIM);
  }
  gemmini_fence();
#endif

}
