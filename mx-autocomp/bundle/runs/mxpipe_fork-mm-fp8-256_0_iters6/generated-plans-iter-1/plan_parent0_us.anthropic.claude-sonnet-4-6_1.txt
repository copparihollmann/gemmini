# Optimization Plan: Strategy 11 — Split into I-Band Partitions for B-Tile Reuse

## Problem Analysis

Looking at the baseline code for `matmul_tiled_fp8_128x128x256` (MATMUL_M=128, MATMUL_N=128, MATMUL_K=256, so tiles_I=8, tiles_J=8, tiles_K=16):

**Current scratchpad usage:**
- All A tiles: `tiles_I * tiles_K * DIM = 8 * 16 * 16 = 2048 rows`
- All B tiles: `tiles_J * tiles_K * DIM = 8 * 16 * 16 = 2048 rows`
- Total: 4096 rows out of 8192 — only **50% utilized**

The hint confirms "Scratchpad utilization is 0KB out of 256KB" (the baseline code reports 0 because the `gemmini_loop_ws_spad` hardware loop manages scratchpad internally, but the total footprint still fits). With 4096 rows free, we can load **more I-tiles per call**, but actually the opposite insight is more valuable: all B tiles already fit, so we can process **multiple I-bands** while keeping **B resident** across them.

## Root Inefficiency

The current code loads all A tiles and all B tiles once, then calls `gemmini_loop_ws_spad` once. The `gemmini_loop_ws_spad` hardware loop already handles everything in one shot, so the issue is not repeated B loading — but the output side has a bottleneck: `tiles_I * tiles_J * DIM = 8 * 8 * 16 = 1024` accumulator rows needed, but `ACC_ROWS = 256`. This means **1024 > 256**, so the single call **overflows the accumulator**!

Actually re-reading: the accumulator constraint says `tiles_I*tiles_J*DIM ≤ 256`. With tiles_I=8, tiles_J=8, DIM=16: 8×8×16 = 1024 >> 256. The hardware loop must handle this internally by flushing, but this causes stalls. Splitting into I-bands of size `I_BAND` where `I_BAND * tiles_J * DIM ≤ 256` gives `I_BAND ≤ 256 / (8*16) = 2`.

## Strategy: Split Into I-Bands of 2, Keeping B Tiles Resident

**Core idea:** Process the 8 I-tiles in bands of `I_BAND=2`. For each band:
- Load only the 2 rows of A tiles (`2 * tiles_K * DIM = 2*16*16 = 512 rows`)
- B tiles (8*16*16 = 2048 rows) stay at b_base throughout — **loaded only once before all bands**
- Each `gemmini_loop_ws_spad(I_BAND, tiles_J, tiles_K, ...)` fits in the accumulator: `2*8*16 = 256 ≤ 256` ✓
- Scratchpad per band: `512 + 2048 = 2560 rows ≤ 8192` ✓

**Key changes:**

1. **Load all B tiles once** before the band loop (b_base fixed at top of scratchpad)
2. **Loop over I-bands**, loading only the current band's A tiles into `a_base` each iteration
3. **Call `gemmini_loop_ws_spad` with `I_BAND` I-tiles** per invocation
4. **Read smem** after each band call, writing the band's C rows to the correct `C_hw` slice
5. The `SPAD_DEST` offset can stay at 0, and `gemmini_mx_read_smem` reads `SPAD_DEST*16` with `I_BAND*MATMUL_N` BF16 values per band, writing to `&C_hw[band*I_BAND*DIM][0]`

**Why this improves performance:**
- Eliminates accumulator overflow/stall: each call fits exactly in 256 accumulator rows
- B tiles are DMA'd from DRAM only once (1/4 of previous B-load work if bands=4)
- Each `gemmini_loop_ws_spad` call processes a clean accumulator-fitting tile block, removing any internal flush overhead the hardware was doing silently
- `mvin2` port can be used for B loads while A loads use `mvin` port (complementary to this strategy)

## Concrete Code Changes

```c
void solution(void) {
  // tiles for full matrix
  const int tiles_I = MATMUL_M / DIM;   // 8
  const int tiles_J = MATMUL_N / DIM;   // 8
  const int tiles_K = MATMUL_K / DIM;   // 16

  // Band size: max I_BAND such that I_BAND * tiles_J * DIM <= ACC_ROWS=256
  // I_BAND = 256 / (tiles_J * DIM) = 256 / (8*16) = 2
  const int I_BAND = 256 / (tiles_J * DIM);  // = 2
  const int num_bands = tiles_I / I_BAND;     // = 4

  // Scratchpad layout:
  // B tiles at top: b_base = BANK_NUM*BANK_ROWS - tiles_K*tiles_J*DIM
  //                        = 8192 - 16*8*16 = 8192 - 2048 = 6144
  // A tiles (band): a_base = 0, uses I_BAND*tiles_K*DIM = 2*16*16 = 512 rows
  // No overlap: 512 < 6144 ✓
  const uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM; // 6144
  const uint32_t a_base = 0;
  const int SPAD_DEST = 128; // output destination in mx_smem

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
      1, 1, 0, 0, false, 0, 0, 3, 0);

#ifdef SPIKE_SIM
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
#else
  load_scale_factors((volatile uint64_t *)GEMMINI_SF_MEM_A,
                     (uint8_t *)&A_scales_row, MATMUL_M, MATMUL_K);
  load_scale_factors((volatile uint64_t *)GEMMINI_SF_MEM_B,
                     (uint8_t *)&B_scales_col, MATMUL_N, MATMUL_K);
#endif

  // ---- Load ALL B tiles once (resident for all I-bands) ----
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));
  for (int k = 0; k < tiles_K; k++) {
    for (int j = 0; j < tiles_J; j++) {
      elem_t *dram_ptr = ((elem_t*)B_in) + k * DIM * MATMUL_N + j * DIM;
      uint32_t sp_addr = b_base + (k * tiles_J + j) * DIM;
      gemmini_extended_mvin((void *)dram_ptr, sp_addr, DIM, DIM);
    }
  }

  // ---- Process I-bands: load A band, compute, read smem ----
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));

  for (int band = 0; band < num_bands; band++) {
    int i_start = band * I_BAND;

    // Load A tiles for this band only (I_BAND * tiles_K tiles)
    for (int i = 0; i < I_BAND; i++) {
      for (int k = 0; k < tiles_K; k++) {
        elem_t *dram_ptr = ((elem_t*)A_in)
            + (i_start + i) * DIM * MATMUL_K + k * DIM;
        uint32_t sp_addr = a_base + (i * tiles_K + k) * DIM;
        gemmini_extended_mvin((void *)dram_ptr, sp_addr, DIM, DIM);
      }
    }

    // Configure output: OUT_COLS = MATMUL_N/4 words per row
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors,
        I_BAND, tiles_J, tiles_K, 0, 0, 1);

    // Compute this band: I_BAND x tiles_J x tiles_K, fits in accumulator
    gemmini_loop_ws_spad(
        I_BAND, tiles_J, tiles_K,
        0, 0, 0,
        a_base,
        BANK_NUM * BANK_ROWS,  // b_base end address
        0,
        SPAD_DEST,
        false, false,
        false, false, false,
        NO_ACTIVATION,
        0, 0,
        false,
        0x38);

    // Read this band's BF16 results from smem to correct C_hw rows
#ifdef SPIKE_SIM
    gemmini_mx_read_smem(&C_hw[i_start * DIM][0],
                         SPAD_DEST * 16,
                         I_BAND * DIM * MATMUL_N);
#else
    uint64_t *smem_start = ((uint64_t*)SMEM) + SPAD_DEST * 2;
    for (int i = 0; i < I_BAND * DIM; i++) {
      for (int j = 0; j < OUT_COLS; j++) {
        C_hw[i_start * DIM + i][j] = *(smem_start + i * OUT_COLS + j);
      }
    }
#endif
    gemmini_fence();
  }
}
```

**Summary of improvements:**
- **Accumulator fit**: each band uses exactly 256 accumulator rows (no overflow stalls)
- **B-tile DRAM traffic cut by 4×**: loaded once instead of once per `gemmini_loop_ws_spad` invocation under any naive re-invocation scheme
- **Smaller A footprint per call**: 512 rows vs 2048, leaving headroom for future double-buffering
- **Clean pipeline**: each `gemmini_loop_ws_spad` starts with a fresh accumulator, no internal partial-flush overhead
