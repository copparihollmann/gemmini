## Selected Strategy: Strategy 13 — Restructure mvin loops to use separate ports and interleave A/B loading

## Plan

**The core change**: Use `gemmini_extended_mvin2` (port 1) for B tile loads instead of `gemmini_extended_mvin` (port 0). This allows A and B tile DMA transfers to proceed concurrently since they use independent ports. Additionally, configure both load ports upfront (A config via port 0, B config via port 1 using `gemmini_extended3_config_ld` with `id=1`), then issue all A mvins via `gemmini_extended_mvin` and all B mvins via `gemmini_extended_mvin2` in an interleaved fashion — issuing the A tile for row `i` immediately followed by the corresponding B tiles, so the systolic array's input buffers receive both operands as soon as possible and DMA bandwidth is shared across both ports simultaneously.

**Concrete steps**:

1. Configure load port 0 for A: `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0)` (id=0)
2. Configure load port 1 for B: `gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), SCALE_IDENTITY, false, 1)` (id=1)
3. Issue all A mvins via `gemmini_extended_mvin` (uses port 0)
4. Issue all B mvins via `gemmini_extended_mvin2` (uses port 1)

By configuring both ports once (outside all loops) and using dedicated ports for A vs B, the hardware's two independent DMA engines can service both streams without serialization. The `gemmini_config_ld` (which maps to `gemmini_extended3_config_ld(..., id=0)`) and the id=1 config are both issued before any mvin, eliminating the mid-sequence reconfiguration bubble that currently exists between the A mvin loop and the B mvin loop.
