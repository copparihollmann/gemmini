## Analysis

Looking at the original code, I need to identify which strategy applies best.

The current mvin phase loads A tiles using `gemmini_extended_mvin` (port 1) and B tiles also using `gemmini_extended_mvin` (port 1) in separate sequential loops. This means A and B DMA transfers are serialized — B loading only begins after all A tiles are loaded.

**Strategy 5** is directly applicable: interleave A and B mvin commands using both load ports simultaneously (`gemmini_extended_mvin` for A and `gemmini_extended_mvin2` for B), reducing total mvin latency by overlapping the two DMA streams.

## Plan

**Strategy: Interleave A and B mvin commands across both DMA ports**

### Changes:

1. **Merge the two separate mvin loops into a single combined loop** that issues A-tile loads (via `gemmini_extended_mvin`, port 1) and B-tile loads (via `gemmini_extended_mvin2`, port 2) in an interleaved fashion within the same loop body.

2. **Issue both `gemmini_config_ld` calls before the combined loop**, since each port has its own stride register: configure port 1 (A) with `gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), SCALE_IDENTITY, false, 0)` and port 2 (B) with `gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), SCALE_IDENTITY, false, 1)`. This sets the DRAM stride independently for each port.

3. **Structure the combined loop** over the outer iteration space. The A loop iterates over `(i, k_batch)` and the B loop iterates over `(k, j_batch)`. To interleave them, we iterate over the maximum of the two loop trip counts and issue whichever mvin commands are available at each step. Concretely: flatten both loops into linear indices and emit pairs of (mvin A, mvin2 B) commands, handling remainders at the end.

4. **Replace `gemmini_extended_mvin` with `gemmini_extended_mvin2`** for B tile loads throughout.

5. The combined loop will look like:
   - Compute total A commands: `tiles_I * ceil(tiles_K / MAX_BLOCK_LEN)`
   - Compute total B commands: `tiles_K * ceil(tiles_J / MAX_BLOCK_LEN)`
   - Iterate up to `max(total_A, total_B)` steps, at each step emitting one A mvin and one B mvin2 (if the respective index is still valid), so both DMA engines are kept busy simultaneously rather than sequentially.

This is semantically equivalent because the hardware tracks data hazards internally — the compute (`gemmini_loop_ws_spad`) will only start consuming tiles once they are available in the scratchpad, and the order of loading A vs B does not affect correctness. The benefit is that the two DMA ports operate in parallel, cutting the effective mvin phase duration roughly in half.
