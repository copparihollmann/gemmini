## Analysis

Looking at the original code, I can identify that the inner mvin loops contain repeated integer multiply operations:

- For A: `i * tiles_K + k` computed every iteration
- For B: `k * tiles_J + j` computed every iteration

These multiplications happen inside hot loops and are redundant — they can be replaced with incremental additions. Strategy **9** (pre-compute all scratchpad addresses into a flat lookup table) directly addresses this.

## Plan: Pre-compute Scratchpad Addresses (Strategy 9)

### What to change

**Before the mvin loops**, build two flat arrays:
- `sp_addr_A[tiles_I][ceil(tiles_K/MAX_BLOCK_LEN)]` — one entry per (i, k-batch) pair
- `sp_addr_B[tiles_K][ceil(tiles_J/MAX_BLOCK_LEN)]` — one entry per (k, j-batch) pair

These are computed once using integer multiplies **outside** the loops. Inside the hot mvin loops, replace `a_base + (i * tiles_K + k) * DIM` and `b_base + (k * tiles_J + j) * DIM` with a simple array lookup (or equivalently, use an incrementing counter that avoids the multiply entirely).

### Specific changes

1. Before the A mvin loop, initialize `uint32_t sp_a = a_base` and increment by `DIM` each inner iteration (since A tiles along K are laid out contiguously at stride `DIM` rows). The outer loop resets: `sp_a = a_base + i * tiles_K * DIM` — but even this can be avoided by maintaining a separate `row_base` that increments by `tiles_K * DIM` each i-step.

2. Before the B mvin loop, initialize `uint32_t sp_b = b_base` and increment by `DIM` each inner iteration. Since the j-batch loop steps through contiguous B tiles, no multiply is needed inside the loop — just `sp_b += batch * DIM` per j-batch step, and `sp_b` resets at the start of each k by keeping a `k_base = b_base + k * tiles_J * DIM` that increments by `tiles_J * DIM` each k-step.

3. Similarly, the DRAM pointer arithmetic can be replaced with pointer increments: `dram_ptr_A` advances by `batch * DIM * sizeof(elem_t)` per j/k step and by `DIM * MATMUL_K * sizeof(elem_t)` per i step; `dram_ptr_B` advances by `batch * DIM * sizeof(elem_t)` per j-batch step and by `DIM * MATMUL_N * sizeof(elem_t)` per k step.

This eliminates all integer multiplications from the hot inner loops, replacing them with additions only.

## Rewritten Code

```c
void solution(void) {

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

#ifdef SPIKE_SIM
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
#else
  load_scale_factors((volatile uint64_t *) GEMMINI_SF_MEM_A, (uint8_t *) &A_scales_row, MATMUL_M, MATMUL_K);
  load_scale_factors((volatile uint64_t *) GEMMINI_SF_MEM_B, (uint8_t *) &B_scales_col, MATMUL_N, MATMUL_K);
#endif

  // ---- MVIN A ----
  // Pre-eliminate multiplies: track spad and dram addresses with
  // incremental additions only inside the hot loops.
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));

  {
    // a_row_sp advances by tiles_K*DIM each i step
    // a_row_dram advances by DIM*MATMUL_K bytes each i step
    uint32_t a_row_sp   = a_base;
    elem_t  *a_row_dram = (elem_t*)A_in;

    for (int i = 0; i < tiles_I; i++) {
      uint32_t sp_addr    = a_row_sp;
      elem_t  *dram_ptr   = a_row_dram;

      for (int k = 0; k < tiles_K; k += MAX_BLOCK_LEN) {
        int batch = (tiles_K - k < MAX_BLOCK_LEN) ? (tiles_K - k) : MAX_BLOCK_LEN;
        gemmini_extended_mvin((void *) dram_ptr, sp_addr, batch * DIM, DIM);
        sp_addr  += (uint32_t)(batch * DIM);
        dram_ptr += batch * DIM;
      }

      a_row_sp   += (uint32_t)(tiles_K * DIM);
      a_row_dram += DIM * MATMUL_K;
    }
  }

  // ---- MVIN B ----
  // Pre-eliminate multiplies: track spad and dram addresses with
  // incremental additions only inside the hot loops.
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));

  {
    // b_k_sp advances by tiles_J*DIM each k step
    // b_k_dram advances by DIM*MATMUL_N bytes each k step
    uint32_t b_k_sp   = b_base;
    elem_t  *b_k_dram = (elem_t*)B_in;

    for (int k = 0; k < tiles_K; k++) {
      uint32_t sp_addr  = b_k_sp;
      elem_t  *dram_ptr = b_k_dram;

      for (int j = 0; j < tiles_J; j += MAX_BLOCK_LEN) {
        int batch = (tiles_J - j < MAX_BLOCK_LEN) ? (tiles_J - j) : MAX_BLOCK_LEN;
        gemmini_extended_mvin((void *) dram_ptr, sp_addr, batch * DIM, DIM);
        sp_addr  += (uint32_t)(batch * DIM);
        dram_ptr += batch * DIM;
      }

      b_k_sp   += (uint32_t)(tiles_J * DIM);
      b_k_dram += DIM * MATMUL_N;
    }
  }

  int SPAD_DEST = 0;

  gemmini_config_st(DIM * sizeof(elem_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // ---- Compute ----
  gemmini_loop_ws_spad(
      tiles_I, tiles_J, tiles_K,
      0, 0, 0,
      a_base,
      BANK_NUM * BANK_ROWS,
      0,
      SPAD_DEST,
      false, false,
      false, false, false,
      NO_ACTIVATION,
      0, 0,
      false,
      0x38);

  gemmini_fence();

#ifdef SPIKE_SIM
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, MATMUL_M * MATMUL_N);
#else
  printf("Moving out:\n");
  for (int i = 0; i < tiles_J*tiles_I*2; i++) {
      gemmini_mvout((void*)((uint64_t*) C_hw + i*2*DIM), SPAD_DEST + i*DIM);
  }
  gemmini_fence();
#endif

}
```
