## Analysis

Looking at the code, I can identify the key bottleneck: **there are two `gemmini_flush(0)` calls per tile iteration** — one before the Q@K^T matmul and one before the P@V matmul. `gemmini_flush` is a heavy drain operation that stalls until all in-flight instructions complete. Between these two matmuls, there's also CPU-side softmax computation (no Gemmini dependency). The second flush before P@V is unnecessarily heavyweight — a `gemmini_fence()` would suffice since the only dependency is ensuring the previous `gemmini_mx_read_smem` has completed before we re-configure for the next matmul.

**Strategy 10** directly addresses this: *eliminate the per-tile `gemmini_flush(0)` calls between the two matmuls within a tile by replacing them with targeted `gemmini_fence()` only where true RAW dependencies exist.*

## Plan

**The first `gemmini_flush(0)` at the start of the tile loop** (before Q@K^T) can be moved out of the loop entirely — flush once before the loop begins, since there's nothing in-flight at that point. After that, a simple `gemmini_fence()` at the end of each matmul block (already present via `gemmini_mx_read_smem` + fence) is sufficient to ensure correctness.

**The second `gemmini_flush(0)` inside the tile loop** (before P@V) is the expensive one. By the time we reach the P@V matmul, the CPU has already executed:
1. `gemmini_mx_read_smem(&S1_hw[0][0], ...)` — drains the Q@K^T result
2. `gemmini_fence()` — full barrier ensuring S1_hw is visible
3. The entire integer softmax loop (CPU-only work, no Gemmini overlap)

After `gemmini_fence()` completes, the Gemmini pipeline is already drained. The subsequent `gemmini_flush(0)` before P@V is therefore redundant — it flushes an already-idle pipeline. Replace it with nothing (or at most a `gemmini_fence()` which is a no-op on an already-drained pipeline but maintains correctness semantics).

**Concretely:**
- Move the single `gemmini_flush(0)` to before the `for (int t = 0; t < N_TILES; t++)` loop (outside it).
- Remove the second `gemmini_flush(0)` inside the loop (before P@V) entirely, since `gemmini_fence()` from the prior block already ensures a clean state.
- Keep all `gemmini_fence()` calls in place.

This eliminates `2*N_TILES` flush operations and replaces them with 1 flush + the already-existing fences, reducing synchronization overhead proportionally to the number of tiles.

```c
// AUTO-GENERATED FLASH attention baseline (S=128, D=64, tile=64).
void solution(void) {
  // ---- flash attention: tile K/V along sequence, online softmax ----
  for (int i = 0; i < ATT_S; i++) { M_run[i] = -((int64_t)1 << 62); L_run[i] = 0; }
  memset(O_acc, 0, ATT_S * ATT_D * sizeof(int64_t));

  // Single flush before the entire tile loop: Gemmini is idle at this point.
  gemmini_flush(0);

  for (int t = 0; t < N_TILES; t++) {
    // 1) scores tile S1 = Q @ K_t^T   [S x BT] on Gemmini
    {
      int tiles_I = ATT_S / DIM, tiles_J = BT / DIM, tiles_K = ATT_D / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
      int SPAD_DEST = 128;
      // gemmini_flush(0) removed: moved outside loop; pipeline already clean
      // on first iteration (flush above), and on subsequent iterations
      // gemmini_fence() at end of P@V block below has already drained it.
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)&Q_scales_row, sizeof(Q_scales_row), 0);
      static uint8_t KT_sc_tile[(ATT_D / 32) * BT];
      for (int sg = 0; sg < ATT_D / 32; sg++)
        for (int sn = 0; sn < BT; sn++)
          KT_sc_tile[sg * BT + sn] = KT_scales_col[sg][t * BT + sn];
      gemmini_mx_load_scales((uint64_t)KT_sc_tile, (ATT_D / 32) * BT, 1);
      gemmini_config_ld(ATT_D * sizeof(elem_t));
      for (int i = 0; i < tiles_I; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)Q_in) + i * DIM * ATT_D + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(ATT_S * sizeof(elem_t));
      for (int j = 0; j < tiles_J; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)KT_in) + (k * DIM) * ATT_S + t * BT + j * DIM),
                                b_base + (k * tiles_J + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      gemmini_mx_read_smem(&S1_hw[0][0], SPAD_DEST * 16, ATT_S * BT);
      gemmini_fence();
    }

    // 2) FLOAT-FREE integer online softmax update + fp8 requant of P_t
    for (int i = 0; i < ATT_S; i++) {
      int64_t q[BT];
      int64_t m_new = M_run[i];
      for (int j = 0; j < BT; j++) {
        int64_t qq = mx_ibf16_to_q((uint16_t)((S1_hw[i][j / 4] >> ((j % 4) * 16)) & 0xFFFF));
        q[j] = qq; if (qq > m_new) m_new = qq;
      }
      int64_t corr = mx_iexp(M_run[i] - m_new);
      int64_t p[BT];
      int64_t st = 0;
      for (int j = 0; j < BT; j++) { int64_t pv = mx_iexp(q[j] - m_new); p[j] = pv; st += pv; }
      L_run[i] = (L_run[i] * corr) / MX_IEXP0 + st;
      for (int d = 0; d < ATT_D; d++) O_acc[i][d] = (O_acc[i][d] * corr) / MX_IEXP0;
      M_run[i] = m_new;
      for (int g = 0; g < GROUPS_BT; g++) {
        int64_t gmax = 0;
        for (int j = g * 32; j < (g + 1) * 32; j++) if (p[j] > gmax) gmax = p[j];
        int eg = (gmax > 0) ? (mx_ilog2((uint64_t)gmax) - MX_P_TARGET_LOG2) : 0;
        P_s[g][i] = (uint8_t)(eg + 127);
        for (int j = g * 32; j < (g + 1) * 32; j++) P_q[i][j] = mx_enc_unnorm(p[j], eg);
      }
    }

    // 3) O_tile = P_t @ V_t  [S x D] on Gemmini; accumulate in fp32
    {
      int tiles_I = ATT_S / DIM, tiles_J = ATT_D / DIM, tiles_K = BT / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
      int SPAD_DEST = 128;
      // gemmini_flush(0) removed: gemmini_fence() at end of Q@K^T block above
      // has already fully drained the Gemmini pipeline. The CPU-side softmax
      // loop further guarantees no in-flight Gemmini work remains.
      // A targeted gemmini_fence() would be a no-op here; no call needed.
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)P_s, GROUPS_BT * ATT_S, 0);
      gemmini_mx_load_scales((uint64_t)&V_scales_col[t * GROUPS_BT][0], GROUPS_BT * ATT_D, 1);
      gemmini_config_ld(BT * sizeof(elem_t));
      for (int i = 0; i < tiles_I; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)P_q) + i * DIM * BT + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(ATT_D * sizeof(elem_t));
      for (int j = 0; j < tiles_J; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)V_in) + (t * BT + k * DIM) * ATT_D + j * DIM),
                                b_base + (k * tiles_J + j) * DIM, DIM, DIM);
      gemmini_config_st(D_OUT_COLS * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      gemmini_mx_read_smem(&O_hw[0][0], SPAD_DEST * 16, ATT_S * ATT_D);
      gemmini_fence();
      for (int i = 0; i < ATT_S; i++)
        for (int d = 0; d < ATT_D; d++) {
          uint16_t b = (uint16_t)((O_hw[i][d / 4] >> ((d % 4) * 16)) & 0xFFFF);
          O_acc[i][d] += mx_bf16_to_fx(b, MX_O_F);
        }
    }
  }

  // final normalization by the online denominator
  for (int i = 0; i < ATT_S; i++) {
    int64_t l = L_run[i]; if (l == 0) l = 1;
    for (int d = 0; d < ATT_D; d++) O_acc[i][d] = O_acc[i][d] / l;
  }
}
```
