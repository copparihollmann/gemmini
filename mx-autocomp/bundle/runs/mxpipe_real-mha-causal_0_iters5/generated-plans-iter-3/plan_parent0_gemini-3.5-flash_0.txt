An elegant and highly effective hardware-specific optimization strategy to reduce execution time—separate from software pipelining, bank conflict avoidance, loop reordering, and CPU division elimination—is to **Maximize the DMA Block Transfer Length (`MAX_BLOCK_LEN = 4`) for all Scratchpad Loads (`mvin`).**

---

### Strategy: Maximize Scratchpad Load Block Length

#### 1. Why It Improves Performance
In the original baseline implementation, the inputs (such as $Q$, $K^T$, $P$, and $V$) are loaded into the scratchpad in sub-optimal chunks of 2 tiles (`bb = 2` blocks of size `DIM=16` columns) along their contiguous dimensions:
```c
for (int k = 0; k < tiles_K; k += 2) { 
  int bb = (tiles_K - k < 2) ? (tiles_K - k) : 2;
  gemmini_extended_mvin(..., bb * DIM, DIM); 
}
```
However, Gemmini's DMA hardware controller supports a maximum block transfer length (`MAX_BLOCK_LEN`) of **4** contiguous tiles in a single transaction before it must fragment the operation. 

By increasing the inner loop step and block factor to `4` (since $M, N, K = 64$ implies $\text{tiles\_I, tiles\_J, tiles\_K} = 4$), we double the DMA transfer block size from 32 columns to the hardware maximum of 64 columns (`4 * DIM`). This yields several microarchitectural benefits:
1. **Halves Instruction Issue Overhead:** The RISC-V host CPU issues exactly half as many RoCC `mvin` instructions to the Gemmini command queue, freeing up valuable CPU cycles during the non-compute phase.
2. **Minimizes DMA Setup Latency:** Every individual DMA command incurs startup handshake overhead in the bus interconnect. Merging two 32-byte transfers into one 64-byte transaction significantly amortizes this latency.
3. **Improves Bus Utilization:** Loading 64 bytes sequentially aligns perfectly with standard cache-line-sized memory bursts, maximizing DRAM read and scratchpad write bandwidth.

---

### How to Modify the Code

Modify the inner loops of both Gemmini execution blocks (Step 1 and Step 3) to load tiles in strides of `4` instead of `2`:

#### A. Step 1: $S1 = Q \times K^T$ Scratchpad Loading
```c
// Change step size from 2 to 4 to load up to 4 tiles (64 bytes) contiguously
for (int i = 0; i < tiles_I; i++) {
  for (int k = 0; k < tiles_K; k += 4) { 
    int bb = (tiles_K - k < 4) ? (tiles_K - k) : 4;
    gemmini_extended_mvin((void*)(((elem_t*)Q_in) + i * DIM * ATT_D + k * DIM),
                          a_base + (i * tiles_K + k) * DIM, bb * DIM, DIM); 
  }
}

for (int k = 0; k < tiles_K; k++) {
  for (int j = 0; j < tiles_J; j += 4) { 
    int bb = (tiles_J - j < 4) ? (tiles_J - j) : 4;
    gemmini_extended_mvin((void*)(((elem_t*)KT_in) + (k * DIM) * ATT_S + j * DIM),
                          b_base + (k * tiles_J + j) * DIM, bb * DIM, DIM); 
  }
}
```

#### B. Step 3: $O = P \times V$ Scratchpad Loading

// Apply same consolidation to the softmax outputs and Value matrices
