### Optimization Plan: Exploiting RISC-V Bitmanip (Zbb) for `mx_ilog2`

#### 1. Inefficiency Analysis
In the provided MHA kernel, the host CPU performs integer-only softmax and $P$-matrix quantization on $64 \times 64 = 4096$ elements per head. Because this is executed entirely on the RISC-V host CPU, any overhead in scalar utility functions directly bottlenecks the entire execution. 

Specifically, the `mx_ilog2` helper function is invoked multiple times per row:
* Once to calculate `ls = mx_ilog2(sm)` for the row-sum.
* Once per group $g$ to compute the exponent adjustment: `mx_ilog2(gmax)`.

In a standard software implementation, `mx_ilog2` uses a loop that repeatedly shifts the input right until it becomes zero, which takes $O(b)$ steps (where $b$ is the position of the MSB). Across 4 heads and 64 rows, `mx_ilog2` is called $4 \times 64 \times (1 + \text{GROUPS\_S}) = 768$ times. Eliminating this loop overhead will significantly reduce CPU clock cycles.

#### 2. Optimization Strategy
We will replace the sequential software loop in `mx_ilog2` with a hardware-accelerated version using the RISC-V Bitmanipulation (Zbb) extension instruction `clz` (Count Leading Zeros). 

For any non-zero 64-bit unsigned integer $x$, the position of its highest set bit (which is equivalent to $\lfloor\log_2(x)\rfloor$) can be computed in a single clock cycle using:
$$\text{ilog2}(x) = 63 - \text{clz}(x)$$

By using the GCC compiler builtin `__builtin_clzll` (Count Leading Zeros, 64-bit), the compiler will lower this operation directly to a single `clz` instruction (when compiling with `-march` targeting Zbb) or a highly optimized branchless bit-hack sequence if Zbb is unavailable.

#### 3. How to Implement the Changes

1. **Redefine `mx_ilog2`**:
   Define `mx_ilog2` using `__builtin_clzll` and mark it with `__attribute__((always_inline))` to eliminate function-call overhead.
   ```c
   static inline int mx_ilog2(uint64_t x) __attribute__((always_inline));
   static inline int mx_ilog2(uint64_t x) {
     if (x == 0) return 0;
     return 63 - __builtin_clzll(x);
   }
   ```

2. **Preserve Kernel Structure**:
   Keep the rest of the host-side integer softmax loop, Gemmini instructions, configurations, and the `solution` function signature exactly the same. Because `mx_ilog2` now executes in $O(1)$ time without branches, the overall host execution latency will drop dramatically while maintaining bit-exact numerical correctness.
