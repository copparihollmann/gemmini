### Inefficiency Analysis
In the baseline implementation, the execution flow for each head $h$ is strictly sequential:
1. **Gemmini** computes $S1 = Q \times K^T$.
2. **Gemmini** transfers the results to DRAM via `gemmini_mx_read_smem`.
3. **Host CPU** blocks at `gemmini_fence()`, waiting for Gemmini to finish.
4. **Host CPU** computes the integer softmax and FP8 requantization (which is highly compute-intensive and runs entirely on the scalar RISC-V core). During this entire time, Gemmini is completely idle.
5. **Gemmini** computes $O = P \times V$ and transfers output.
6. **Host CPU** blocks again at `gemmini_fence()`, leaving Gemmini idle.

This lock-step execution wastes substantial hardware execution time on both sides. Since all attention heads are independent, we can overlap the CPU softmax of head $h$ with Gemmini computations of other heads.

---

### Optimization Plan: Inter-Head Pipelining

We will restructure the program flow to overlap the CPU-bound softmax execution with Gemmini's execution. To do this safely without data corruption, we introduce a double-buffered intermediate buffer for the $S1$ matmul output.

#### 1. Double-Buffering the Intermediate Output
We define a double-buffered local or static array for $S1$:
```c
static out_t S1_hw_db[2][ATT_S][S_OUT_COLS];
```
This allows Gemmini to write the results of $S1$ for head $h+1$ into one buffer while the CPU is concurrently reading and processing the $S1$ results of head $h$ from the other buffer.

#### 2. Pipeline Structure
- **Prologue (Before Loop):** Queue Matmul 1 ($S1$) for head 0 into `S1_hw_db[0]`.
- **Main Loop ($h = 0 \dots H-1$):**
  1. Issue a single `gemmini_fence()` at the start of the iteration. This ensures that $S1$ for head $h$ is fully computed and transferred, and that the previous Gemmini computations are finished before we overwrite `P_q`/`P_scales`.
  2. Compute Softmax and FP8 Requantization on the CPU for head $h$ using `S1_hw_db[h % 2]`, producing `P_q` and `P_scales`.
  3. Queue Matmul 2 ($O = P \times V$) for head $h$ on Gemmini.
  4. Queue Matmul 1 ($S1$) for head $h+1$ on Gemmini into `S1_hw_db[(h+1) % 2]` (if $h+1 < H$).
- **Epilogue (After Loop):** Issue a final `gemmini_fence()` to ensure that the last head's Matmul 2 has finished writing to `O_hw[H-1]` before returning.

This hides the CPU softmax processing latency behind the Gemmini execution of Matmul 2 (head $h$) and Matmul 1 (head $h+1$), keeping the systolic array fed with back-to-back tiles.
