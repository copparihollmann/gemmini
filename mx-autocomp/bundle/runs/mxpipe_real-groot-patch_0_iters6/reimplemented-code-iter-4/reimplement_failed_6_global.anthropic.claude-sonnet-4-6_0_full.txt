Looking at the failing code, I need to identify the bugs:

1. **B tile mvin layout is wrong**: The B tile index should be `b_base + (j*tiles_K + k)*DIM` (matching the documented layout), but the code uses `b_base + (k*tiles + j)*DIM`. The B layout in the docs is `b_base + (j*tiles_K + k)*DIM`.

2. **gemmini_mx_load_scales sel convention**: sel=0 is A (activation), sel=1 is B (weight) — this looks correct in the code already.

3. **scale_factors**: The `gemmini_mxquant_config_mvout` is called with `scale_factors` but the scales loaded are from `A_s` and `B_s` staging buffers. The scale_dram address in mxquant_config_mvout refers to the output quantization scale memory, which should point to the staged scale data properly.

4. **gemmini_flush** placement: Should be done once before the entire loop, not inside the inner loop (causes stale state reset).

5. **mvin2 for B**: B tiles should use `gemmini_extended_mvin2` (mvin2 port) while A uses `gemmini_extended_mvin`.

6. **C_hw read smem offset**: The `/ BF16_PER_WORD` division may be incorrect for byte addressing.
