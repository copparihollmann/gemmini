## Analysis of the Current Code

Looking at the innermost mvin loops, the A-tile mvin loop contains:

```c
for (int i = 0; i < tiles; i++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                          a_base + (i * tiles_K + k) * DIM, DIM, DIM);
```

Each iteration computes `(i0 * BLK + i * DIM) * MATMUL_K + k * DIM` — a multiply-heavy expression with three multiplications per call: `i0*BLK`, `i*DIM`, the product with `MATMUL_K`, and `k*DIM`. Similarly for B:

```c
for (int j = 0; j < tiles; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                          b_base + (k * tiles + j) * DIM, DIM, DIM);
```

This recomputes `k * DIM * MATMUL_N` and `j0*BLK + j*DIM` on every inner iteration.

## Selected Strategy: #5 — Use Direct Pointer Arithmetic with Running Pointer

### Plan

**For A tiles (outer `i`, inner `k`):**
- Before the `i`-loop, compute `elem_t *a_row_base = ((elem_t*)A_in) + i0 * BLK * MATMUL_K`.
- At the start of each `i`-iteration, set `elem_t *a_ptr = a_row_base + i * DIM * MATMUL_K`. This replaces `(i0*BLK + i*DIM)*MATMUL_K`.
- Inside the `k`-loop, start with `a_ptr` and after each iteration increment it by `DIM` (one FP8 tile column along K). The spad address `a_base + (i*tiles_K + k)*DIM` similarly becomes a running variable initialized to `a_base + i*tiles_K*DIM` and incremented by `DIM` each `k`-step.

**For B tiles (outer `j`, inner `k`):**
- Before the `j`-loop, compute `elem_t *b_col_base = ((elem_t*)B_in) + j0 * BLK`.
- At the start of each `j`-iteration, set `elem_t *b_ptr = b_col_base + j * DIM`. This gives the starting column offset.
- Inside the `k`-loop, instead of recomputing `k * DIM * MATMUL_N`, maintain a running pointer incremented by `DIM * MATMUL_N` each `k`-step. The spad address `b_base + (k*tiles + j)*DIM` becomes a running variable initialized to `b_base + j*DIM` and incremented by `tiles*DIM` each `k`-step.

**For spad addresses:** Both `a_spad` and `b_spad` running variables replace the multiply-based index expressions with additions of fixed strides (`DIM` for A, `tiles*DIM` for B).

This eliminates all integer multiplications inside the `k`-loop body for both A and B mvins, converting them to pointer additions and integer additions — cheaper operations that reduce the command-issue overhead in the innermost loop, which executes `tiles * tiles_K` times per `(i0, j0)` block.
