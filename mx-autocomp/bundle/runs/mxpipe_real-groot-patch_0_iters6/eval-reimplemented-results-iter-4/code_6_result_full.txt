1. **B scales are loaded once per `j0`**, reused across all `i0` — requires inverting the loop order to `j0` outer, `i0` inner.
2. **A scales are memcpy'd and loaded once per `(i0, j0)` pair** — but since A scales don't change with `j0`, we can load A scales once per `i0` into `A_s`, then re-issue `gemmini_mx_load_scales` for A at the start of each `j0` inner iteration (which is cheap because the `memcpy` is eliminated — `A_s` is already populated for this `i0`).

### Why This Improves Performance

The profiler comment says *"Host staging is typically the dominant cost"* and identifies `memcpy` calls.
