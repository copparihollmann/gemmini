## Analysis

Looking at the original code, the key inefficiency targeted by **strategy 4** is:

- The outer loop is `i0` outer / `j0` inner (or `i0` outer, `j0` inner as written)
- Actually re-reading: the loop is `i0` outer / `j0` inner
- For each `(i0, j0)` pair, **B tiles are loaded fresh from DRAM** — even though for a fixed `j0`, the same B block is needed for every `i0` iteration
- By swapping to **`j0` outer / `i0` inner**, the B block for a given `j0` can be loaded once and reused across all `i0` iterations (all M-blocks), amortizing the B mvin cost over the entire M dimension

### Scratchpad Capacity Check

With `BLK = 32` (tiles=2), `tiles_K = 512/16 = 32`:
- B tiles: `tiles_J * tiles_K * DIM = 2 * 32 * 16 = 1024` rows
- A tiles: `tiles_I * tiles_K * DIM = 2 * 32 * 16 = 1024` rows  
- Total: 2048 rows ≤ 8192 ✓ — B fits while we reload A each i0

### Plan: Reorder to j0-outer / i0-inner, hoist B mvin outside i0 loop

1. Make `j0` the outer loop and `i0` the inner loop
2. Before the `i0` loop: load B scales and mvin all B tiles for this `j0` block (once)
3. Inside the `i0` loop: load A scales, mvin A tiles, configure mvout, compute, readout
4. B's `b_base` stays the same formula; since B doesn't change across i0, no re-mvin needed
5. Scale loading: B scales loaded once per j0; A scales loaded once per i0 — but since `gemmini_mx_load_scales` must precede `gemmini_loop_ws_spad` and both A and B must be loaded before compute, we load A scales inside i0 loop and B scales outside (before i0 loop), then call `gemmini_loop_ws_spad` inside i0. This satisfies the ordering constraint since B scales persist until overwritten.

```c
void solution(void) {
  gemmini_flush(0);  // hoisted outside all loops (strategy 3 bonus, but required for strategy 4 restructuring)

  int tiles   = BLK / DIM;
  int tiles_K = MATMUL_K / DIM;
  uint32_t a_base = 0;
  uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
  int SPAD_DEST   = 128;

  // j0 outer: B block is fixed for all i0 — load B once per j0
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    int ncols = REAL_N - j0 * BLK;
    if (ncols > BLK) ncols = BLK;
    if (ncols <= 0) continue;

    // Stage B scales for this j0 block (once, amortized over all i0)
    for (int g = 0; g < MATMUL_K / 32; g++)
      memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);

    // Load B tiles into scratchpad once for all i0 iterations
    gemmini_config_ld(MATMUL_N * sizeof(elem_t));
    for (int j = 0; j < tiles; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin2(
          (void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
          b_base + (k * tiles + j) * DIM, DIM, DIM);

    // i0 inner: A changes each iteration, B stays resident
    for (int i0 = 0; i0 < BLOCKS_M; i0++) {
      int mrows = REAL_M - i0 * BLK;
      if (mrows > BLK) mrows = BLK;
      if (mrows <= 0) continue;

      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      // Stage A scales for this i0 block
      for (int g = 0; g < MATMUL_K / 32; g++)
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);

      // Programming model sequence: config_ex → load_scales (A, B) → mvin → config_mvout → loop_ws_spad
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
                                  1, 1, 0, 0, false, 0, 0, 3, 0);

      // Both A and B scales must be loaded before loop_ws_spad
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);  // B_s already staged above

      // Load A tiles for this i0
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
            a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors,
                                   tiles, tiles, tiles_K, 0, 0, 1);

      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0,
                           a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST,
                           false, false, false, false, false,
                           NO_ACTIVATION, 0, 0, false, 0x38);

      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
  }
}
```

**Key changes:**
- `gemmini_flush(0)` hoisted before all loops (called once, not per tile)
- Loop order inverted: `j0` is now outer, `i0` is inner
- B tile `mvin` (via `mvin2` to use the dedicated B port) and B scale staging moved outside the `i0` loop — executed once per `j0` block
- A tile `mvin` and A scale staging remain inside `i0` loop
- `gemmini_mx_load_scales` for B still called inside `i0` loop (required by programming model ordering before each `gemmini_loop_ws_spad`), but `B_s` buffer is already populated from the outer j0 staging — this satisfies the ordering constraint with only the cheap SRAM→accelerator transfer repeated, not the memcpy from DRAM scales
- B mvin cost is now amortized over `BLOCKS_M` iterations instead of paid per iteration
