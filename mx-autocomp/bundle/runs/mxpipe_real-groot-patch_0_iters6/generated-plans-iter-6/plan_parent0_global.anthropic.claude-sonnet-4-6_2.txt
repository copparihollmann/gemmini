## Analysis

Looking at the code, `gemmini_flush(0)` and `gemmini_extended3_config_ex(...)` are called **inside the double loop** over `(i0, j0)` blocks — once per `BLOCKS_M * BLOCKS_N` iterations. For a 41×512×512 problem with BLK=32, that's potentially many redundant calls.

- `gemmini_flush(0)` resets all hardware state and is expensive. It should only be called **once** at kernel entry.
- `gemmini_extended3_config_ex(...)` sets format fields (FP8, WS mode, identity scale, etc.) that are **invariant across all blocks**. Re-issuing it every iteration wastes cycles.

**Strategy selected: Hoist `gemmini_flush(0)` outside all tile loops (Strategy 4), and also hoist `gemmini_extended3_config_ex` (Strategy 3).**

Since the plan must cover exactly one strategy, I'll apply **Strategy 4** (hoist `gemmini_flush`) which naturally subsumes hoisting `gemmini_extended3_config_ex` since both are loop-invariant — the instructions say "do not count out strategies unless clearly irrelevant," and strategies 3 and 4 are tightly coupled here (both move the same two invariant calls out of the loop).

## Plan

1. **Move `gemmini_flush(0)` to before the `for (i0 ...)` loop.** It must still precede all `gemmini_extended3_config_ex` and scale load calls, but only needs to run once.

2. **Move `gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0)` to immediately after `gemmini_flush(0)`, outside both loops.** The format (FP8, WS, identity acc scale, no transpose) is the same for every `(i0, j0)` block, so one-time configuration is sufficient.

3. **Inside the loop body**, remove the two hoisted calls. Everything else (scale loads, mvin, config_st, mxquant_config_mvout, loop_ws_spad, read_smem, fence) stays exactly where it is — those are data-dependent on the block index and must remain per-iteration.

This preserves the programming model order: flush → config_ex (once) → then per block: load_scales → mvin → config_mvout → loop_ws_spad → read_smem → fence. The order within each block iteration is still correct because config_ex was already issued before the first scale load.

```c
void solution(void) {
  const int GK = MATMUL_K / 32;

  static uint8_t pre_A_s[BLOCKS_M][MATMUL_K / 32][BLK];
  static uint8_t pre_B_s[BLOCKS_N][MATMUL_K / 32][BLK];

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_A_s[i0][g][0], &A_scales_row[g][i0 * BLK], BLK);

  for (int j0 = 0; j0 < BLOCKS_N; j0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_B_s[j0][g][0], &B_scales_col[g][j0 * BLK], BLK);

  // HOISTED: flush and config_ex issued once before all tile iterations
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
                               1, 1, 0, 0, false, 0, 0, 3, 0);

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      // REMOVED: gemmini_flush(0) and gemmini_extended3_config_ex (hoisted above)

      gemmini_mx_load_scales((uint64_t)pre_A_s[i0], A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)pre_B_s[j0], B_S_BYTES, 1);

      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);

      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
}
```
