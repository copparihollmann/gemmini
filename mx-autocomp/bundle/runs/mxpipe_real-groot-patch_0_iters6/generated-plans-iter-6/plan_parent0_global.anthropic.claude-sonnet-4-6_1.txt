## Analysis

The current code has `gemmini_flush(0)` inside the `i0/j0` loop, and more importantly, it calls `gemmini_mx_load_scales` every `(i0, j0)` iteration with **pre-staged contiguous arrays** — but it still does a one-time `memcpy` restride into `pre_A_s`/`pre_B_s` before the loop. The feedback says:

- Scratchpad utilization: 0KB/256KB — tiles are tiny relative to capacity
- The dominant cost is data movement (2 memcpy calls for the pre-staging)

## Strategy Selection: Strategy 3 — Weight-Stationary Reuse Across I Tiles

Currently the loop is `for i0: for j0:` — A scales are reloaded for every `(i0, j0)` pair. B tiles and B scales are also reloaded for every `(i0, j0)` pair.

**Key insight:** In weight-stationary mode, B (weights) are fixed. If we load all B tiles for a given `j0` once and reuse them across all `i0` iterations, we eliminate `BLOCKS_M - 1` redundant B mvin + B scale-load operations per `j0`.

The strategy is to **swap the loop order to `for j0: for i0:`**, load B tiles + B scales once per `j0`, and reuse them across all `i0` iterations. A tiles + A scales are loaded once per `(j0, i0)` pair (which is correct since A changes with `i0`).

However, the scratchpad must hold A + B simultaneously. Currently with `tiles = BLK/DIM` tiles per dimension:
- A: `tiles * tiles_K * DIM` rows  
- B: `tiles * tiles_K * DIM` rows  
- Total: `2 * tiles * tiles_K * DIM` rows

With `BLK=64`, `tiles=4`, `tiles_K=32`: `2 * 4 * 32 * 16 = 4096` rows ≤ 8192 ✓

This fits, so we can keep all B tiles in the scratchpad across all `i0` iterations within a `j0` block.

Additionally, eliminate the `pre_A_s`/`pre_B_s` memcpy pre-staging by loading A and B scales directly with proper stride — but the scales need contiguous layout for `gemmini_mx_load_scales`. Instead, we eliminate the pre-staging of B entirely by reusing B scales (loaded once per `j0`) across all `i0`.

The pre-staging memcpy for A cannot be avoided (strided source), but pre-staging B can be amortized: load `pre_B_s[j0]` once per `j0` outer iteration instead of once per `(i0, j0)`.

## Plan

1. **Swap loop order** to `for j0: for i0:` 
2. **Move B-related operations outside the `i0` loop:** `gemmini_mx_load_scales` for B and `gemmini_extended_mvin` for B tiles are issued once per `j0`, not once per `(i0, j0)`
3. **Move `gemmini_flush` and `gemmini_extended3_config_ex`** outside both loops (issued once total at the start)
4. **Move `pre_B_s` pre-staging** so it is still done once per `j0` (unchanged in count), but B mvin is not repeated per `i0`
5. **A mvin and A scale load** remain inside the `i0` loop (A changes per row block)
6. The `gemmini_mxquant_config_mvout` + `gemmini_loop_ws_spad` + `gemmini_mx_read_smem` + `gemmini_fence` sequence remains inside `i0` (one compute per `(i0,j0)` pair, as required since C changes)
7. The programming model sequence per compute invocation remains: config_ex (already set) → load_scales A (per i0) — but B scales were loaded at `j0` level; we must reload A scales before each `loop_ws_spad`. Since B scales persist from `j0`-level load, we only call `gemmini_mx_load_scales` for A inside `i0`.

Wait — per rule 15: scales must be loaded before each `gemmini_loop_ws_spad`. B scales loaded at `j0` level are still valid for all subsequent `i0` invocations (same B block, same scales). A scales must be reloaded per `i0`. This is correct.

The programming model sequence per `(i0, j0)` compute call becomes:
- B loaded (mvin + scale) at `j0` level (once)
- Per `i0`: load A scales → mvin A → config_mvout → loop_ws_spad → read_smem → fence ✓

This reduces total `gemmini_mx_load_scales(B)` calls from `BLOCKS_M * BLOCKS_N` to `BLOCKS_N`, and total B mvin instructions from `BLOCKS_M * BLOCKS_N * tiles * tiles_K` to `BLOCKS_N * tiles * tiles_K`. With `BLOCKS_M = ceil(41/64) = 1` and `BLOCKS_N = ceil(512/64) = 8`, the savings are modest for this problem size, but the structure is correct for larger M.

More impactfully: **eliminate `gemmini_flush` from inside the loop** — it was called `BLOCKS_M * BLOCKS_N` times, flushing the pipeline every iteration. Move it outside.

```c
// AUTO-GENERATED outer-tiled MX matmul baseline (41x512x512).
void solution(void) {
  const int GK = MATMUL_K / 32;

  static uint8_t pre_A_s[BLOCKS_M][MATMUL_K / 32][BLK];
  static uint8_t pre_B_s[BLOCKS_N][MATMUL_K / 32][BLK];
  static uint32_t scale_factors[512] = {0};

  // Pre-stage A scales once
  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_A_s[i0][g][0], &A_scales_row[g][i0 * BLK], BLK);

  // Pre-stage B scales once
  for (int j0 = 0; j0 < BLOCKS_N; j0++)
    for (int g = 0; g < GK; g++)
      memcpy(&pre_B_s[j0][g][0], &B_scales_col[g][j0 * BLK], BLK);

  int tiles   = BLK / DIM;
  int tiles_K = MATMUL_K / DIM;
  uint32_t a_base   = 0;
  uint32_t b_base   = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
  int      SPAD_DEST = 128;

  // Flush and configure ONCE outside all loops
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY,
                               1, 1, 0, 0, false, 0, 0, 3, 0);

  // Outer loop: j0 (weight/column block) — B tiles loaded once per j0
  for (int j0 = 0; j0 < BLOCKS_N; j0++) {
    int ncols = REAL_N - j0 * BLK;
    if (ncols > BLK) ncols = BLK;
    if (ncols <= 0) continue;
    int pad_j = BLK - ncols;

    // Load B scale factors once for this j0 block (reused across all i0)
    gemmini_mx_load_scales((uint64_t)pre_B_s[j0], B_S_BYTES, 1);

    // MVIN B tiles once for this j0 block into fixed top-of-scratchpad region
    gemmini_config_ld(MATMUL_N * sizeof(elem_t));
    for (int j = 0; j < tiles; j++)
      for (int k = 0; k < tiles_K; k++)
        gemmini_extended_mvin(
          (void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
          b_base + (k * tiles + j) * DIM, DIM, DIM);

    // Inner loop: i0 (activation/row block) — A tiles loaded per i0
    for (int i0 = 0; i0 < BLOCKS_M; i0++) {
      int mrows = REAL_M - i0 * BLK;
      if (mrows > BLK) mrows = BLK;
      if (mrows <= 0) continue;
      int pad_i = BLK - mrows;

      // Load A scale factors for this i0 block
      gemmini_mx_load_scales((uint64_t)pre_A_s[i0], A_S_BYTES, 0);

      // MVIN A tiles for this i0 block
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin(
            (void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
            a_base + (i * tiles_K + k) * DIM, DIM, DIM);

      // Configure output and run compute
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0,
                           a_base, BANK_NUM * BANK_ROWS, 0, SPAD_DEST,
                           false, false, false, false, false,
                           NO_ACTIVATION, 0, 0, false, 0x38);

      // Read results back from shared memory
      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
  }
}
```

**Key changes:**
- `gemmini_flush` + `gemmini_extended3_config_ex` moved outside both loops (called once instead of `BLOCKS_M * BLOCKS_N` times)
- Loop order swapped to `j0` outer, `i0` inner
- B mvin and B `gemmini_mx_load_scales` moved to the `j0` level (called `BLOCKS_N` times instead of `BLOCKS_M * BLOCKS_N` times)
- A mvin and A `gemmini_mx_load_scales` remain inside `i0` (correct — A changes per row block)
- Programming model ordering per compute call is preserved: A scales loaded → A tiles mvin'd → B already in spad and scales already loaded → config_mvout → loop_ws_spad → read_smem → fence ✓
- B tiles remain in their fixed `b_base` region across `i0` iterations (weight-stationary reuse)
- `gemmini_config_ld` for B is also moved outside the `i0` loop (stride for B doesn't change across `i0`)
