The im2col matrix `A_buf[MATMUL_M][MATMUL_K]` maps:
- Row `pi * PATCHES_X + pj` → patch at position `(pi, pj)`
- Column `c * CONV_KSZ * CONV_KSZ + dy * CONV_KSZ + dx` → channel `c`, kernel offset `(dy, dx)`

Each row of `A_buf` (one patch) is built from `CONV_C * CONV_KSZ * CONV_KSZ` elements drawn from `X_in`. For a given patch `(pi, pj)` and offset `(c, dy, dx)`, the source is `X_in[c][pi*CONV_KSZ + dy][pj*CONV_KSZ + dx]`.

### Key observation for direct mvin

The K dimension (columns of A) is structured as `(c, dy, dx)` where `dx` is the innermost index. For a fixed `(pi, pj, c, dy)`, the `dx` values form a **contiguous row segment** in `X_in[c][pi*CONV_KSZ + dy][pj*CONV_KSZ + 0..CONV_KSZ-1]`. This means consecutive `dx` elements are stride-1 in memory — perfect for a DMA transfer.

The DIM×DIM tile in the scratchpad covers 16 rows (patches) × 16 columns (K elements). The stride for mvin should match the width of `X_in` in memory: `CONV_H * sizeof(elem_t)` bytes per row (since `X_in[c]` is a `CONV_H × CONV_H` image, row-major).

## Final Plan: Strategy 12 — Eliminate im2col via Direct Mvin

With `CONV_KSZ=4, CONV_C=2, CONV_H=32, PATCHES_X=8, DIM=16, MATMUL_K=32, tiles_K=2`:

- K-tile `k=0` → channel 0 elements, K-tile `k=1` → channel 1 elements
- For K-tile `k`, I-tile `i`: 16 rows (patches), each row from patch `p = i*16 + r` (r=0..15)
