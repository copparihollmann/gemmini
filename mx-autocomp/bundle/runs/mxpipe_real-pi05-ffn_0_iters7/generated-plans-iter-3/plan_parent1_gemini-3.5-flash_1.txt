An elegant and highly effective optimization strategy to improve the performance of your MX-Gemmini kernel is **Strategy 6: reorder I/J/K loop nest to maximize weight-stationary B-tile reuse across I iterations**.

### Inefficiency in the Current Code
In the current implementation, the outer block loop iterates over activations ($M$-blocks via `i0`), and the inner block loop iterates over weights ($N$-blocks via `j0`). This configuration results in the following performance bottlenecks:
1. **Redundant Weight DMA Loads**: For every single activation block `i0`, the entire set of weight tiles $B$ must be re-loaded from DRAM into the scratchpad. Weight tiles are thus loaded $BLOCKS\_M \times BLOCKS\_N$ times.
2. **Redundant Scale Loading**: Weight scale factors (`B_scales_col`) are similarly re-loaded via `gemmini_mx_load_scales` in the inner loop, creating high MMIO configuration and DMA transaction overhead.

### Optimization Plan

We will restructure the block loop nest to hoist the weight-stationary $B$ tiles and their scale factors to the outermost loop level.

1. **Reorder the Loops**:
   Move the $N$-block loop (`j0`) to the outer level and the $M$-block loop (`i0`) to the inner level.
   
2. **Hoist $B$ (Weight) Memory Operations**:
   - Load the dynamic $B$ scale factors (`B_scales_perf`) once per outer `j0` iteration.
   - Load the dynamic $B$ tiles into the upper half of the scratchpad (`b_base`) once per outer `j0` iteration.

3. **Keep $A$ (Activation) and Output Operations in the Inner Loop**:
   - Inside the inner `i0` loop, load the $A$ scale factors (`A_scales_perf`) and the $A$ tiles into the lower half of the scratchpad (`a_base`).
   - Run the fused hardware loop `gemmini_loop_ws_spad` using the already resident stationary $B$ tiles and the freshly loaded $A$ tiles.
   - Drain the results from the MX shared memory back to the DRAM output buffer $C\_hw$ and synchronize with `gemmini_fence()`.

This reordering reduces the total number of weight $B$ DRAM transfers and scale-factor loads by a factor of $BLOCKS\_M$, substantially decreasing DRAM bandwidth bottlenecking and maximizing PE utilization.
