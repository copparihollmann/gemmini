## Analysis of the Original Code

The original code loads all A tiles, then all B tiles in **separate sequential loops**:

```c
// First loop: all A tiles
for (int i = 0; i < tiles_I; i++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin(...A..., a_base + (i*tiles_K + k)*DIM, DIM, DIM);

// Second loop: all B tiles  
for (int j = 0; j < tiles_J; j++)
  for (int k = 0; k < tiles_K; k++)
    gemmini_extended_mvin(...B..., b_base + (j*tiles_K + k)*DIM, DIM, DIM);
```

This means the DMA engine must finish **all A loads** before it can begin any B loads. The two load streams are fully serialized, leaving the second DMA port idle throughout the entire mvin phase.

## Selected Strategy: #11 — Interleave A-tile and B-tile mvins in a single merged loop

### Plan

The key insight is that `gemmini_extended_mvin` (port 0) and `gemmini_extended_mvin2` (port 1) are **independent DMA channels**. By issuing them in alternating pairs within a single merged loop, both ports can pipeline their respective loads simultaneously, roughly halving the memory-load phase duration.

**Concrete changes:**

1. **Merge the two separate nested loops into one merged loop** that iterates over a combined index space. For this 64×64×64 problem: `tiles_I = tiles_J = tiles_K = 4`. The A-tile loop has `tiles_I * tiles_K = 16` iterations and the B-tile loop has `tiles_J * tiles_K = 16` iterations — both have equal trip counts.

2. **In the merged loop**, use a single loop index `t` from 0 to `tiles_I*tiles_K - 1` (= 15), and within each iteration:
   - Decompose `t` into `(i, k) = (t / tiles_K, t % tiles_K)` for the A tile
   - Decompose `t` into `(j, k) = (t / tiles_K, t % tiles_K)` for the B tile (same index mapping since `tiles_I == tiles_J`)
   - Issue `gemmini_extended_mvin(A_dram_ptr, a_spad_addr, DIM, DIM)` using port 0
   - Issue `gemmini_extended_mvin2(B_dram_ptr, b_spad_addr, DIM, DIM)` using port 1

3. **Keep the same `gemmini_config_ld` call** with stride `MATMUL_K * sizeof(elem_t)` before the merged loop (both A and B share the same stride since `MATMUL_K == MATMUL_M == MATMUL_N = 64` and `sizeof(elem_t) = 1`).

4. All other steps (config_ex, load_scales, config_st, mxquant_config_mvout, loop_ws_spad, mx_read_smem, fence) remain **unchanged**.

5. The scratchpad layout invariants are preserved: A tiles land at `a_base + (i*tiles_K + k)*DIM` and B tiles land at `b_base + (j*tiles_K + k)*DIM`, exactly as before. No addressing rules are violated.

This interleaving allows the hardware DMA engine to overlap the DRAM→scratchpad transfers for A and B, pipelining both streams in parallel instead of sequentially, which should reduce total mvin latency by approximately 50%.
