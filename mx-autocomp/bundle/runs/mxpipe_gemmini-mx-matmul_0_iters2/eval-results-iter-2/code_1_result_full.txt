The hardware has three independent mvin ports (`gemmini_extended_mvin`, `gemmini_extended_mvin2`, `gemmini_extended_mvin3`), which can overlap A and B loads concurrently.

**Strategy 12: Restructure the A and B mvin loops into a single fused loop that interleaves A and B tile loads (for each k, load one A tile via mvin and one B tile via mvin2) to maximize DMA pipeline utilization.**

## Plan

The key insight is that the current code issues all A mvins (tiles_I × tiles_K = 4×4 = 16 commands), waits implicitly for those to drain, then issues all B mvins (tiles_J × tiles_K = 4×4 = 16 commands). Since A and B tiles are independent, they can be loaded concurrently by using separate mvin ports.

**Specific changes:**

1. Replace the two separate nested loops with a single fused loop over `k` (the K dimension), which interleaves A and B tile loads:
   - For each `k`, loop over `i` to issue A tile loads via `gemmini_extended_mvin` 
   - For the same `k`, loop over `j` to issue B tile loads via `gemmini_extended_mvin2`
   
2. This interleaves mvin (port 0) for A tiles and mvin2 (port 1) for B tiles at the same `k` index, allowing the DMA hardware to pipeline both loads simultaneously rather than serializing them.

3. The `gemmini_config_ld` call configures the stride for mvin port 0 (A). Since we're using `gemmini_extended_mvin2` for B tiles with the same stride (`MATMUL_K * sizeof(elem_t)`), we need to ensure the stride is also correct for mvin2. In the reference, `gemmini_config_ld` configures the default for all mvin ports, so a single `gemmini_config_ld(MATMUL_K * sizeof(elem_t))` before the fused loop covers both.

4. The scratchpad addresses remain identical: A at `a_base + (i*tiles_K + k)*DIM`, B at `b_base + (j*tiles_K + k)*DIM`. No layout changes needed.

The restructured loop looks like:
```c
gemmini_config_ld(MATMUL_K * sizeof(elem_t));
for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++) {
        elem_t *a_ptr = ((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM;
        uint32_t a_sp = a_base + (i * tiles_K + k) * DIM;
        gemmini_extended_mvin((void*)a_ptr, a_sp, DIM, DIM);

    }
}

This allows the hardware to overlap A and B DMA transfers for each K-slice, reducing total load latency.
