Looking at the error "max retries reached", the issue is likely with the B tile layout. The original code uses `b_base + (k * tiles_J + j) * DIM` but the architecture spec says B tiles should be laid out as `b_base + (j * tiles_K + k) * DIM`. Let me fix this and ensure all other aspects are correct.

Key issues to fix:
1. B tile address indexing: should be `b_base + (j * tiles_K + k) * DIM` not `b_base + (k * tiles_J + j) * DIM`
2. The scratchpad/accumulator sizes in the rules differ from the summary (rules say 256KB spad, 64KB acc vs summary's 128KB/32KB) - I'll use rules values but keep DIM=16, BANK_NUM=4, BANK_ROWS=2048 as specified in rule 7.

  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // MVIN A tiles into scratchpad using port 0
  for (int i = 0; i < tiles_I; i++)
    for (int k = 0; k < tiles_K; k++)

        (void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
        a_base + (i * tiles_K + k) * DIM,
        DIM, DIM);

  // Configure mvin port 1 for B (stride = full N row in bytes)
  gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // B layout: b_base + (j * tiles_K + k) * DIM  (spec-correct ordering)

        (void*)(((elem_t*)B_in) + k * DIM * MATMUL_N + j * DIM),
        b_base + (j * tiles_K + k) * DIM,

  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0,
