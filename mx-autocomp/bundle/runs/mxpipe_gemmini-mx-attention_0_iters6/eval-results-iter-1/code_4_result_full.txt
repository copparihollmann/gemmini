Looking at the profiled code, the dominant cost is **step 2: the CPU-side integer softmax loop**. The original code has a structural inefficiency in how it unpacks and processes the BF16 output from step 1:

**Current structure:**

3. **Third pass** for scale/encode — reads back `p[4][ATT_S]` per group.

With `ATT_S` large, `q[4][ATT_S]` and `p[4][ATT_S]` are large stack allocations of `int64_t`. For example if `ATT_S = 128`, that is `4 × 128 × 8 = 4096` bytes per array, `8 KB` total on the stack. ### The Strategy: Merge the iexp+sum Pass Into the Unpack+Max Pass Using a Two-Pass Algorithm

The key insight is that computing softmax requires knowing the row maximum before computing exponentials — but we can **eliminate the intermediate `q[][]` storage entirely** by doing two passes directly over the *packed BF16 words in `S1_hw`* rather than over an unpacked `int64_t` buffer.

**Proposed structure:**
1. **Pass 1** over `S1_hw[i][j/4]` — unpack BF16 words, compute row maxima `mq[4]`. **Do not store `q[][]`.**
2. **Pass 2** over `S1_hw[i][j/4]` — re-unpack BF16 words, compute `mx_iexp(val - mq[r])` on the fly, accumulate `sm[r]`, and compute scale/encode **directly per group** without storing `p[][]`.

This eliminates the `p[4][ATT_S]` array entirely and replaces the `q[4][ATT_S]` array with nothing (we re-read from `S1_hw` which is already in L1/L2 because it was just written and is much smaller in uint64 packing: `ATT_S × ATT_S / 4` bytes vs `4 × ATT_S × 8` bytes per 4-row batch).

### Why This Reduces Latency

- **Eliminated one large intermediate buffer**: `q[4][ATT_S]` of `int64_t` is replaced by re-reading the already-cached packed `S1_hw` words. Since `S1_hw` stores 4 BF16 values per `uint64_t`, it is `4×` more compact than the unpacked `int64_t` array, fitting better in cache.
- **Eliminated `p[4][ATT_S]`**: The per-group max and encode loop that read back `p[]` now runs inline during pass 2, so we never materialize `p[]` to memory at all.
- **Pass 2 combines iexp, sum, group-max, and encode** in one sweep: for each group `g` in pass 2, we can compute `iexp` values, track the group max, accumulate the sum, and after finishing the group call `mx_ienc_fp8` — all without a third pass.
- **Reduced stack pressure**: Eliminating two `4 × ATT_S` arrays of `int64_t` from the stack reduces register spills and cache pressure.

      int64_t ev3 = mx_iexp(mx_ibf16_to_q((uint16_t)((w3 >> shift) & 0xFFFF)) - mq[3]);

      exp_buf[g][0][jloc] = ev0;
      exp_buf[g][1][jloc] = ev1;
      exp_buf[g][2][jloc] = ev2;
      exp_buf[g][3][jloc] = ev3;

      sm[0] += ev0; sm[1] += ev1; sm[2] += ev2; sm[3] += ev3;

      if (ev0 > gmax_exp[g][0]) gmax_exp[g][0] = ev0;
      if (ev1 > gmax_exp[g][1]) gmax_exp[g][1] = ev1;
      if (ev2 > gmax_exp[g][2]) gmax_exp[g][2] = ev2;
      if (ev3 > gmax_exp[g][3]) gmax_exp[g][3] = ev3;
    }

    // Compute log2 + reciprocal for 4 rows
    for (int r = 0; r < 4; r++) {
      ls[r] = mx_ilog2((uint64_t)sm[r]);
      inv_sm[r] = (((uint64_t)1 << (ls[r] + MX_FRAC)) + ((uint64_t)sm[r] >> 1)) / (uint64_t)sm[r];
    }

    // --- Encode pass: per group, per row, using buffered exp values ---
    // exp_buf[g][r][0..31] is hot in L1 (32 * 4 * 8 = 1024 bytes per group)
    for (int g = 0; g < GROUPS_S; g++) {
      int jstart = g * 32;
      for (int r = 0; r < 4; r++) {
        int row = i + r;
        int64_t gmax = gmax_exp[g][r];
        if (gmax == 0) {
          P_scales[g][row] = 0;
          for (int jloc = 0; jloc < 32; jloc++)
            P_q[row][jstart + jloc] = 0;
          continue;
        }
        int e = mx_ilog2((uint64_t)gmax) - ls[r] - MX_P_TARGET_LOG2;
        P_scales[g][row] = (uint8_t)(e + 127);
        for (int jloc = 0; jloc < 32; jloc++)
          P_q[row][jstart + jloc] = mx_ienc_fp8(exp_buf[g][r][jloc], inv_sm[r], ls[r], e);
      }
    }
  }

  // ---- 3) O = P @ V on Gemmini (bf16 out) ----
  {
    int tiles_I = ATT_S / DIM, tiles_J = ATT_D / DIM, tiles_K = ATT_S / DIM;
    uint32_t a_base = 0;
    uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM;
    gemmini_flush(0);
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
    gemmini_mx_load_scales((uint64_t)&P_scales, sizeof(P_scales), 0);
    gemmini_mx_load_scales((uint64_t)&V_scales_col, sizeof(V_scales_col), 1);
    gemmini_config_ld(ATT_S * sizeof(elem_t));
    for (int i = 0; i < tiles_I; i++)
      for (int k = 0; k < tiles_K; k += 2) {
        int bb = (tiles_K - k < 2) ? (tiles_K - k) : 2;
        gemmini_extended_mvin((void*)(((elem_t*)P_q) + i * DIM * ATT_S + k * DIM),
                              a_base + (i * tiles_K + k) * DIM, bb * DIM, DIM);
      }
    gemmini_config_ld(ATT_D * sizeof(elem_t));
    for (int k = 0; k < tiles_K; k++)
      for (int j = 0; j < tiles_J; j += 2) {
        int bb = (tiles_J - j < 2) ? (tiles_J - j) : 2;
        gemmini_extended_mvin((void*)(((elem_t*)V_in) + (k * DIM) * ATT_D + j * DIM),
                              b_base + (k * tiles_J + j) * DIM, bb * DIM, DIM);
      }
    gemmini_config_st(D_OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
    gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                         SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&O_hw[0][0], SPAD_DEST * 16, ATT_S * ATT_D);
    gemmini_fence();
  }
