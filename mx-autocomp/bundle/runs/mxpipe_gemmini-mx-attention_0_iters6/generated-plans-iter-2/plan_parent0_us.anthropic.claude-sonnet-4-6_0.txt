## Actual Plan: Apply Strategy 2 — Increase Batch Size to 2 Consistently

The current code already attempts batch=2 but uses a complex `bb` clamping inline. The actual bottleneck is that when tile counts are odd, some mvins fall back to batch=1. More importantly, in the **O kernel**, `tiles_J = ATT_D / DIM` for B and `tiles_K = ATT_S / DIM` for A — depending on ATT_D and ATT_S, these may already be even.
