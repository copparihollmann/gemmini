An elegant and highly effective optimization strategy to improve performance is **Dual-Port DMA Parallelism with Load Controller Striding**.

### Strategy Explanation

In the baseline implementation, both matrix A and matrix B are loaded into the scratchpad sequentially using the same `gemmini_extended_mvin` instruction (which uses the default load controller `id=0`). This creates two severe performance bottlenecks:
1. **Serialization of Data Movement**: Since both matrices use the same DMA port, the hardware cannot overlap the loading of A and B. The memory transfer of B cannot start until the transfer of A is completely finished.
2. **Redundant Configuration Overhead**: The host CPU must repeatedly reconfigure the DMA stride (`gemmini_config_ld`) between `MATMUL_K` and `MATMUL_N` because the same load controller is shared.

**Our Optimization**: 
We configure two separate hardware load controllers: `id=0` for matrix A (stride `MATMUL_K`) and `id=1` for matrix B (stride `MATMUL_N`). We then load matrix A using `gemmini_extended_mvin` (port 0) and matrix B using `gemmini_extended_mvin2` (port 1). 

Furthermore, we restructure the loops to use `k` as the outermost loop. In each step, we interleave the loading of the $k$-th column of A tiles with the $k$-th row of B tiles. This maximizes the utilization of both hardware DMA engines simultaneously and completely eliminates all redundant stride reconfiguration instructions.

### Optimized Code

```c
// Optimized MX matmul kernel (32x256x256, fp8:e4m3).
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // Configure load controller 0 for Matrix A (stride K) and controller 1 for Matrix B (stride N)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // Interleave the loads of A and B using separate DMA engines (mvin and mvin2)
  for (int k = 0; k < tiles_K; k++) {
    for (int i = 0; i < tiles_I; i++) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
    for (int j = 0; j < tiles_J; j++) {
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + j * DIM),
                             b_base + (k * tiles_J + j) * DIM, DIM, DIM);
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

  // Read only the REAL rows (smem row stride is the padded MATMUL_N)
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
```
