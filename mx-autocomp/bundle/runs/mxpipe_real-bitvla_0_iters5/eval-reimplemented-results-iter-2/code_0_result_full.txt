We will apply **Strategy 2: Eliminate redundant computation/instructions** by batching the Memory-In (`mvin`) operations for both matrices $A$ and $B$. 

In the baseline implementation, each $16 \times 16$ tile of $A$ and $B$ is loaded using an individual `gemmini_extended_mvin` instruction. Because the hardware supports loading up to `MAX_BLOCK_LEN = 4` consecutive tiles along the contiguous dimension in a single DMA transfer, loading tiles individually incurs significant instruction-issue and DMA-setup overhead.

Since the layout of both matrices is contiguous along the horizontal tile dimension (increasing $k$ for $A$, and increasing $j$ for $B$):
1. We can group up to 4 consecutive $A$ tiles along the $K$ dimension and load them in a single `mvin` call.
2. We can reorder the $B$ loading loops to make $j$ the inner loop, grouping up to 4 consecutive $B$ tiles along the $N$ dimension and loading them in a single `mvin` call.

This optimization reduces the total number of `mvin` instructions by up to 4x, eliminating redundant command overhead on the host-accelerator interface.
