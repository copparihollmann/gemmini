### Optimization Plan

The host CPU serves as the controller that issues non-blocking RoCC instructions to Gemmini's queue. When we have nested loops with small, statically determinable bounds like `tiles_I = 2`, `tiles_J = 16`, and `tiles_K = 16`, the host CPU spends a significant fraction of its cycles managing loop branch overhead, incrementing induction variables, and performing dynamic index/address arithmetic.

We will eliminate this host-CPU overhead by:
1. **Fully unrolling the A tile loading loop**: Since `tiles_I = 2` and `tiles_K = 16`, we can write out all 32 `gemmini_extended_mvin` commands sequentially. This completely eliminates both loops, branch instructions, and dynamic address calculation overhead.
2. **Fully unrolling the inner loop of the B tile loading**: For loading B tiles, we keep the outer loop over `j` (from `0` to `15`) but completely unroll the inner loop over `k` (from `0` to `15`). This eliminates 15 out of 16 branch instructions per outer iteration and allows the compiler to optimize the address calculations into compile-time constant offsets.
