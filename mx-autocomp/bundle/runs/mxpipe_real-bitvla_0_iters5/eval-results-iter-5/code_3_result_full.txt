Plan: An elegant and highly effective optimization strategy for reducing the execution latency of Gemmini kernels running on RISC-V hosts (such as Spike simulations) is **Pointer-increment induction in host loops** (Strategy 5). 

### Analysis of Inefficiencies in the Baseline Code
In the baseline implementation, the host CPU executes nested loops to issue `gemmini_extended_mvin` instructions for matrices A and B. In each iteration, the DRAM source address and the scratchpad destination address are computed using multi-dimensional index multiplications:
- **For Matrix A:** `((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM` and `a_base + (i * tiles_K + k) * DIM`
- **For Matrix B:** `((elem_t*)B_in) + (k * DIM) * MATMUL_N + j * DIM` and `b_base + (k * tiles_J + j) * DIM`

These calculations involve multiple integer multiplications, additions, and shifts per iteration. Because the RISC-V host CPU issues RoCC instructions sequentially, these host-side scalar arithmetic operations create a bottleneck, leaving the hardware systolic array underutilized while waiting for the next instruction.

### Optimization Plan
We will eliminate all multi-dimensional index multiplications inside the `mvin` loops by replacing them with simple, sequential pointer additions. Since the DRAM memory layout and scratchpad layouts are contiguous along the inner loop dimensions, we can track the addresses with scalar accumulator registers:
1. **Matrix A Pointer Induction:**
   - Track the row-start pointer in DRAM (`a_dram_ptr_row`) and scratchpad (`a_sp_addr_row`).
   - For each tile row `i`, initialize the active pointers (`a_dram_ptr` and `a_sp_addr`).
   - In the inner `k` loop, increment both pointers by `DIM` (which is $16$ elements/addresses) per iteration.
   - At the end of the outer loop `i`, increment `a_dram_ptr_row` by `DIM * MATMUL_K` and `a_sp_addr_row` by `tiles_K * DIM`.

2. **Matrix B Pointer Induction:**
   - Track the column-start pointer in DRAM (`b_dram_ptr_col`).
   - For each tile column `j`, initialize the active pointers `b_dram_ptr` to `b_dram_ptr_col` and `b_sp_addr` to `b_base + j * DIM`.
   - In the inner `k` loop, increment `b_dram_ptr` by `DIM * MATMUL_N` and `b_sp_addr` by `tiles_J * DIM` to jump to the next block-row in memory.
   - At the end of the outer loop `j`, increment `b_dram_ptr_col` by `DIM`.

This completely removes scalar multiplication from the critical path of instruction dispatch, dramatically reducing CPU scalar overhead.

// Optimized MX matmul kernel (32x256x256, fp8:e4m3).
void solution(void) {
  // 1. Configure execution format
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  
  // 2. Load scale factors
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. MVIN A: DRAM -> Scratchpad with pointer-increment induction
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K
  elem_t *a_dram_ptr_row = (elem_t*)A_in;
  uint32_t a_sp_addr_row = a_base;
  
  for (int i = 0; i < tiles_I; i++) {
    elem_t *a_dram_ptr = a_dram_ptr_row;
    uint32_t a_sp_addr = a_sp_addr_row;
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin((void*)a_dram_ptr, a_sp_addr, DIM, DIM);
      a_dram_ptr += DIM;
      a_sp_addr += DIM;
    }
    a_dram_ptr_row += DIM * MATMUL_K;
    a_sp_addr_row += tiles_K * DIM;
  }

  // 4. MVIN B: DRAM -> Scratchpad with pointer-increment induction
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
  elem_t *b_dram_ptr_col = (elem_t*)B_in;
  
  for (int j = 0; j < tiles_J; j++) {
    elem_t *b_dram_ptr = b_dram_ptr_col;
    uint32_t b_sp_addr = b_base + j * DIM;
    for (int k = 0; k < tiles_K; k++) {
      gemmini_extended_mvin((void*)b_dram_ptr, b_sp_addr, DIM, DIM);
      b_dram_ptr += DIM * MATMUL_N;
      b_sp_addr += tiles_J * DIM;
    }
    b_dram_ptr_col += DIM;
  }

  // 5. Configure store and requantizer
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  
  // 6. Fused compute loop
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  
  // 7. Drain output and synchronize
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
