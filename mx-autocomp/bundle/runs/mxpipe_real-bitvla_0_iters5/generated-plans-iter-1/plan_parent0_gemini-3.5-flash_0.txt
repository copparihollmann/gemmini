An elegant optimization plan to improve the performance of the baseline MX matmul kernel.

### Optimization Plan

We will apply **Strategy 2: pack A and B tiles contiguously in scratchpad to maximize `gemmini_loop_ws_spad` fused loop coverage**.

**Inefficiency in Baseline:**
In the baseline implementation, tiles of $A$ and $B$ are loaded from DRAM using two nested loops, making $32$ individual `gemmini_extended_mvin` calls for $A$ and $256$ individual calls for $B$ (totaling $288$ DMA commands). Each separate instruction introduces command-issuing overhead, stalls the host CPU, and prevents the Gemmini DMA engine from utilizing its full memory-channel bandwidth.

**Optimization Details:**
1. **Pre-pack Tiles Contiguously in DRAM:** We allocate aligned stack buffers `A_packed` and `B_packed`. We then pack the tiles of `A_in` and `B_in` sequentially into these buffers. This ensures that every tile is stored contiguously in memory, and all tiles are ordered exactly as they will reside in the Gemmini scratchpad.
2. **Coalesced Block DMA Transfers:** Using `A_packed` and `B_packed`, we configure the loader stride to `DIM * sizeof(elem_t)` and issue exactly **one** large contiguous `gemmini_extended_mvin` for the entire $A$ matrix and exactly **one** for the entire $B$ matrix.
3. This eliminates $286$ RoCC instructions, maximizes DMA burst lengths, and drastically reduces the execution latency while keeping the systolic array completely fed.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// Assuming the following are defined globally or in headers:
// DIM, BANK_NUM, BANK_ROWS, MATMUL_M, MATMUL_N, MATMUL_K, REAL_M, OUT_COLS, PAD_I, PAD_J, PAD_K
// elem_t, out_t, C_hw, A_in, B_in, scale_factors, A_scales_row, B_scales_col, a_base, b_base, SPAD_DEST

void solution(void) {
  int tiles_I = MATMUL_M / DIM;
  int tiles_J = MATMUL_N / DIM;
  int tiles_K = MATMUL_K / DIM;

  // 1. Configure Gemmini execution format and strides
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  
  // 2. Load scale factors
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. Pack A and B tiles contiguously in DRAM
  elem_t A_packed[tiles_I * tiles_K * DIM * DIM] __attribute__((aligned(64)));
  elem_t B_packed[tiles_K * tiles_J * DIM * DIM] __attribute__((aligned(64)));

  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k++) {
      for (int r = 0; r < DIM; r++) {
        memcpy(A_packed + (i * tiles_K + k) * DIM * DIM + r * DIM,
               ((elem_t*)A_in) + (i * DIM + r) * MATMUL_K + k * DIM,
               DIM * sizeof(elem_t));
      }
    }
  }

  for (int k = 0; k < tiles_K; k++) {
    for (int j = 0; j < tiles_J; j++) {
      for (int r = 0; r < DIM; r++) {
        memcpy(B_packed + (k * tiles_J + j) * DIM * DIM + r * DIM,
               ((elem_t*)B_in) + (k * DIM + r) * MATMUL_N + j * DIM,
               DIM * sizeof(elem_t));
      }
    }
  }

  // 4. Contiguous MVIN for A tiles (reduced to a single command)
  gemmini_config_ld(DIM * sizeof(elem_t));
  gemmini_extended_mvin(A_packed, a_base, DIM, tiles_I * tiles_K * DIM);

  // 5. Contiguous MVIN for B tiles (reduced to a single command)
  gemmini_config_ld(DIM * sizeof(elem_t));
  gemmini_extended_mvin(B_packed, b_base, DIM, tiles_K * tiles_J * DIM);

  // 6. Configure quantization and execute weight-stationary hardware loop
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

  // 7. Drain output and synchronize
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
```
