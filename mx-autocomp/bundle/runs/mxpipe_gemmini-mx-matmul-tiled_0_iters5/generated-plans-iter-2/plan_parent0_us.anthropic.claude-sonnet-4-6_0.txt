## Analysis

Looking at the original code, I can identify a clear inefficiency related to **strategy 11**: `gemmini_flush(0)` is called inside the `i0`/`j0` double loop. This resets **all accelerator state** on every iteration — including format configuration, any cached state, etc. This is entirely unnecessary since the format, dataflow, and configuration are invariant across all block iterations.

Beyond `gemmini_flush`, `gemmini_extended3_config_ex` is also called inside the loop (strategy 6), which is redundant since the MX format (fp8, WS, out=BF16) never changes.

## Plan: Apply Strategy 11 (+ Strategy 6 as a direct consequence)

**What to change:**

1. Move `gemmini_flush(0)` to **before the `i0`/`j0` loop nest** — call it exactly once at program start.
2. Move `gemmini_extended3_config_ex(...)` to **before the `i0`/`j0` loop nest** — since all its arguments are constant (format=fp8, WS, no LUT, strides=1), it never needs to be re-issued.

These two calls currently execute `BLOCKS_M * BLOCKS_N` times. Each `gemmini_flush` stalls the pipeline and resets all state, forcing every subsequent configuration to be re-issued from scratch. By hoisting them outside all loops, we pay this cost exactly once.

The `gemmini_mx_load_scales` calls **cannot** be hoisted because `A_s` and `B_s` change per `(i0, j0)` block (they are populated by the `memcpy` of per-block scale subsets). Similarly, `gemmini_config_ld`, `gemmini_config_st`, `gemmini_mxquant_config_mvout`, mvins, `gemmini_loop_ws_spad`, `gemmini_mx_read_smem`, and `gemmini_fence` must remain inside the loop since they depend on `i0`/`j0`.

void solution(void) {
  // Hoist flush and format config outside all loops (strategies 11 and 6).
  // Format is invariant: fp8 WS, BF16 output, no LUT, strides=1.
  gemmini_flush(0);
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      // PROF cpu_stage
      // Stage only the tiny per-32-group scales; A/B data is mvin'd DIRECTLY
      // from DRAM (no host-side block memcpy — that was 98% of the cycles).
      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      // PROF accel
      // gemmini_flush and gemmini_extended3_config_ex hoisted above.
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
      for (int j = 0; j < tiles; j++)                    // B[k][j0*BLK+j] -> slot (k*tiles + j)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      gemmini_config_st(BLK_OUTC * sizeof(out_t));
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, 0, 0, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      gemmini_mx_read_smem(&C_blk[0][0], SPAD_DEST * 16, BLK * BLK);
      gemmini_fence();
      // PROF cpu_store
      for (int r = 0; r < BLK; r++)
        for (int c = 0; c < BLK; c++) {
          uint16_t b = (uint16_t)((C_blk[r][c / 4] >> ((c % 4) * 16)) & 0xFFFF);
          C_acc[i0 * BLK + r][j0 * BLK + c] = bf16f(b);
        }
    }
}
