## Selected Strategy: #13 — Use gemmini_extended_mvin2 for B tiles while simultaneously issuing gemmini_extended_mvin for A tiles

## Plan

**Problem:** The baseline issues all A mvins first (via `gemmini_extended_mvin`), then all B mvins (also via `gemmini_extended_mvin`). Both go through the same port, serializing both transfer streams completely. Total DMA time = time(A loads) + time(B loads).

**Solution:** Use `gemmini_extended_mvin` (port 0) for A tiles and `gemmini_extended_mvin2` (port 1) for B tiles, interleaving the two loops so that A and B tile loads are issued in alternating fashion. The hardware can pipeline both DMA streams concurrently, reducing effective DMA time toward max(time(A loads), time(B loads)).

**Concrete changes:**

1. Keep `gemmini_config_ld` for A tile stride as before (it configures port 0).
2. Issue a second `gemmini_extended3_config_ld` or `gemmini_config_ld` call using the id=1 variant (`gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1)`) to configure port 1 for B tiles with the same stride.
3. Merge the A and B mvin loops into a single interleaved loop nest. Since `tiles_I == tiles_J` is not guaranteed, iterate over the full Cartesian product of tile indices and interleave: for each (i,k) pair issue an A mvin via port 0, and for the corresponding (j,k) pair issue a B mvin via port 1. When one dimension is exhausted before the other, continue issuing the remaining tiles on their respective port.
4. Specifically: create a combined loop over `max(tiles_I, tiles_J)` outer iterations and `tiles_K` inner iterations, issuing an A mvin (if `i < tiles_I`) and a B mvin (if `j < tiles_J`) in each iteration body. This maximizes overlap of the two DMA streams.
5. The rest of the sequence (`gemmini_config_st`, `gemmini_mxquant_config_mvout`, `gemmini_loop_ws_spad`, `gemmini_mx_read_smem`, `gemmini_fence`) remains unchanged, as does the im2col preprocessing and scale loading.

This change requires no scratchpad layout modifications (A at `a_base`, B at `b_base` with the same formulas), no tiling changes, and no correctness risk — it only changes which DMA port issues each transfer. The expected speedup comes from overlapping A and B DRAM→scratchpad transfers that were previously serialized.
