An elegant and highly effective optimization plan to improve the latency of the MX matmul kernel by applying **Strategy 1: Reduce data movement**.

### Optimization Plan

1. **Maximize Batching for Matrix A**: The original implementation batches the MVIN of matrix A by 2 tiles along the $K$ dimension. Gemmini's hardware allows a maximum block transfer length (`MAX_BLOCK_LEN`) of 4 tiles. We will increase the batch size from `2 * DIM` to `4 * DIM` and step the loop index $k$ by 4 instead of 2. This reduces the number of DMA transfer commands for A by half and maximizes the burst transfer size on the DRAM-to-scratchpad interface.

2. **Full Batching for Matrix B**: In the original code, the loading of matrix B is completely unbatched, invoking a separate `gemmini_extended_mvin` call for every single $16 \times 16$ tile. Since $t_j = 4$, we can batch all 4 tiles along the J dimension into a single wide MVIN transfer of `4 * DIM` columns. This eliminates the inner loop over $j$ entirely, reducing the total MVIN commands for B from $t_k \times t_j = 64$ down to just $t_k = 16$, dramatically lowering control-flow and DMA setup overhead on the host and accelerator.

// AUTO-GENERATED optimized MX matmul kernel (128x128x256, fp4:e2m1).
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    // Configure execution with A_stride = 2 to match the batched scratchpad layout
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 2, 0, 0, false, 2, 2, 3, 0);
    
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 1);
    
    // MVIN A: Batched by 4 along the K dimension (cols = 4 * DIM) to minimize command overhead
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 4) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM), ab + (i*tk + k)*DIM, 4 * DIM, DIM);
      }
    }
    
    // MVIN B: Batched by 4 along the J dimension (cols = 4 * DIM) to maximize transfer width
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2)), bb + k*tj*DIM, 4 * DIM, DIM);
    }
    
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
