### Optimization Plan: DMA Block Transfer Optimization (MVIN Coalescing)

#### What is the inefficiency?
The baseline kernel utilizes single-tile `mvin` operations to load the input matrices $A$ and $B$ into the Gemmini scratchpad. Specifically, it loops through every $16 \times 16$ tile and dispatches an individual `gemmini_extended_mvin` command.
- For matrix $A$ (size $ti \times tk$), this requires $4 \times 16 = 64$ individual DMA load instructions.
- For matrix $B$ (size $tk \times tj$), this requires $16 \times 4 = 64$ individual DMA load instructions.

In total, the host CPU must issue $128$ separate `mvin` instructions. This introduces significant instruction dispatch overhead, register spilling, and memory pipeline bubbles on the RISC-V host CPU, while failing to fully saturate the hardware DMA bandwidth.

#### How the strategy improves performance:
Gemmini supports block-based transfers up to `MAX_BLOCK_LEN = 4` tiles (equivalent to $4 \times \text{DIM} = 64$ columns of 1-byte elements) in a single instruction. Since both matrices $A$ and $B$ are contiguous along their columns in DRAM:
1. **For Matrix A**: We can group 4 adjacent tiles along the $K$ dimension and load them in a single `mvin` command of $4 \times \text{DIM}$ columns. This reduces the load commands from 64 to 16.
2. **For Matrix B**: Since the tile width $tj = 4$ is exactly equal to the maximum block length limit, we can load the entire row of $B$ tiles for any given $k$ step in a single `mvin` instruction of size $tj \times \text{DIM} = 64$ columns. This reduces the load commands from 64 to 16.

By coalescing memory accesses, we reduce the total number of DMA commands by **4x** (from 128 down to 32), greatly decreasing host CPU overhead and achieving optimal DRAM-to-scratchpad streaming throughput.

### Optimized Code

```c
#include <stdint.h>
#include "include/gemmini_testutils.h"

// Optimized MX matmul kernel using DMA block coalescing
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;

    // 1. Configure execution formats (FP4 input, BF16 output)
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 2, 2, 3, 0);

    // 2. Load scale factors
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    // 3. Configure output and requantization bounds
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 1);

    // 4. Coalesced loading for A (block size = 4 tiles)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 4) {
        gemmini_extended_mvin(
          (void*)(((elem_t*)A_in_hw) + i * DIM * MATMUL_K + k * DIM), 
          ab + (i * tk + k) * DIM, 
          4 * DIM, 
          DIM
        );
      }
    }

    // 5. Coalesced loading for B (block size = tj = 4 tiles)
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      gemmini_extended_mvin(
        (void*)(((elem_t*)B_in) + k * DIM * (MATMUL_N / 2)), 
        bb + (k * tj) * DIM, 
        tj * DIM, 
        DIM
      );
    }

    // 6. Execute WS hardware tiled matmul loop
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

    // 7. Drain results to DRAM and synchronize
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
