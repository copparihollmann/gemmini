An elegant and highly effective optimization strategy for this phase is **Maximized Block-Length Batching combined with Compile-Time Constant Folding**.

### How This Strategy Works
1. **Maximized Block-Length Batching (`MAX_BLOCK_LEN = 4`)**:
   In the original code, the A and B matrix tiles are loaded with a block length of `2 * DIM` columns. Gemmini's DMA engine physically supports a maximum block length of `MAX_BLOCK_LEN = 4` tiles (`4 * DIM` columns) per single `mvin` command. 
   - For **Matrix A**: We increase the step size along the reduction dimension ($K$) from 2 to 4 (`k += 4`), loading `4 * DIM` columns at once. This cuts the number of `mvin` instruction dispatches for A in half.
   - For **Matrix B**: Since `tj` (the number of column tiles) is exactly 4, we can load all 4 column tiles at once in a single `4 * DIM` wide `mvin` command. This completely eliminates the inner `j` loop for B and cuts the B `mvin` instruction count in half.

2. **Compile-Time Constant Folding**:
   Defining loop bounds and tile parameters as compile-time constants (`#define`) rather than runtime variables allows the compiler to pre-compute the complex bit-packing required for RoCC instruction registers. This eliminates CPU-side dynamic shift-and-mask overhead before dispatching to the accelerator.

### Optimized Code

```c
#include <stdint.h>
#include "include/gemmini_testutils.h"

// Compile-time constants for tiling and limits
#define TC_TI (MATMUL_M / DIM / 2)
#define TC_TJ (MATMUL_N / DIM / 2)
#define TC_TK (MATMUL_K / DIM)
#define BB_ADDR (BANK_NUM * BANK_ROWS - TC_TK * TC_TJ * DIM)
#define SDST 128

// Optimized MX matmul kernel (128x128x256, fp4:e2m1)
void solution(void) {
  {
    // Configure format and execution (FP4 format, no LUT)
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 2, 2, 3, 0);
    
    // Load scale factors
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    
    // Configure store and requantizer
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, TC_TI, TC_TJ, TC_TK, 0, 0, 1);
    
    // Batched MVIN for A: Load 4 K-tiles of size DIMxDIM at once (MAX_BLOCK_LEN = 4)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < TC_TI; i++) {
      for (int k = 0; k < TC_TK; k += 4) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM), 
                              (i*TC_TK + k)*DIM, 
                              4 * DIM, 
                              DIM);
      }
    }
    
    // Batched MVIN for B: Load all 4 J-tiles of size DIMxDIM at once (MAX_BLOCK_LEN = 4)
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < TC_TK; k++) {
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2)), 
                            BB_ADDR + (k*TC_TJ)*DIM, 
                            4 * DIM, 
                            DIM);
    }
    
    // Compute weight-stationary loop in hardware
    gemmini_loop_ws_spad(TC_TI, TC_TJ, TC_TK, 0, 0, 0, 0, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    
    // Read BF16 results from SMEM and sync
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
