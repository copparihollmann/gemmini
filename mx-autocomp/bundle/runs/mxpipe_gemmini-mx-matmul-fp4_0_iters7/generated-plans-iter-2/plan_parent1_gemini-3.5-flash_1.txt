An elegant and highly effective optimization strategy for the Gemmini architecture is to **exploit the independent hardware DMA engines of Gemmini to load matrices A and B in parallel**. 

### Explanation of the Strategy

In the baseline implementation, matrices A and B are loaded sequentially using the default `gemmini_extended_mvin` instruction (which uses the primary `mvin` channel, `id=0`), and the stride is reconfigured between the loads. This serializes all memory traffic and introduces reconfiguration overhead.

However, the Gemmini hardware has **multiple independent DMA channels** (`mvin` on channel 0, and `mvin2` on channel 1). By using both channels, we can:
1. **Configure both strides once at the beginning**: `gemmini_extended3_config_ld` allows us to set the stride for channel 0 (`mvin` for A) and channel 1 (`mvin2` for B) independently. 
2. **Overwap memory transactions**: Interleaving the calls to `gemmini_extended_mvin` and `gemmini_extended_mvin2` within a single unified loop over `k` queues both A and B load requests in parallel. The Gemmini hardware can execute these loads concurrently using separate DMA streams, significantly reducing memory-bound stall time.

### Optimized Code

Here is the fully optimized, semantically equivalent code:

```c
#include <stdint.h>
#include "include/gemmini_testutils.h"

void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;

    // 1. Configure execution format
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 2, 2, 3, 0);

    // 2. Load scale factors
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    // 3. Configure requantizer write-back bounds
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 1);

    // 4. Configure DMA channels 0 and 1 independently
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), 1.0f, false, 0);       // Channel 0 for Matrix A
    gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t) / 2, 1.0f, false, 1);   // Channel 1 for Matrix B

    // 5. Interleave parallel loads of A and B using different DMA ports
    for (int k = 0; k < tk; k++) {
      for (int i = 0; i < ti; i++) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i * DIM * MATMUL_K + k * DIM), 
                              ab + (i * tk + k) * DIM, DIM, DIM);
      }
      for (int j = 0; j < tj; j++) {
        gemmini_extended_mvin2((void*)(((elem_t*)B_in) + k * DIM * (MATMUL_N / 2) + j * DIM), 
                               bb + (k * tj + j) * DIM, DIM, DIM);
      }
    }

    // 6. Execute hardware-accelerated tiled GEMM loop
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, 
                         false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

    // 7. Drain the packed BF16 results from SMEM to DRAM
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
