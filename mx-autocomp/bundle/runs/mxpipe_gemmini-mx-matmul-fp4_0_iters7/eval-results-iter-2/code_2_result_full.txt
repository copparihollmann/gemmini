Plan: An elegant and highly effective way to optimize this MX-Gemmini matmul kernel is to apply **Strategy 6: reuse loaded B (weight) tiles across multiple I-tile iterations without re-mvin**.

### Analysis of Inefficiencies in the Baseline Code:
1. **Incomplete/Incorrect Computation Range:** 
   The baseline code sets `ti = MATMUL_M / DIM / 2 = 4` (64 rows of M) and `tj = MATMUL_N / DIM / 2 = 4` (128 columns of N, since FP4 packed format has 2 elements per byte). Because the accumulator can only hold up to 256 rows at once (`ti * tj * DIM = 4 * 4 * 16 = 256`), attempting to compute the entire $128 \times 128$ output matrix in a single fused hardware loop would overflow the accumulator. Consequently, the baseline code only computed half of the rows (64 out of 128) of the output $C$ matrix and lacked outer loop tiling to cover the full size.
2. **Redundant Memory Traffic:**
   If we tile the rows of $C$ into two blocks of 64 rows ($b_i = 0$ and $b_i = 1$), the B (weight) matrix of size $256 \times 128$ is completely identical for both blocks. In a naive implementation, B would be reloaded from DRAM for each block.
3. **Frequent Fence Overhead:**
   Calling `gemmini_fence()` after every sub-block write-back adds unnecessary CPU stall cycles. 

### Optimization Plan:
1. **Outer Loop Tiling:** Introduce an outer loop over the row blocks `b_i` (from 0 to 1) to process the full $128 \times 128$ matrix in two $64 \times 128$ steps.
2. **B-tile Reuse (Strategy 6):** Hoist the loading of B (weight) tiles completely out of the `b_i` loop. Load B into the top of the scratchpad once at the beginning, and reuse it across both iterations of the `b_i` loop. This halves the off-chip DRAM bandwidth and loading latency for the weights.
3. **Adjust Memory Offsets:** 
   * Shift the $A$ dram pointer inside the $b_i$ loop to load the correct rows: `(b_i * ti + i) * DIM * MATMUL_K`.
   * Shift the `scale_factors` pointer to point to the current row block: `&scale_factors[b_i * ti * DIM][0]`.
   * Shift the destination $C$ write-back pointer in `gemmini_mx_read_smem` to point to the correct output rows: `&C_hw[b_i * ti * DIM][0]`.
4. **Deferred Fence:** Move `gemmini_fence()` out of the loop to execute only once at the end of the entire matrix multiplication.

  }
