An elegant and hardware-specific strategy to optimize the execution time of this MX matmul kernel is **Dual-Port DMA Parallelization with Interleaved Dispatching**.

### Explanation of the Strategy

In the baseline implementation, both matrix $A$ and matrix $B$ are loaded using the default `gemmini_extended_mvin` instruction, which maps to DMA Port 0. This serializes all memory transfers because the RISC-V host CPU queues all DMA requests in a single hardware queue.

However, the Gemmini hardware architecture features **three independent DMA channels/ports** (`mvin`, `mvin2`, and `mvin3`) that can process memory transfers in parallel. 

By applying this strategy:
1. We configure **DMA Port 0** specifically for the layout and stride of Matrix $A$.
2. We configure **DMA Port 1** specifically for the layout and stride of Matrix $B$ using `gemmini_extended3_config_ld` with `id = 1`.
3. We replace B's loading calls with `gemmini_extended_mvin2`, which maps to DMA Port 1.
4. We **interleave the dispatch of A and B tile transfers** in a single outer loop over the $K$ dimension. 

This interleaving fills both hardware DMA queues simultaneously. The Gemmini memory controller can then overlap the DRAM access latencies of both ports in parallel, maximizing memory bandwidth utilization and eliminating the serialization bottleneck.

---

### Optimized Code

```c
// Optimized MX matmul kernel (32x256x256, fp8:e4m3).
void solution(void) {
  // 1. Configure Gemmini execution format
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  // 2. Load scale factors
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. Configure independent DMA ports
  // Configure DMA Port 0 for Matrix A (stride K)
  gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 0);
  // Configure DMA Port 1 for Matrix B (stride N)
  gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t), MVIN_SCALE_IDENTITY, false, 1);

  // 4. Interleaved Multi-Port DMA loading of A and B tiles
  // By interleaving mvin (Port 0) and mvin2 (Port 1), we fill both hardware DMA queues
  // simultaneously, allowing the hardware to parallelize and overlap DRAM transfers.
  for (int k = 0; k < tiles_K; k++) {
    // Load A tiles for this k (using Port 0)
    for (int i = 0; i < tiles_I; i++) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, DIM, DIM);
    }
    // Load B tiles for this k (using Port 1)
    for (int j = 0; j < tiles_J; j++) {
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + j * DIM),
                             b_base + (k * tiles_J + j) * DIM, DIM, DIM);
    }
  }

  // 5. Configure store and requantizer
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // 6. Fused hardware loop execution over scratchpad tiles
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

  // 7. Drain output from shared memory and synchronize
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
```
