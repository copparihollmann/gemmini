An elegant and highly effective optimization strategy to reduce latency is **Block-level DMA (mvin) Coalescing / Batching**.

### Explanation of the Strategy

In the baseline implementation, tiles of A and B are loaded one by one using individual `gemmini_extended_mvin` instructions. For a matrix of size $32 \times 256 \times 256$, this results in $32$ loads for A and $256$ loads for B, totaling $288$ individual `mvin` host instructions. This causes significant CPU-to-coprocessor instruction dispatch overhead and underutilizes Gemmini's DMA engine.

Gemmini's DMA engine supports loading up to `MAX_BLOCK_LEN = 4` contiguous `DIM`-row tiles in a single instruction. We can leverage this to coalesce adjacent tile transfers:
1. **Matrix A Coalescing:** For a fixed row block `i`, the tiles along the reduction dimension `k` are contiguous in both DRAM and the scratchpad (`a_base + (i * tiles_K + k) * DIM`). We can pack up to 4 adjacent tiles of size `DIM × DIM` into a single horizontal block transfer of size `(4 * DIM) × DIM`.
2. **Matrix B Coalescing:** Under the hardware-mandated scratchpad layout `b_base + (j * tiles_K + k) * DIM`, the tiles along the `k` dimension for a fixed column block `j` are entirely contiguous in the scratchpad. They are also contiguous in DRAM. Thus, we can load up to 4 contiguous tiles along the `k` dimension with a single vertical block transfer of size `DIM × (4 * DIM)`.

This reduces the total number of `mvin` instructions from $288$ to $72$ (a **4× reduction**), drastically cutting instruction overhead and maximizing memory bandwidth utilization.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"
#include "include/matmul_fp8_64x64.h"

void solution(void) {
  // 1. Flush and configure MX FP8 weight-stationary mode
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

  // 2. Load per-block scale factors (sel=0 for A, sel=1 for B)
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // 3. MVIN A tiles: Coalesced block transfer along K (up to 4 tiles per command)
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k += 4) {
      int len = (tiles_K - k >= 4) ? 4 : (tiles_K - k);
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, len * DIM, DIM);
    }
  }

  // 4. MVIN B tiles: Coalesced block transfer along K (up to 4 tiles per command)
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
  for (int j = 0; j < tiles_J; j++) {
    for (int k = 0; k < tiles_K; k += 4) {
      int len = (tiles_K - k >= 4) ? 4 : (tiles_K - k);
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + j * DIM),
                            b_base + (j * tiles_K + k) * DIM, DIM, len * DIM);
    }
  }

  // 5. Configure output stride and MX requantizer
  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

  // 6. Execute fused weight-stationary hardware loop
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);

  // 7. Read results from shared memory & enforce memory barrier before CPU reads
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
```
