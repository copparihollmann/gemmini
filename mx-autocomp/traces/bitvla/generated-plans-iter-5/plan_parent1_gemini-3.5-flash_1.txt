### Optimization Plan

We will apply **Strategy 6: Batch the `mvin` with `block_mvin`** to load 2 adjacent `DIM`-tiles per single `gemmini_extended_mvin` call (setting `cols = 2 * DIM = 32`). 

#### Inefficiencies in the Baseline Code:
The baseline code performs point-to-point `DIM` $\times$ `DIM` (`16` $\times$ `16`) memory loads for both $A$ and $B$. This results in a large instruction dispatch overhead, bottlenecking the system on the CPU-side of the RoCC interface.

#### Optimization Details:
1. **Batched $A$-Matrix Load**: $A$ is row-major with dimension `MATMUL_M` $\times$ `MATMUL_K`. Adjacent tiles along $K$ (i.e., tile $(i, k)$ and tile $(i, k+1)$) are contiguous in both DRAM and the target scratchpad slots. Since `tiles_K = 16` is even, we can increment `k` by 2 and issue a single `gemmini_extended_mvin` with `cols = 32`, decreasing the $A$ `mvin` count by half.
2. **Batched $B$-Matrix Load**: Similarly, $B$ is row-major with dimension `MATMUL_K` $\times$ `MATMUL_N`. We restructure the B-loading loop so that $k$ is the outer loop and $j$ is the inner loop (incremented by 2). This allows us to load two horizontally contiguous tiles of $B$ (tile $(k, j)$ and tile $(k, j+1)$) using a single `gemmini_extended_mvin` with `cols = 32`.

This batched strategy reduces DMA setup and transfer overhead by 50% while fully utilizing the 32-byte physical width limits of the Gemmini scratchpad memory controller.

### Optimized Code

```c
// Optimized MX matmul kernel (32x256x256, fp8:e4m3).
void solution(void) {
  gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
  gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
  gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

  // MVIN A: Batch 2 horizontal DIM-tiles (cols = 32)
  gemmini_config_ld(MATMUL_K * sizeof(elem_t));      // A rows: stride K
  for (int i = 0; i < tiles_I; i++) {
    for (int k = 0; k < tiles_K; k += 2) {
      gemmini_extended_mvin((void*)(((elem_t*)A_in) + i * DIM * MATMUL_K + k * DIM),
                            a_base + (i * tiles_K + k) * DIM, 2 * DIM, DIM);
    }
  }

  // MVIN B: Batch 2 horizontal DIM-tiles (cols = 32)
  gemmini_config_ld(MATMUL_N * sizeof(elem_t));      // B rows: stride N
  for (int k = 0; k < tiles_K; k++) {
    for (int j = 0; j < tiles_J; j += 2) {
      gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + j * DIM),
                            b_base + (k * tiles_J + j) * DIM, 2 * DIM, DIM);
    }
  }

  gemmini_config_st(OUT_COLS * sizeof(out_t));
  gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);
  gemmini_loop_ws_spad(tiles_I, tiles_J, tiles_K, PAD_I, PAD_J, PAD_K, a_base, BANK_NUM * BANK_ROWS, 0,
                       SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
  
  // read only the REAL rows (smem row stride is the padded MATMUL_N); padded rows stay 0 (memset).
  gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * MATMUL_N);
  gemmini_fence();
}
```
