## Analysis of the Current Code

The current code has `gemmini_flush(0)` and `gemmini_extended3_config_ex(...)` inside the outer `i0`/`j0` loop. Since the MX format fields (FP8, weight-stationary, BF16 output) are **completely invariant** across all tiles — they never change between iterations — this re-issues the full CONFIG_EX instruction on every block iteration unnecessarily.

For a problem with `BLOCKS_M × BLOCKS_N` outer iterations, this means `gemmini_flush` and `gemmini_extended3_config_ex` are each called `BLOCKS_M × BLOCKS_N` times when they only need to be called once.

## Selected Strategy: Hoist `gemmini_extended3_config_ex` Outside All Loops

### Plan

**Move `gemmini_flush(0)` and `gemmini_extended3_config_ex(...)` to before the `i0`/`j0` outer loops.**

Specifically:
1. Before the `for (int i0 = 0; ...)` loop begins, issue `gemmini_flush(0)` once.
2. Immediately after the flush, issue `gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0)` once.
3. Remove both calls from inside the `i0`/`j0` loop body.

The CONFIG_EX fields being hoisted are:
- `WEIGHT_STATIONARY` — same for every block
- format fields `act_mx_fmt=0, wgt_mx_fmt=0, out_mx_fmt=3, uselut=0` — same FP8→BF16 for every block
- strides `A_stride=1, C_stride=1` — same for every block
- transpose flags `0, 0` — same for every block

None of these change across the `i0`/`j0` iteration space. The per-block scale loads (`gemmini_mx_load_scales`), mvin strides, and compute calls that **do** vary per block remain inside the loop.

**The programming model ordering is preserved:** the hoisted `config_ex` still appears before the first `gemmini_mx_load_scales` call (which remains inside the loop), satisfying the required sequence: config_ex → load_scales → mvin → mxquant_config_mvout → loop_ws_spad → read_smem → fence.

This eliminates `BLOCKS_M × BLOCKS_N - 1` redundant `gemmini_flush` + `gemmini_extended3_config_ex` instruction pairs. For `BLOCKS_M=4` (ceil(50/16)) and `BLOCKS_N=8` (ceil(256/32)), that's 31 redundant flush+config pairs removed, reducing instruction dispatch overhead and pipeline drain cost from each `gemmini_flush`.
