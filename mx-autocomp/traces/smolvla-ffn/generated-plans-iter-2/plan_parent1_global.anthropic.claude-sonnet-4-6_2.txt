## Analysis

Looking at the original code, I can see that `gemmini_config_st(BLK_OUTC * sizeof(out_t))` is called **inside the i0/j0 double loop** on every tile iteration. The output stride `BLK_OUTC * sizeof(out_t)` never changes — it depends only on compile-time constants. This means we're issuing a redundant store-configuration instruction on every single (i0, j0) pair, which is pure overhead.

## Selected Strategy: #5 — Hoist `gemmini_config_st` outside all loops

### Plan

The `gemmini_config_st(BLK_OUTC * sizeof(out_t))` call is entirely loop-invariant:
- `BLK_OUTC` is a constant (the output column width in BF16-packed words)
- `sizeof(out_t)` is a constant
- The output stride does not vary with `i0` or `j0`

Move it to execute **once** before the `for (int i0 ...)` loop. This eliminates one RoCC configuration instruction per (i0, j0) tile pair. With `BLOCKS_M × BLOCKS_N` iterations, this saves a non-trivial number of instructions, especially since each RoCC instruction incurs command-queue and ordering overhead on the accelerator.

No other changes are needed: the correctness of the programming model sequence is preserved because `gemmini_config_st` still precedes `gemmini_mxquant_config_mvout` and `gemmini_loop_ws_spad` on every tile iteration (the config is set once and persists, which is explicitly supported by the hardware state model — "CONFIG_ST fields persist until changed").

```c
void solution(void) {
  // Hoist the loop-invariant store config outside all loops.
  gemmini_config_st(BLK_OUTC * sizeof(out_t));

  for (int i0 = 0; i0 < BLOCKS_M; i0++)
    for (int j0 = 0; j0 < BLOCKS_N; j0++) {
      int mrows = REAL_M - i0 * BLK; if (mrows > BLK) mrows = BLK; if (mrows <= 0) continue;
      int ncols = REAL_N - j0 * BLK; if (ncols > BLK) ncols = BLK; if (ncols <= 0) continue;

      for (int g = 0; g < MATMUL_K / 32; g++) {
        memcpy(&A_s[g][0], &A_scales_row[g][i0 * BLK], BLK);
        memcpy(&B_s[g][0], &B_scales_col[g][j0 * BLK], BLK);
      }
      int tiles = BLK / DIM, tiles_K = MATMUL_K / DIM;
      uint32_t a_base = 0;
      uint32_t b_base = BANK_NUM * BANK_ROWS - tiles * tiles_K * DIM;
      int SPAD_DEST = 128;
      int pad_i = BLK - mrows, pad_j = BLK - ncols;

      gemmini_flush(0);
      gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);
      gemmini_mx_load_scales((uint64_t)A_s, A_S_BYTES, 0);
      gemmini_mx_load_scales((uint64_t)B_s, B_S_BYTES, 1);
      gemmini_config_ld(MATMUL_K * sizeof(elem_t));
      for (int i = 0; i < tiles; i++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)A_in) + (i0 * BLK + i * DIM) * MATMUL_K + k * DIM),
                                a_base + (i * tiles_K + k) * DIM, DIM, DIM);
      gemmini_config_ld(MATMUL_N * sizeof(elem_t));
      for (int j = 0; j < tiles; j++)
        for (int k = 0; k < tiles_K; k++)
          gemmini_extended_mvin((void*)(((elem_t*)B_in) + (k * DIM) * MATMUL_N + (j0 * BLK + j * DIM)),
                                b_base + (k * tiles + j) * DIM, DIM, DIM);
      // gemmini_config_st removed from here — hoisted above
      gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles, tiles, tiles_K, 0, 0, 1);
      gemmini_loop_ws_spad(tiles, tiles, tiles_K, pad_i, pad_j, 0, a_base, BANK_NUM * BANK_ROWS, 0,
                           SPAD_DEST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
      for (int r = 0; r < mrows; r++)
        gemmini_mx_read_smem(&C_hw[i0 * BLK + r][(j0 * BLK) / BF16_PER_WORD],
                             SPAD_DEST * 16 + r * BLK, ncols);
      gemmini_fence();
    }
}
```
