### Strategy: Full-Scale Hardware-Loop Fusion with Global Scale Factor Loading

To achieve maximum performance on the MX-Gemmini hardware, we can apply **Full-Scale Hardware-Loop Fusion**. 

The original code artificially partitioned the matrix multiplication into smaller blocks (`BLK = 32`) on the CPU. For each block, it performed complex scale-factor transpositions, loaded scale factors dynamically, ran multiple inner loop executions, and repeatedly flushed the coprocessor. This created severe CPU-side loop overhead and left the scratchpad and accumulator virtually empty (reported as 0KB utilization).

Since the matrix dimensions are $64 \times 64 \times 64$ ($M=64, N=64, K=64$), we have:
* **Scratchpad Capacity Required:** $(4 \times 4 + 4 \times 4) \times 16 = 512$ rows. This occupies only $6.25\%$ of the $8192$-row scratchpad.
* **Accumulator Capacity Required:** $4 \times 4 \times 16 = 256$ rows. This fits exactly in the $256$-row accumulator.

Rather than running slow nested CPU loops, we can **fuse the entire matrix multiplication into a single, global hardware-tiled loop execution**:
1. **Eliminate Outer CPU Loops completely:** No `i0` or `j0` loop overhead, and no dynamic scale-factor transposition/formatting.
2. **Global Scale Factor Loading:** Stream the entire $A$ and $B$ scale factor matrices once globally prior to starting the execution, entirely removing scale reloading stalls from the computation path.
3. **Continuous DMA Streaming:** Load all $A$ and $B$ tiles into the scratchpad at once using consecutive, un-flushed `gemmini_extended_mvin` calls.
4. **Fused Compute:** Invoke `gemmini_loop_ws_spad` once with the full $I=4, J=4, K=4$ tile bounds to compute the complete $64 \times 64 \times 64$ GEMM in hardware.
5. **Single-Pass Smem Readout:** Drain the full output matrix with a single `gemmini_mx_read_smem` call followed by a single `gemmini_fence()`.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// Ensure inline execution of Gemmini helpers
#define ALWAYS_INLINE __attribute__((always_inline)) inline

void solution(void) {
    // 1. Hoist global execution configuration (Format: FP8-E4M3 inputs, BF16 output)
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 0, 0, 3, 0);

    // Calculate tile dimensions globally (M=64, N=64, K=64 -> 4x4x4 tiles)
    const int tiles_I = REAL_M / DIM;
    const int tiles_J = REAL_N / DIM;
    const int tiles_K = MATMUL_K / DIM;

    const uint32_t a_base = 0;
    const uint32_t b_base = BANK_NUM * BANK_ROWS - tiles_K * tiles_J * DIM; // 8192 - 256 = 7936
    const int SPAD_DEST = 128;

    // 2. Load all scale factors once globally
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);

    // 3. MVIN all A tiles into the lower half of the scratchpad
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < tiles_I; i++) {
        for (int k = 0; k < tiles_K; k++) {
            elem_t *dram_ptr = ((elem_t *)A_in) + (i * DIM) * MATMUL_K + k * DIM;
            uint32_t sp_addr = a_base + (i * tiles_K + k) * DIM;
            gemmini_extended_mvin((void *)dram_ptr, sp_addr, DIM, DIM);
        }
    }

    // 4. MVIN all B tiles into the upper half of the scratchpad
    gemmini_config_ld(REAL_N * sizeof(elem_t));
    for (int j = 0; j < tiles_J; j++) {
        for (int k = 0; k < tiles_K; k++) {
            elem_t *dram_ptr = ((elem_t *)B_in) + (k * DIM) * REAL_N + j * DIM;
            uint32_t sp_addr = b_base + (j * tiles_K + k) * DIM;
            gemmini_extended_mvin((void *)dram_ptr, sp_addr, DIM, DIM);
        }
    }

    // 5. Configure output stride and mxquant parameters for the full output
    static uint32_t scale_factors[512] __attribute__((aligned(64))) = {0};
    gemmini_config_st((REAL_N / BF16_PER_WORD) * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, tiles_I, tiles_J, tiles_K, 0, 0, 1);

    // 6. Compute the full 64x64x64 matrix multiplication in a single hardware loop invocation
    gemmini_loop_ws_spad(
        tiles_I, tiles_J, tiles_K,
        0, 0, 0,                     // pad_I, pad_J, pad_K
        a_base,
        BANK_NUM * BANK_ROWS,
        0,                           // D spad address (None)
        SPAD_DEST,
        false, false,                // A_transpose, B_transpose
        false, false, false,         // full_C, low_D, ex_accumulate
        NO_ACTIVATION,
        0, 0,                        // double-buffer spad IDs
        false,                       // is_resadd
        0x38                         // skips: skip DRAM loads (ldA, ldB, ldD)
    );

    // 7. Drain complete BF16-packed outputs from shared memory to DRAM
    gemmini_mx_read_smem(&C_hw[0][0], SPAD_DEST * 16, REAL_M * REAL_N);
    gemmini_fence();
}
```
