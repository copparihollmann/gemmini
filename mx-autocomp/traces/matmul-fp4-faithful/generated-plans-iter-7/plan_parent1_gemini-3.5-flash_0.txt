An elegant and highly effective way to optimize this kernel is to apply **Strategy 13: Declare loop limits (`ti`, `tj`, `tk`) as compile-time constants / `const`**. 

### Optimization Plan

1. **Declare Loop Limits as `const`**: Change `ti`, `tj`, and `tk` from mutable `int` variables to `const int` constants.
2. **Compile-Time Address Generation**:
   - In the original code, the RISC-V compiler has to generate runtime instructions for multi-dimensional index multiplications such as `i * DIM * MATMUL_K + k * DIM` and `(i * tk + k) * DIM`.
   - By declaring `ti`, `tj`, and `tk` as `const` values (`4`, `4`, and `16` respectively), the compiler can replace all runtime multiplications and divisions in these loop bounds and index calculations with fast, single-cycle compile-time constant arithmetic, bit-shifts (e.g., multiplication by `DIM` (16) becomes `<< 4`), and induction register additions.
3. **Preserve Layout and Correctness**: Keep the exact same packing configurations, strides (`A_stride = 2`), and overall programming model sequence to guarantee bit-exact correctness with the MX golden model.

void solution(void) {
  {
    // Declare loop limits as const to enable compile-time induction and shift optimizations
    const int ti = MATMUL_M / DIM / 2; // 4
    const int tj = MATMUL_N / DIM / 2; // 4
    const int tk = MATMUL_K / DIM;     // 16
    
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    // Configure execution with A_stride = 2 to match the batched scratchpad layout
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 2, 0, 0, false, 2, 2, 3, 0);
    
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 1);
    
    // MVIN A: Batched by 2 along the K dimension (cols = 2 * DIM)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 2) {
        // Multiplications are fully resolved to shifts/additions at compile time
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM), ab + (i*tk + k)*DIM, 2 * DIM, DIM);
      }
    }
    
    // MVIN B remains unbatched as B_stride is fixed to 1 in weight-stationary mode
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      for (int j = 0; j < tj; j++) {
        gemmini_extended_mvin((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2) + j*DIM), bb + (k*tj + j)*DIM, DIM, DIM);
      }
    }
    
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
