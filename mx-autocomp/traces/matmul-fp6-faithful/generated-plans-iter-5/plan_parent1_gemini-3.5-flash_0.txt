An elegant way to improve the performance of this kernel is to **overlap and batch data movement** using **Strategy 7 (batch the mvin with block_mvin)**. 

### Inefficiency Analysis
In the baseline kernel, matrix $A$ and matrix $B$ are loaded tile-by-tile using `gemmini_extended_mvin` with a size of `DIM` $\times$ `DIM` (16 $\times$ 16). Since the systolic array is instruction-driven, issuing a large number of individual DMA transfer instructions creates a significant bottleneck on the host CPU.

### Optimization Plan
Because both matrix $A$ (along the $K$ dimension) and matrix $B$ (along the $J$ dimension) are stored contiguously in DRAM and mapped contiguously into the Gemmini scratchpad:
1. We can batch the load of 2 consecutive tiles into a single `gemmini_extended_mvin` instruction by setting the `cols` parameter to `2 * DIM` (32 columns) and stepping our loop counters by 2.
2. Since `2 * DIM` = 32 is less than the hardware limit of 48, this is safe and will not cause truncation/overflow errors in the Gemmini instruction fields.
3. This modification cuts the number of required `mvin` RoCC instructions in half, significantly reducing loop and instruction dispatch overhead.

### Optimized Code

```c
// Optimized MX matmul kernel (128x128x256, fp6:e3m2) using batched MVINs.
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 1, 1, 3, 1);
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 9);
    gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
    gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
    
    // Batch MVIN for matrix A (2 tiles along the K-dimension per instruction)
    gemmini_config_ld(MATMUL_K * sizeof(elem_t));
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 2) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i * DIM * MATMUL_K + k * DIM), 
                              ab + (i * tk + k) * DIM, 
                              2 * DIM, 
                              DIM);
      }
    }
    
    // Batch MVIN for matrix B (2 tiles along the J-dimension per instruction)
    gemmini_config_ld(MATMUL_N * sizeof(elem_t) / 2);
    for (int k = 0; k < tk; k++) {
      for (int j = 0; j < tj; j += 2) {
        gemmini_extended_mvin((void*)(((elem_t*)B_in) + k * DIM * (MATMUL_N / 2) + j * DIM), 
                              bb + (k * tj + j) * DIM, 
                              2 * DIM, 
                              DIM);
      }
    }
    
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
