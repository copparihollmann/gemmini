An elegant strategy to optimize this workload is to leverage **Multi-Port DMA Concurrency** alongside **Maximized Block-Size Transfers**.

### Explanation of the Strategy

1. **Maximized Block-Size Transfers (`MAX_BLOCK_LEN = 4`)**:
   In the original code, the DMA engine transfers 2 tiles of size `DIM` at a time (`2 * DIM`). The hardware supports up to `MAX_BLOCK_LEN = 4` tiles (64 bytes) per transfer. By increasing the transfer width to `4 * DIM`, we reduce the loop iterations for both matrix loads, cutting the CPU overhead of generating and sending RoCC instructions to the accelerator.

2. **Multi-Port DMA Overlapping**:
   The original program uses the standard `gemmini_extended_mvin` (which utilizes DMA Port 0) for both $A$ and $B$. This forces serial execution of the DMA transfers. We can instead route $A$ through `mvin` (Port 0) and $B$ through `mvin2` (Port 1). 
   To do this, we configure separate stride values for each port once up front using `gemmini_extended3_config_ld(..., id)`. This eliminates stride-reconfiguration overhead inside the loop nest and allows the coprocessor to overlap the DRAM-to-Scratchpad transfers of $A$ and $B$ concurrently.

### Optimized Code

```c
#include <stdint.h>
#include <string.h>
#include "include/gemmini_testutils.h"

// AUTO-GENERATED optimized MX matmul kernel (128x128x256, fp6:e3m2).
void solution(void) {
  {
    int ti = MATMUL_M / DIM / 2, tj = MATMUL_N / DIM / 2, tk = MATMUL_K / DIM;
    uint32_t ab = 0;
    uint32_t bb = BANK_NUM * BANK_ROWS - tk * tj * DIM;
    int SDST = 128;
    
    // 1. Base Configuration
    gemmini_extended3_config_ex(WEIGHT_STATIONARY, 0, 0, ACC_SCALE_IDENTITY, 1, 1, 0, 0, false, 1, 1, 3, 1);
    gemmini_mx_load_scales((uint64_t)&A_scales_row, sizeof(A_scales_row), 0);
    gemmini_mx_load_scales((uint64_t)&B_scales_col, sizeof(B_scales_col), 1);
    gemmini_config_st(OUT_COLS * sizeof(out_t));
    gemmini_mxquant_config_mvout((uint64_t)scale_factors, ti, tj, tk, 0, 0, 9);
    gemmini_mx_load_lut((uint64_t)B_lut_p, 1, 0);
    gemmini_mx_load_lut((uint64_t)A_lut_p, 1, 1);
    
    // 2. Multi-Port Stride Configuration (id=0 for A/mvin, id=1 for B/mvin2)
    gemmini_extended3_config_ld(MATMUL_K * sizeof(elem_t), 1.0, false, 0);
    gemmini_extended3_config_ld(MATMUL_N * sizeof(elem_t) / 2, 1.0, false, 1);
    
    // 3. Batch MVIN for A (Port 0): Load 4 tiles (64 columns) at once
    for (int i = 0; i < ti; i++) {
      for (int k = 0; k < tk; k += 4) {
        gemmini_extended_mvin((void*)(((elem_t*)A_in_hw) + i*DIM*MATMUL_K + k*DIM), ab + (i*tk + k)*DIM, 4 * DIM, DIM);
      }
    }
    
    // 4. Batch MVIN for B (Port 1 / mvin2): Load 4 tiles (64 columns) at once
    for (int k = 0; k < tk; k++) {
      gemmini_extended_mvin2((void*)(((elem_t*)B_in) + k*DIM*(MATMUL_N/2)), bb + (k*tj)*DIM, 4 * DIM, DIM);
    }
    
    // 5. Compute and Output Drain
    gemmini_loop_ws_spad(ti, tj, tk, 0, 0, 0, ab, BANK_NUM * BANK_ROWS, 0, SDST, false, false, false, false, false, NO_ACTIVATION, 0, 0, false, 0x38);
    gemmini_mx_read_smem(&C_hw[0][0], SDST * 16, MATMUL_M * MATMUL_N);
    gemmini_fence();
  }
}
```
